# Behavior Analytics 0.1.10

The world map arrives. The default "SOC Overview" template gains a Geography widget across its
bottom row, and `/geography` shows the same answer at full size: events per country, by the country
of the source or the destination address, over 1 hour, 24 hours or 7 days. The map is a sequential
scale, not a status scale: up to four classes on a log axis, the `--map-0…--map-4` ramp, and a
numeric legend with its unit. A country the collection did not see is drawn in `--map-0` as "No
data", never as the lowest class. Nothing collected gives "Not collected." and no map at all;
buckets collected with no address resolved give "Insufficient data."; a partial read draws the map
and says "Partial"; a lower bound says "At least" in the legend, the table and the tooltip. A
country too small for the 1:110m outlines is named under the map and stays in the table. The widget
needs `read:geo` and names the permission when it is missing.

The editors are clearer. In the custom rule editor the operator list is words ("above", "at or
above", "below"…), the units are words ("events/bucket", "events/s", "share"), and every technical
field carries a "?" that explains it in the analyst's terms — what a bucket is, that an unmeasured
slice is not a zero, what sustain and recovery count. The metric note under Metric is now the
frontend's own sentence for each of the eleven catalog metrics, in both languages, instead of the
backend's English note. In the property watch editor, a disabled "New combination" says why it is
off ("Needs two properties." / "Choose the scope first.") and, when the second property can be
added, offers that button in place, with focus handed to the new picker. On the IPS and WAF source
pages the "add source" control is the page header's action instead of a row in the body, and a load
error shows no button. A session that fails now sets the server's own detail apart as its own
labelled clause ("The server said: …"), and the sign-in-required, rate-limited and error notices
sit at the top at the sign-in form's width instead of stretching to the viewport height.

"Phase A" is gone from everything a reader sees: the family is "Log source volume" in English and
"Log source hacmi" in Turkish, in the catalog, the search-cadence page, the installer summary and
the retention line. `doctor`'s always-on family token is `LOG_SOURCE_VOLUME`. The stored identifier
`PHASE_A_VOLUME` is unchanged, and so is every stored row.

The rest is smaller. A new or changed console gets its first log-source and rule inventory queued
right after the row commits, instead of waiting for the hourly beat. `QRADAR_CONSOLE_FQDN` accepts a
`host:port`. Every request the default rate limit counts now carries the `X-RateLimit-*` window,
including a coded refusal; `Retry-After` is written only on the 429. The schema head moves to
`0045` for one index. The operator documents name the dashboard template that carries the Scheduled
searches widget, and the manual test now asks which of the installer's address lines appeared
(DOC-5). The message engine gained a clause-list style; the rendered sentences are byte for byte
what they were (MSG-9). The CI shard weights changed (CI-5); nothing a site runs is affected.

## Before you upgrade

- **The schema head moves to `0045` (FIX-14).** One additive migration,
  `0045_rule_match_window_start_index`, creates the btree `ix_rule_match_window_window_start` on
  `rule_match_window.window_start`. The daily `rule_match_retention` delete runs
  `WHERE window_start < :cutoff`; the primary key is `(instance_id, window_start)`, which does not
  serve a predicate on the time column alone, so each batch scanned the table. No row changes, no
  backfill, no new column. Downgrade drops the index. `alembic check` reports no drift.
- **A counted refusal now carries the rate-limit window (FIX-14).** The default-limit dependency
  counts a request and writes `X-RateLimit-Limit`, `X-RateLimit-Remaining` and `X-RateLimit-Reset`
  onto the response it was given, and FastAPI copies those headers only when the route returns. A
  coded refusal, a plain `HTTPException` and a validation error each built a fresh response, so a
  request that was counted left with no window. From 0.1.10 the window is copied onto whatever
  response leaves, so a 401, 403, 404 or 422 that was counted carries the same three headers as a
  200. `Retry-After` is written **only** on the 429; every other counted response, including a
  200, keeps the window alone. What is counted did not change: per client key and per path, the
  same limits, the same exempt routes (`GET /api/v1/health/live`, `GET /api/v1/health/ready`), and
  CSRF refusals still return before the count and carry no window. 0.1.9's notes described
  `Retry-After` on every limited response; that sentence stays as shipped, and this release is the
  correction.
- **`QRADAR_CONSOLE_FQDN` accepts `host:port` (FIX-13).** The installer accepts a host name or a
  host name with an optional `:port` from 1 to 65535, and refuses a scheme, a path and any other
  shape. An omitted name is still the QRadar URL's host with the port removed, and `PUBLIC_HOSTNAME`
  stays a bare host. The MCP client strips a scheme and calls `https://<value>/api/…`, so a value
  with a port dials that port; certificate verification matches the host, not the port. A console
  whose API is not on 443 can now use the MCP profile by setting the port. `install` writes the
  value as given.
- **A new or changed console gets its first inventory (FIX-13).** `python -m app.cli.qradar add` is
  the only operator writer of a console row; there is no update command, and `add` is idempotent by
  name. After the row commits, an enabled console that was created, whose connection settings
  changed, or that was just re-enabled queues `sync_instance_inventories` once with that instance
  id; the task runs the existing `sync_log_sources` and `sync_rule_inventory` bulk passes for that
  console only and is not on the beat. A disabled console is not queued, and neither is
  `app.services.seed` (it syncs log sources inline). If the broker refuses the send, the row stays,
  stdout says `first inventory was not queued; the hourly beat will catch up`, and the exit code is
  still the connection check's. The installer summary prints `First inventory    queued` or
  `First inventory    not queued; the hourly beat will catch up`.
- **No new setting is required.** The map reads `GEO_*` settings that 0.1.9 already had, and the
  geography source stays today's `GEO::LOOKUP` of the address. The property-based source and its
  `GEO_COUNTRY_SOURCE` / `GEO_SOURCE_COUNTRY_PROPERTY` settings are not in this release.
  <!-- REL-9 r1: GEO_COUNTRY_SOURCE, GEO_SOURCE_COUNTRY_PROPERTY (default "Source Geographic Location"), GEO_DESTINATION_COUNTRY_PROPERTY: describe in round 1. -->
- **The interface is English only from 0.1.10 (LANG-1, D-41).** The account language control (`/account`, "Arayüz dili" / "Interface language") is hidden; the interface renders in English regardless of the previous cookie (`ba_locale`) or account preference (`ui_language`). The Turkish catalogs (`frontend/messages/tr/`) stay frozen exactly as they were at tag `checkpoint/bilingual-2026-11-02`: they are never deleted, translated or corrected into English. Existing Turkish text in the interface, the Turkish operator runbook (`docs/OPERATIONS.md`) and the Turkish manual-test guide (`docs/MANUAL-TEST.md`) stays unchanged. If Turkish must be restored, the switch is a single setting in the locale file (`frontend/src/i18n/locale.ts`, the array that controls enabled locales — described in this paragraph as `ENABLED_LOCALES` from the spec; verify the exact name against the LANG-1 task). <!-- REL-9 r1: verify against LANG-1 -->
- **An 0.1.9 site upgrades directly.** `min_from` is `0.1.9`. A 0.1.8 site upgrades to 0.1.9 first;
  the 0.1.9 notes describe that path. `qradar-dash` reads this file's `min_from` from the checkout
  before it edits `.env`, loads a bundle or pulls an image, and refuses an older site with
  `upgrade refused: 0.1.10 requires at least 0.1.9; nothing was changed`; after the pull the
  image's own notes must agree.

## New for the operator

- **The world map is on the default dashboard.** The "SOC Overview" template places `map.geography`
  across the bottom (12 columns by 18 rows). Its configuration is the address direction (Source,
  the default, or Destination); its range is 1 hour, 24 hours or 7 days; it drills to
  `/geography?direction=…`. The same answer is on `/geography`, under Behavior in the navigation,
  with the address and the window in the URL. The page lists every country; the widget lists the top
  five and links to the page in every state. `read:geo` is required; a role without it sees the
  widget's forbidden sentence naming the permission. The 1:110m outlines are a lazily loaded
  content-hashed chunk, not part of the first load of any route.
- **The map says what it does not know.** "Not collected." means nothing was collected for that
  direction in the range, and the map is not drawn; the coverage reads "0 of N". "Insufficient
  data." means buckets were collected but no address resolved to a country, and again no map is
  drawn. A partial read draws the map with a "Partial" qualifier and the measured-bucket coverage.
  A lower-bound read says "At least" and marks every cell "≥". A failed refresh keeps the previous
  answer and the frame's note. The remainders (unresolved, over the country cap, unparseable) are
  disclosed with their meanings; the unresolved note is the server's own sentence in English and
  the catalog's Turkish sentence in Turkish. None of these states draws a zero.
- **"Log source volume" instead of "Phase A".** The family name, its empty sentence, the installer
  summary, the retention line and the search-cadence page say "Log source volume" / "Log source
  hacmi". `doctor`'s `families_off` line names the always-on family `LOG_SOURCE_VOLUME` in its
  `on:` list. The API and the database keep `PHASE_A_VOLUME`, so nothing stored changes.
- **A console's first inventory is queued (FIX-13).** The installer's step 9 relays `qradar add`'s
  line as `First inventory    queued` or `First inventory    not queued; the hourly beat will catch
  up`. The second line is not an error: the hourly beat still runs both inventories, and a changed
  console's source and rule pages fill on the next beat. A broker failure prints one warning line
  and does not change the exit code.
- **`QRADAR_CONSOLE_FQDN` may carry a port (FIX-13).** `docs/INSTALL.md` and `.env.example` now say
  so, and `docs/OPERATIONS.md`'s MCP TLS one-liner splits the value, so it works with and without a
  port. The wizard's step 5 says an optional port is allowed (1–65535).
- **The rate-limit window is on every counted response (FIX-14).** A refused request that was
  counted carries `X-RateLimit-*`; only the 429 carries `Retry-After`. `docs/OPERATIONS.md`,
  OPS-R21, and the manual test's rate-limit check say the same.
- **The documents name the right template and page (DOC-5).** `docs/OPERATIONS.md`'s daily overview
  says the Scheduled searches widget lives in the "QRadar Administration" template, not "SOC
  Overview", and that `/admin/search-cadence` shows the same data. `docs/FIELD-MAPPING.md` states
  the real threshold rule: thresholds apply to the fields collection reads (the required fields
  plus a mapped virtual host), and the validation report's per-field `used_by_collection` is the
  per-profile truth. The manual test's installer check asks which of the address lines appeared.
- **There is no user delete.** Removing access is disabling the account (`POST
  /api/v1/users/{id}/disable`): it keeps the account row, sets `disabled_at`, revokes the account's
  sessions and writes a `user.disable` audit record naming the actor. The last active administrator
  still cannot be disabled (AUTH-1).

## For the analyst

- **The world map** (opening, "New for the operator"). The widget and the page share one body, so
  every state reads the same in both.
- **The custom rule editor speaks words (POL-10).** The operator options are "above", "at or above",
  "below", "at or below", "equal to" (and the recovery forms), while the stored value stays the
  code. The metric option, the threshold label and suffix, the condition on the list and detail
  pages, the preview chart's axis and tooltip, and the summary use the unit's words
  ("events/bucket", "requests/bucket", "events/s", "share"; Turkish "olay/zaman dilimi",
  "istek/zaman dilimi", "olay/sn", "pay"). Each of Metric, Operator, Threshold, Sustain, Recovery,
  Window and Severity has a "?" that opens on hover, keyboard focus or a click and closes on Escape
  or blur; it is a real button, its text is a tooltip, and the field is described by it while it is
  shown. Right-column tips open leftwards so they stay inside a 1024-pixel window.
- **The metric note is the analyst's (POL-13).** Under Metric, each of the eleven catalog metrics
  (the ten `PHASE-F-CUSTOM-DETECTIONS.md` §F.1.1 rows and the property-watch `PW_VALUE_EVENTS`) has
  a sentence in the interface language about what it reads and when it is exact, partial or a lower
  bound. A metric this frontend has no text for shows no note. The backend's `note` field is
  unchanged and no longer shown here.
- **New combination says why it is off (POL-14).** With no scope, "Choose the scope first."; with a
  scope and room for a second property, "Needs two properties." and an "Add a second property"
  button that does what the section-2 button does and moves focus to the new picker; at the
  catalog ceiling, the existing validation sentence and no button. With two properties the box
  enables and the reason disappears; removing a property unticks the box and the reason returns.
- **The add-source control is in the page header (POL-12).** On `/admin/ips-sources` and
  `/admin/waf-sources` the control sits beside the guide link when the list loads; the open picker
  is a second row in flow under the header, scrolls inside its own bound and does not cover the
  table. A load error shows the notice and no button. Enter still opens and closes the picker and
  Tab reaches its search field.
- **A failed session says what the server said (POL-9).** The detail is its own clause between the
  first sentence and "Try again.": "The server said: internal error." / "Sunucu şunu bildirdi:
  internal error." A detail that already ends in `.`, `!` or `?` keeps its mark; no detail gives no
  clause; a network failure (no HTTP status) has only the local text and no longer repeats the
  heading. The 429 sentence and its layout are unchanged.
- **The gate notices size to their content (POL-8).** The sign-in-required notice, the 429 notice
  and the generic error notice sit at the top at the sign-in form's width (24 rem), instead of
  stretching to the viewport height. Their text is unchanged. The unused `login.wait` catalog key
  is removed; no page showed it.
- **"Log source volume"** wherever a reader sees the family (opening, "New for the operator").
- **Nothing else renders differently.** The clause-list message style (MSG-9) joins three
  history sentences with "; " in every language, and the rendered text is byte for byte what 0.1.9
  produced.

**Known limits.** `/geo/countries` carries no data time (`until` is the request's own now), so the
map widget can show the failed-refresh note but never "Stale: data from …". A country whose events
the 1:110m outlines do not draw (Singapore, Malta and other micro-states) is named under the map and
kept in the table. The map's canvas cannot be read by assistive technology beyond its label, which
names the top three countries; the table beside it carries every figure and is a named, focusable,
keyboard-scrollable region. In the custom rule editor, a metric added to the backend with no
frontend text shows no note until the catalogs gain it. In the property watch editor, the property
pickers still have no reason of their own when no scope is chosen, and the history window select
and "Add pinned value" at the ceiling carry no state-linked reason (the unticked checkbox above and
the static cap line are their only explanations). A rate-limited refresh on a widget that already
shows data keeps the data and the short note only.

## API

0.1.10 changes no request shape and no existing field's meaning, and adds no endpoint. The map
reads the existing `GET /api/v1/geo/countries`; the editors read the existing catalogs.

- **A counted response carries the rate-limit window** (FIX-14): `X-RateLimit-Limit`,
  `X-RateLimit-Remaining` and `X-RateLimit-Reset` on a 200 and on a counted 401, 403, 404, 422 or
  429. `Retry-After` is present only on the 429. The exempt health routes carry no window.
- **`GET /api/v1/version`** reports `migration_head` `0045` after the upgrade.
- **The custom rule catalog's `note`** is unchanged; the editor no longer renders it. No response
  field is removed.

## Schema

The head is `0045`. 0.1.10 adds one migration, `0045_rule_match_window_start_index`, which creates
`ix_rule_match_window_window_start` on `rule_match_window.window_start` and drops it on downgrade.
It is additive: no row, column or constraint changes, no backfill, and `alembic check` reports no
drift. A site coming from 0.1.9 runs it once. A rollback is a restore of the upgrade's backup, as
always; no migration is ever run downward on a site.

## Upgrade

```bash
git fetch --tags && git checkout v0.1.10
./qradar-dash upgrade 0.1.10
```

The upgrade is allowed from `0.1.9`. A site on 0.1.8 upgrades to 0.1.9 first; the 0.1.9 notes
describe that path. An older release is refused before anything is touched (FIX-12): the refusal
comes from the checkout's own `docs/releases/0.1.10.md`, read before any `.env` edit, bundle load
or pull — `upgrade refused: 0.1.10 requires at least 0.1.9; nothing was changed` — so `.env`
keeps its bytes and no image is pulled. If that file is missing, unreadable or not for 0.1.10, the
refusal names the file and changes nothing either. The migration runs once (`Running upgrade 0044
-> 0045`), and after the upgrade `/api/v1/version` reports `migration_head` `0045`. The upgrade
takes its own backup before it migrates, as every upgrade does, and that backup carries the install
answers. The collection families resume on their cadence; the pages show "stale" or "not collected"
until the first cadence after the upgrade has passed, and that is correct. The map shows "Not
collected." until `GEO_COLLECTION` has run for the chosen direction and range.

On a host with no registry access, make the bundle on a connected host from the same checkout
(`./qradar-dash bundle --output DIR` writes `qradar-dash-0.1.10-bundle.tar` in that directory;
without `--output` the file is written in the current directory, and an existing file is not
overwritten), copy it over, and run, in the installation directory:

```bash
tar -xf /path/to/qradar-dash-0.1.10-bundle.tar --exclude=images.tar
./qradar-dash upgrade 0.1.10 --offline /path/to/qradar-dash-0.1.10-bundle.tar
```

If the upgrade fails and the site must return to 0.1.9, follow `docs/OPERATIONS.md`, "Geri alma
(`rollback`)": it restores the backup the upgrade took — including the install answers and the
`0044` schema — and starts the previous images. Data written since the upgrade is kept only in the
broken copy it leaves. `rollback` runs no `git checkout`; after a successful rollback the operator
returns the checkout to the version that now runs (`git checkout v0.1.9`), as that section says. A
return to 0.1.10 is then `git fetch --tags && git checkout v0.1.10` and
`./qradar-dash upgrade 0.1.10`.
