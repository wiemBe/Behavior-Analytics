# qradar-observability 0.1.0

The first release. An operator gets an on-premises, read-only QRadar behavioral-analytics
platform, installed with `./qradar-dash install` and started behind the bundled TLS proxy.

- Source-volume behavioral analytics (Phase A): seasonal baselines per log source, the
  `VOLUME_SPIKE`, `VOLUME_DROP` and `NO_EVENTS` detectors, incident lifecycle and a
  contributor explanation of what changed.
- WAF endpoint behavior (Phase B) and IPS traffic behavior (Phase D). Collection is off for
  each until it is enabled per source.
- QRadar health, offenses, rule health, MITRE ATT&CK coverage and scheduled searches, the
  anomaly investigation page, saved dashboards and custom threshold rules.
- `GET /api/v1/version` and the version line in the account menu and on the sign-in page.

**Schema.** Migration head `0025` (`0025_auth_sessions`). `migrate` runs
`alembic upgrade head` on a new database.

**Retention and compression are off until set.** `RETENTION_ENABLED` defaults to false, so
metric history grows without bound and no TimescaleDB retention or compression policy exists
until you turn it on and set the retention days (`RETENTION_*_DAYS`, `COMPRESSION_AFTER_DAYS`).
The install does not turn on MCP, the LLM, OIDC, `LAB_MODE` or the mock provider.

**Read-only.** The platform never creates, updates or deletes anything in QRadar.
