# Behavior Analytics 0.1.11

For the analyst: the world map states how each bucket was collected, Kosovo is a country in both collection modes, and eleven pages carry less first-screen text. The interface is English only.

For the operator: a new `QRADAR_HEALTH` search family collects per-host disk, system, pipeline and system-notification figures from Ariel and stores them for trends, on by default every 15 minutes; alert e-mail is sent through the site's SMTP relay with admin-edited templates; a stored access check runs every 6 hours per console and `doctor --aql` tries every family's real query once on demand. The schema head moves to `0054`.

## Before you upgrade

- **The schema head moves to `0054`.** See the Schema section for the seven additive migrations (`0048` to `0054`) that run once in order. Migration `0049` makes existing geography rows read as unknown (NULL means unknown). `alembic check` reports no drift.
- **Alert e-mail is not configured until `SMTP_HOST` is set (MAIL-1).** Empty `SMTP_HOST` means no relay is configured, so nothing is sent and the channel fails closed. Set `SMTP_HOST` in `.env` and recreate the backend, worker and beat containers if alert e-mail is wanted.
- **A username with `SMTP_SECURITY=none` is refused (MAIL-1).** The credentials would cross the network in clear text. No connection is opened, no login is attempted, delivery fails with the code `insecure_login` and `doctor` reports FAIL (`email`, runbook OPS-R68). Use `starttls` or `ssl`, or clear `SMTP_USERNAME` for an unauthenticated plain relay.
- **`QRADAR_HEALTH` collects on by default (HLT-2).** `QRADAR_HEALTH_COLLECTION_ENABLED` defaults to `true`. It adds two aggregating Ariel searches per console every 15 minutes. It needs the custom properties `Metric ID`, `Element` and `Value` on each console: a console without them records the metric part as not collected and still runs the notification search.
- **The access check adds one Ariel probe per console every 6 h (ACC-1, ACC-3).** `QRADAR_ACCESS_CHECK_INTERVAL_SECONDS` is 21600 (minimum 300). The probe is recorded under its own caller `ACCESS_CHECK`. A cancelled probe is its designed end and is not counted as Failed.
- **Old geography buckets read as unknown (GEO-6).** Buckets stored before 0.1.11 keep NULL provenance. The map states how many of them do not record how and never guesses.
- **An 0.1.10 site upgrades directly.** `min_from` is `0.1.10`. A 0.1.9 site upgrades to 0.1.10 first. `qradar-dash` reads this file before any `.env` edit, bundle load or pull and refuses an older site with `upgrade refused: 0.1.11 requires at least 0.1.10; nothing was changed`.

## New for the operator

- **QRadar's health in detail, on the SIEM load page (HLT-1, HLT-2, HLT-3, HLT-5).** The QRadar section of `/admin/siem-load` now holds a managed-hosts table. One row per managed host, with role, appliance, version, status, EPS and FPM average and peak with allocated-of-limit, 24 hour and 7 day trends. A "Disk, system and pipeline" block per host holds the fullest allowlisted mount with used percent and free space, CPU, memory, load, swap, I/O wait, rule-engine queue and throttle spill. The busiest stage is the runnable share (FIX-22). QRadar's system notifications over 24 hours follow (top 50 groups plus a counted remainder). High-availability pairs are one host with one or two members. Pair states are `single`, `ha_healthy`, `ha_degraded`, `ha_failed_over`, `ha_failed` and `unknown`. EPS is counted once per pair. The section reads stored windows of the `QRADAR_HEALTH` family and the fresh health read, each with its own state. A field that was not read is never drawn as a zero. When `QRADAR_HEALTH_COLLECTION_ENABLED` is off, the page says so above the stored figures and names the last window collected in UTC. Free space is carried between the hourly totals (HLT-5). `DiskSpaceTotal` arrives once an hour. A mount with no total carries the newest total of the same console, host and mount from a window ending at most 2 hours before the latest window's end. The API carries `total_from` and the page says "total as of hh:mm UTC".
- **The QRadar health family behind it (HLT-2).** `QRADAR_HEALTH` is the ninth search family. Two aggregating searches per console per run run through the Ariel permit pool (REST/Ariel provider only). The metric list is fixed and the mount allowlist is `QRADAR_HEALTH_DISK_MOUNTS`. No payload is ever selected, and `Information Message` is excluded. Rows are kept `QRADAR_HEALTH_RETENTION_DAYS` (default 35) by a daily deleter. The page's "Failed" definition in the guide counts abandoned searches (their worker stopped before recording an end). The WAF guide states that refused over quota means the search stayed unsent.
- **Four `doctor` lines (HLT-1, HLT-2, FIX-20).** `qradar_disk` (OPS-R69) FAILs at the fail share and WARNs at the warn share of the fullest allowlisted mount (defaults 85 and 95 percent). It names the host, the mount, the share and the free space. A missing, failed, partial or stale run is a WARN with "not collected since <time> UTC". `qradar_pipeline` (OPS-R70) WARNs when a host spilled events to disk or its rule-engine queue is above `QRADAR_HEALTH_CRE_QUEUE_WARN` 10000. `qradar_health` is HA-aware (OPS-R67): the standby of a healthy pair is never a problem, a cut server read WARNs, and a pair with no active member FAILs. `watermarks` and `errors_recent` name switched-off families after `not judged (family off):` and do not change the status (FIX-20). Rows with no family switch (`log_source_metric`, `offense_snapshot`, the inventories) are judged as before. Checks MT-133 to MT-135 and MT-136 cover the surface (HLT-4, AQL-1).
- **QRadar access, stored and paged (ACC-1, ACC-2, ACC-3).** Every 6 hours and on demand, each enabled REST console is asked which of its 14 APIs the token reaches. The 14 are system_about, managed_servers, deployment_hosts, license_pool, ariel_search_list, ariel_searches, log_sources, log_source_types, log_source_groups, custom_properties, property_expressions, analytics_rules, building_blocks and offenses. `/admin/qradar-access` (under Administration, `admin:*`) shows the verdict per console. The last check is shown in UTC with its age. Refused rows come first, then not answered or unchecked, then ok. The page states what to ask the QRadar administrator for (IBM hints labelled as hints). "Check now" is `POST /api/v1/admin/qradar-access/check` (202, rate limited `RATE_LIMIT_ACCESS_CHECK` 2 per minute, one run per console at a time). It queues the check for the worker and answers at once. Polling stops on unmount, pauses while the tab is hidden and ends after 3 minutes. The guide has a qradar-access section, and a forbidden figure on the SIEM load page links here. `doctor qradar_access` (OPS-R71) reads the stored result and sends no search. Plain `doctor` sends no search.
- **`doctor --aql` tries every family's real query once (AQL-1).** The opt-in flag sends each collection family's own provider method over the latest complete 5-minute bucket with the smallest row cap (1 row). One family and one console at a time run through the permit pool. Nine checks `aql_<family>` result, listed below.

  - `aql_log_source_volume`, `aql_rule_match`, `aql_history`, `aql_waf_collection`, `aql_ips_collection`, `aql_property_watch`, `aql_catchall_senders`, `aql_geo_collection`, `aql_qradar_health`.
  - PASS: the search completed (a truncated result still PASSes and says so).
  - FAIL: QRadar refused the search request (400, 404, 409, 422 or another 4xx), refused the token (401 or 403), or a property the query needs is absent. The line names the step that failed, the HTTP status, the query version and the property names, never QRadar's reply (AQL-2).
  - WARN: timeout, unavailable console, rate limiting (429), a 5xx, a search QRadar created and then errored, or no free permit (AQL-2).
  - SKIP: family off, nothing configured, or the console uses MCP.
  - Every search a family sends per cycle is tried (AQL-2): WAF sends 2 for the volume method plus 1 per breakdown its profile collects (up to 3), IPS sends 1 per planned dimension (up to 7), QRADAR_HEALTH sends 2, and each of the other six families sends 1. That is at most 20 searches per REST console. One failed step does not stop the others. A family without a query version says "this family's query has no version number". A long configured property name is printed in full. The searches are recorded under the caller `DOCTOR_AQL` (migration 0053), so a doctor run never shows as family load. Waits `DOCTOR_AQL_TIMEOUT_SECONDS` (default 60, 10 to 600). Runbook OPS-R72 and check MT-136.
- **Alert e-mail, end to end (MAIL-1, MAIL-2, MAIL-3).** Templates and recipients are administered at `/admin/email` ("Alert e-mail", `admin:notifications`). There is no password input or value anywhere on the page. A shipped default template in code covers every alert type, per-type rows override it and reset is one DELETE. Fifteen allowlisted `{{ placeholder }}` names are refused on save when unknown. Saving returns the sanitised HTML and says whether the sanitiser changed it (no `url(`, no `expression`, no `javascript:`, links only `{{ alert.url }}`, `https:` or `mailto:`). Multipart text and HTML is sent over `starttls`, `ssl` or `none` with verification always on for the TLS modes. A relay that does not offer STARTTLS is refused. The sandboxed preview and test send carry the current editor (MAIL-2, MAIL-3). The in-app guide gained an alert-email section. `./qradar-dash doctor --check-smtp` (alone or with `--json`) connects, says EHLO, finishes the handshake and quits. Nothing is sent and no login is attempted.
- **The session commits before the response is sent (FIX-23).** `SessionDep` uses `scope="function"`, so the commit runs when the path function returns. A request after a sign-in no longer races the commit. A failed commit now surfaces as a 500 instead of being lost after a 200.
- **The load summary folds in PostgreSQL (ARL-4).** `/admin/siem-load` and the `ariel_load` CLI fold the window in two statements instead of loading every row into Python. On 100000 rows over 720 hours the measured time went from 1081 to 137 ms. The JSON is identical (same keys, order and integers). The existing `submitted_at` index serves both statements. A flaky guide-seen test that failed under load was fixed to wait for the passive effect before counting (FIX-21).
- **A search whose worker died is closed as `ABANDONED` (ARL-5).** The beat task `reap_abandoned_ariel_searches` (every `ARIEL_SEARCH_ABANDON_SCAN_SECONDS` 600, 60 to 86400) closes an `IN_FLIGHT` row older than the longest wait a search may have plus the scan interval. Measured columns stay null. The load summary counts it as Failed. A terminal write that arrives later still overwrites it. `docs/OPERATIONS.md` no longer says such rows stay `IN_FLIGHT`.
- **The world map's provenance is stored per bucket (GEO-6, GEO-7).** See the analyst section for the provenance line and Kosovo.
- **The manual test follows the code (DOC-7, DOC-8, HLT-4).** MT-99 states each family's own cadence plus 3 minutes: 8 minutes at most for Log source volume, Catch-all senders and Rule matches, 18 minutes for WAF and IPS collection. An off family's scope rows do not move (DOC-7). MT-102 states rule health is its own 30 minute beat task (`RULE_HEALTH_EVALUATION_INTERVAL_SECONDS` 1800). MT-10 carries the measured 0.1.10 upgrade times with their cases: online (pulls inside the command) 99 s wall and 25.9 s of outage, offline from the bundle 80 s wall and 20.3 s, images already on the machine 47 s wall and 21.3 s. Each carries "this is not a promise" (DOC-8). MT-09 states `qradar_health` is SKIP with "the console did not answer; see qradar_auth" when the console does not answer. Section 14 states which commands send an Ariel search: plain `doctor` none, `doctor --aql` up to 20 per console, the access check exactly one probe per console per check.

- **Tables that fit (POL-15, POL-16).** In the SIEM load page's "Load by caller", wall p50 and p95 and QRadar execution total and p95 are stacked in one cell each, so the table fits at 1024 pixels. On the same page, a host name never breaks inside a label and breaks only after a dot. The notification name column takes the slack and wraps between words.

The line under the map states how the plotted buckets were collected. "Collected from the QRadar property ..." or "Collected with QRadar's GEO::LOOKUP". In a Dashboard widget the Not collected and Insufficient data states are a centred block filling the frame instead of a blank frame.
- **Less text on eleven pages (D40-2).** First-screen prose at 1440×900 went from 937 to 510 words across the SIEM load, behavior and WAF behavior, rules, search-cadence, e-mail, QRadar access, ips-sources, catch-all, classification-rules and outage-policy routes. Page descriptions that restated the heading became "Times are UTC.". Tutorial footnotes moved into the guide sections that already carry them. No time zone, unit, threshold or honesty state was cut.

## API

- **New (`admin:notifications`), under `/api/v1/admin/email`:**

  - `GET /settings`, `GET /placeholders`, `GET /templates`, `GET /templates/{key}`, `PUT /templates/{key}`, `DELETE /templates/{key}`.
  - `POST /preview`, `POST /test` (rate limited `RATE_LIMIT_EMAIL_TEST`; the relay's text is never returned).
  - `GET /recipients`, `POST /recipients`, `PUT /recipients/{id}`, `DELETE /recipients/{id}`.
  - Writes are audited by size, not markup.
- **New (`admin:*`):**

  - `GET /api/v1/admin/qradar-access` (the stored check per console; carries `check_running`, `last_check_started_at` and `last_check_finished_at`).
  - `POST /api/v1/admin/qradar-access/check` (202 with `started`, `already_running` and `failed`; rate limited 2 per minute).
  - `GET /api/v1/admin/qradar-health/latest` (newest stored window per console; optional `notifications_hours` 1 to 168). Carries `collection_enabled` and `MountValue.total_from` when the total was carried.
  - `GET /api/v1/admin/qradar-health/history?hours=24|168` (per-host series of the fullest mount, the rule-engine queue, the throttle spill, reachability and latency).
  - Each part carries its state (OK, PARTIAL, STALE, NOT_COLLECTED, FAILED) with reason code and sentence. No window gives NOT_COLLECTED, never zeros.
- **`GET /api/v1/geo/countries`** adds `collected_with`. `ways` holds `country_source`, `country_property` and `buckets`. `unknown_buckets` holds the rest. It is null while NOT_COLLECTED. The stored setting fields stay (the current setting, not what the buckets used).
- **`GET /api/v1/admin/ariel-load` and `/current`** now include the `ABANDONED` outcome and the callers `DOCTOR_AQL` and `ACCESS_CHECK`. A cancelled `ACCESS_CHECK` probe is not counted in `failed`. `ERROR`, `TIMEOUT`, `ABANDONED` and `PROVIDER_UNAVAILABLE` stay failed for every caller. The load summary's `load_summary` output is byte-identical to the Python fold it replaced.
- **The 429 body (FIX-23)** carries `limit` as the rate text (for example "2 per 1 minute" for the sign-in limit), not a Python object repr. `Retry-After` stays on the 429 only. `X-RateLimit-Limit`, `X-RateLimit-Remaining` and `X-RateLimit-Reset` stay on every counted response, as before.
- **The generic webhook now carries the real alert id (MAIL-1).** Notification delivery builds `alert_id` from the `alert_notification.alert_id` column instead of the stored payload copy (`***redacted***` from `redact()`), so the e-mail link is not dead. Only the generic webhook carries the id; Teams, Slack and syslog never did.
- **`GET /api/v1/version`** reports `migration_head` `0054` after the upgrade.

## Schema

The head is `0054`. 0.1.11 adds seven migrations. Each is additive and needs no backfill beyond the unknown reading for `0049`. `alembic check` stays clean.

- `0048_email_templates_recipients` (MAIL-1): the tables `email_template` and `email_recipient`. No server default outliving the revision except the timestamps.
- `0049_geo_bucket_provenance` (GEO-6): the nullable columns `geo_country_bucket.country_source` and `country_property` with a check constraint. Older rows stay NULL (unknown).
- `0050_qradar_health_detail` (HLT-2): the hypertables `qradar_health_run`, `qradar_health_metric_bucket`, `qradar_health_notice_bucket` and `qradar_health_rest_sample`, plus the `QRADAR_HEALTH` cadence row and caller.
- `0051_qradar_access_result` (ACC-1): the tables `qradar_access_result` and `qradar_access_run`, one row per console and catalog entry plus the run claim.
- `0052_ariel_search_abandoned` (ARL-5): the `ABANDONED` outcome. The downgrade returns such rows to `IN_FLIGHT`.
- `0053_ariel_caller_doctor_aql` (AQL-1): the `DOCTOR_AQL` caller. The downgrade deletes its rows first.
- `0054_ariel_caller_access_check` (ACC-3): the `ACCESS_CHECK` caller. The downgrade deletes its rows first.

A site coming from 0.1.10 runs them once, in order. A rollback is a restore of the upgrade's backup, as always. No migration is ever run downward on a site.

## Upgrade

```bash
git fetch --tags && git checkout v0.1.11
./qradar-dash upgrade 0.1.11
```

The upgrade is allowed from `0.1.10`. A site on 0.1.9 upgrades to 0.1.10 first; the 0.1.10 notes describe that path. An older release is refused before anything is touched (FIX-12): the refusal comes from the checkout's own `docs/releases/0.1.11.md`, read before any `.env` edit, bundle load or pull — `upgrade refused: 0.1.11 requires at least 0.1.10; nothing was changed`. If that file is missing, unreadable or not for 0.1.11, the refusal names the file and changes nothing either. The migrations run once (`Running upgrade 0047 -> 0048`, then `0048 -> 0049`, `0049 -> 0050`, `0050 -> 0051`, `0051 -> 0052`, `0052 -> 0053`, `0053 -> 0054`), and after the upgrade `/api/v1/version` reports `migration_head` `0054`. The upgrade takes its own backup before it migrates, as every upgrade does, and that backup carries the install answers. The collection families resume on their cadence; the pages show "stale" or "not collected" until the first cadence after the upgrade has passed, and that is correct.

**After the upgrade, set `SMTP_HOST` in `.env` if alert e-mail is wanted, recreate the backend, worker and beat containers so they read it, and check `./qradar-dash doctor` for `email`, `qradar_access`, `qradar_disk` and `qradar_pipeline`.** The health family collects within its 15 minute cadence; the access check runs on the worker start and every 6 hours, or on demand from the QRadar access page. `./qradar-dash doctor --aql` (after an upgrade, with the console quiet) shows whether each family's real query is accepted.

On a host with no registry access, make the bundle on a connected host from the same checkout (`./qradar-dash bundle --output DIR` writes `qradar-dash-0.1.11-bundle.tar` in that directory; without `--output` the file is written in the current directory, and an existing file is not overwritten), copy it over, and run, in the installation directory:

```bash
tar -xf /path/to/qradar-dash-0.1.11-bundle.tar --exclude=images.tar
./qradar-dash upgrade 0.1.11 --offline /path/to/qradar-dash-0.1.11-bundle.tar
```

If the upgrade fails and the site must return to 0.1.10, follow `docs/OPERATIONS.md`, "Geri alma (`rollback`)": it restores the backup the upgrade took — including the install answers and the `0047` schema — and starts the previous images. Data written since the upgrade is kept only in the broken copy it leaves. `rollback` runs no `git checkout`; after a successful rollback the operator returns the checkout to the version that now runs (`git checkout v0.1.10`), as that section says. A return to 0.1.11 is then `git fetch --tags && git checkout v0.1.11` and `./qradar-dash upgrade 0.1.11`.
