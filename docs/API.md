# API and interface reference

The backend serves a versioned REST API under `/api/v1`. The browser talks only to this API; it
never receives a QRadar credential and never connects to QRadar or the optional MCP service.

OpenAPI documentation generated by FastAPI is the endpoint-level contract. This document groups
the public surfaces and records the authorization and data-honesty rules that apply across them.

## Authentication and authorization

Health and build-version endpoints are public. Login is public; logout and password change require
an authenticated principal. `/me` returns only that principal's identity and effective grants.

All product routers are guarded when mounted. Adding a handler to a guarded router therefore cannot
make it anonymous accidentally. Read-only roles commonly use `read:*`; writes require the specific
capability or `admin:*`.

| API group | Read requirement | Additional write requirement |
|---|---|---|
| `/overview` | `read:overview` | none |
| `/log-sources` | `read:log_sources` | `log_source:write` or administrative inventory access |
| `/searches` | `read:searches` | `search:write`; execution also needs `search:execute` |
| `/alerts` | `read:alerts` | `alert:ack` or `alert:resolve` |
| `/admin/search-cadence` | `read:search_cadence` | `admin:search_cadence` |
| `/offenses` | `read:offenses` | none |
| `/rules` | `read:rules` | `rule:write` |
| `/coverage` | `read:coverage` | `coverage:write` |
| `/providers` | `read:providers` | none |
| `/anomalies`, `/behavior` | `read:anomalies` | none |
| `/waf` | `admin:waf` | same administrative capability |
| `/ips` | `admin:ips` | same administrative capability |
| `/fleet`, `/classification-rules`, `/fleet/catchall` | `read:fleet` | `admin:classification` or `log_source:write`, depending on action |
| `/geo` | `read:geo` | none |
| `/outage-policy` | `admin:outage` | same administrative capability |
| `/dashboards` | `read:dashboards` | `dashboard:write`; sharing needs `admin:dashboards` |
| `/custom-rules` | `read:custom_rules` | `custom_rule:write` |
| `/property-watches` | `read:property_watches` | `property_watch:write` |
| `/auth/admin` | `admin:auth` | same administrative capability |
| `/users` | `admin:users` | same administrative capability |

`read:*` does not grant any write capability. `admin:*` grants every administrative, read and write
capability.

## Behavioral incidents

`GET /anomalies` is the unified incident list. A detail read returns the subject, lifecycle,
detector observation, expected range and evidence metadata. Source-volume, WAF, IPS and
property-watch incidents share the analyst surface while retaining their own anomaly taxonomies.

The investigation page exposes every expected evidence dimension even when it is unavailable. An
unavailable dimension includes a reason and is never hidden as though it were checked and clean.
Evidence states are explicit: `NOT_REQUESTED`, `PENDING`, `COMPLETE`, `PARTIAL`, `UNAVAILABLE` and
`FAILED`.

Null means unmeasured. A measured zero remains `0`. Partial or missing chart buckets are gaps and
are not connected across an outage. Expected ranges are returned and drawn as bands.

## WAF profiles

Each WAF source has a versioned mapping from logical URL, method, virtual-host, action,
response-code, rule and user-agent fields to QRadar properties. The profile also defines which
action values mean blocked or allowed.

The property catalog contains names and types only. Any property name that passes the syntax guard
may be entered, but a profile must validate against read-only bounded Ariel probes before it can
collect. A mapping change increments the profile version and pauses collection until that version
is valid. Stale concurrent edits return `409`. Every mutation and validation result is audited.

## IPS profiles and analyst reads

The `/ips` administration API supplies the mapping schema, candidates, profiles, validation,
history and property catalog. Mapping changes are versioned and stale writes return `409`. There is
no IPS profile CLI.

Analyst reads live under `/behavior/ips`: sources, entities, metrics and seasonal baselines. IPS
incidents also appear in `/anomalies`. An unmeasured bucket is `null`; source IP values are not
served outside a bounded stored contributor list, and these routes do not expose that list.

## Property-watch API

All paths below are under `/property-watches`.

| Method and path | Purpose |
|---|---|
| `GET /catalog` | Collection mode, detector catalog, caps and preview bounds |
| `GET /scope-options` | Search synced sources, types and groups |
| `GET /property-options` | Properties applicable to the selected scope |
| `GET /` | List watches with status, reason, coverage and last bucket in UTC |
| `POST /` | Create a disabled watch |
| `GET /{id}` | Read one watch and its detector state |
| `PATCH /{id}` | Edit, enable or disable with optimistic concurrency |
| `DELETE /{id}` | Resolve open state and delete, unless a rule pins a value |
| `GET /{id}/scope` | Resolved members, inventory age and membership history |
| `GET /{id}/buckets` | Coverage, measurements, admission and scope-change flags |
| `GET /{id}/aql` | Return generated read-only AQL without running it |
| `GET /{id}/values` | Tracked values, current reading, band and learning progress |
| `GET /{id}/series` | Bulk series for at most twelve values |
| `POST /{id}/preview` | Run one bounded, rate-limited Ariel preview |
| `PUT /{id}/pins` | Replace pinned values and report dependent threshold rules |

Preview history is limited to 1–168 hours and defaults to 24 hours. Audit records store counts and
digests of pinned values, never the values themselves.

## Custom threshold rules

Custom rules evaluate stored aggregates only. The metric catalog defines the subject, unit and
whether a lower bound can prove an increase. A rule names a stored subject, operator, threshold,
sustain period, recovery period and severity; it never contains free-form subject text.

The API supports list, create, detail, patch, delete, draft preview, stored-rule preview, catalog
and breach history. New rules are safe to preview without persisting, alerting or running Ariel.
Writes use optimistic concurrency. Domain validation returns all reasons together; duplicate names
and enabled-cap conflicts return `409`.

Rule status is explicit: disabled, subject retired, not collected, stale, open, recovering, OK or
no verdict. A never-evaluated null is not OK. Unmeasured and maintenance buckets pause hysteresis;
they are not treated as zeros.

## Scheduled searches

Only stored, validated and versioned AQL executes. A new search is disabled. The API validates time
range, timeout, row and concurrency bounds, and requires new or changed cron expressions to leave at
least five minutes between runs.

`GET /searches/{search_id}/results` returns stored aggregates oldest first. It accepts:

| Parameter | Default | Notes |
|---|---|---|
| `metric_key` | `total` | Total or one stored grouped dimension |
| `start`, `end` | unbounded | Inclusive; naive timestamps are interpreted as UTC |
| `limit` | `500` | Maximum `5000`; the most recent matching points win |

Each point carries execution state, duration, result count, threshold state and query version. A
failed execution creates a chart gap, not a zero. Query-version boundaries are marked because data
on either side may not be comparable.

The dispatcher seeds a new search without running it immediately, runs one catch-up after downtime,
deduplicates repeated delivery by run key, skips a still-running execution, preserves schedule state
for malformed cron text, and caps the number dispatched per cycle.

## Geography

`GET /geo/countries` requires timezone-aware `since` and `until`, an ordered interval within the API
range cap, and `direction=SOURCE` or `DESTINATION`. It returns countries, unresolved/over-cap/
unparseable remainder counts, exact or lower-bound measurement, expected and measured bucket counts,
and one of `NOT_COLLECTED`, `INSUFFICIENT_DATA`, `PARTIAL` or `OK`.

Private, internal and unknown addresses all produce the same unresolved lookup result in QRadar and
cannot be distinguished. No address is selected or stored by this collector.

## Dashboards

Dashboard records store widget identity, geometry and bounded configuration, never executable
content. Layout version and size are validated. Owners can see their private dashboards; every
reader can see shared dashboards. Updates carry an expected revision and return `409` with the
current revision on conflict. Audit entries include the dashboard name, revision and widget count,
not the layout.

## Alerts and operator actions

The shared alert lifecycle is `OPEN → ACKNOWLEDGED → RESOLVED`. A partial unique index on the active
deduplication key prevents two unresolved alerts with the same fingerprint.

Alerts can originate from behavioral incidents, stored-search thresholds, repeated search failure,
custom-rule breaches, new inventory, new catch-all senders and stale offense collection. Each
condition has its own fingerprint. Recovery and operator actions enqueue notifications through the
same transition pipeline.

Acknowledge, resolve and manual-search actions are authorized by the backend. The browser receives
identifiers and ordinary display values, never credentials. Notification enqueueing is separate
from delivery; the worker retries and dead-letters failures without delaying the HTTP response.
