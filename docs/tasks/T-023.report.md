## What I did

- **Permissions/guards:** reads need `read:fleet`; rule writes check `admin:classification` and override/review check `log_source:write`, in the handler before any lookup (403 before 404).
- **Summary:** per class (all classes except QRADAR_INTERNAL): enabled/disabled counts, expected/complete/partial/missing bucket counts, events and mean EPS, expected EPS (sum of reliable `average_eps` medians for the current UTC weekday-hour) with `baseline_sources`/`baseline_share`, open unsuppressed Phase A incidents by type, top 5 sources. Top level: `internal` source counts (apart), `new_sources`, `conflict_sources`, `unclassified_sources`. The window ends at the last closed 5-minute bucket (`collection_interval_seconds`).
  - Only COMPLETE buckets feed events/EPS. No complete bucket gives `events: null`, `mean_eps: null`, never 0. Mean EPS is the sum of per-source rates over each source's measured seconds, so a gap does not dilute it.
  - A source with no classification row counts as UNCLASSIFIED.
  - Statement count is 4 (plus none per class/source), pinned at 10 vs 400 sources for 1h and 7d.
- **Sources list:** filters `class`, `review_status`, `has_conflict`, `basis`; `items/total/limit/offset`; sources lacking a row appear as UNCLASSIFIED with null review fields.
- **Override:** set/clear via `classify_sources` upsert (one source), audited `{from, to, class}`; review state untouched.
- **Review:** sets `reviewed_at/by`, resolves the source's inventory alert via `AlertService.apply_bulk`, enqueues the resolve notification like the alert route, audits; second call returns the row unchanged with no audit and no alert work. Classifying does not resolve it (tested).
- **Rules:** built-ins accept only `enabled` (else 409; DELETE 409); patterns <= 256 chars, regex kinds compiled (422); GROUP/TYPE need a numeric pattern; UNCLASSIFIED target rejected; null fields 422; uniqueness 409 via savepoint; every change audited and re-classifies its instance (all instances for a global rule); statement count pinned at 5 vs 200 sources.
- **Routing:** `source_classes` matched against `alert.context["source_class"]`; inventory alerts already carried it (T-022); anomaly alerts now do. Anomaly fingerprint literals are pinned in a unit test and `fingerprint.py` is unchanged.
- **Break-and-restore verified:** dropping the null-on-incomplete handling failed the summary tests; disabling the built-in guard failed the built-in test; disabling the class check failed three routing tests; removing the already-reviewed guard failed the review test. All restored.
