## The question each view answers

- **`/fleet`**: "Which classes of log sources are off their normal volume right now, and what needs
  my review?" — per class: sources (enabled / disabled), events and EPS in the window against the
  expected EPS (with the share of sources that have a baseline), completeness, open Phase A
  incidents by type, and the top sources; a 1 h / 24 h / 7 d window switch; the NEW, conflict and
  UNCLASSIFIED counts as entry points to the review queue. Internal (QRadar) sources apart, as the
  API returns them.
- **`/fleet/sources`**: "Which sources are new or ambiguously classified, and what should their
  class be?" — the filters the API offers (class, review status, conflict, basis); per row: name,
  DSM type, class with its basis and the rule that matched, conflicts in words ("type says IPS,
  name says LINUX"), first seen (UTC), auto-discovered, review status; actions: set or clear the
  override class, mark reviewed.
- **`/admin/classification-rules`**: "Which rules decide a source's class, in what order?" — the
  precedence (§C.3) stated once; rules grouped by level; built-in rules show only an enable toggle
  (other edits are refused by the API with 409, so do not offer them); custom rules can be created,
  edited and deleted, with the pattern validated server-side (422 message shown at the field).

## Honesty (§3a, guidelines §4/§6)

- A class with no complete measurement shows "not measured" — never `0`, never `0 EPS`.
- Expected EPS is shown with its basis ("expected from N of M sources with a baseline"); with no
  baseline, an em dash with its meaning. Completeness (complete / expected buckets) is visible
  next to the figures it qualifies.
- Numbers carry units, tabular figures, right-aligned in tables. Times in UTC with the zone.
- No row of identical KPI cards. The NEW / conflict / UNCLASSIFIED counts are links in a sentence
  or a compact summary line, not three cards.
