## Questions to answer

Answer each question with measured facts. Write "not measured" where you could not measure, and
say why.

### G1 — log-source inventory and classification

1. **Endpoints.** QRadar serves an endpoint catalog at `GET /api/help/endpoints`. List every
   endpoint path and method under `/config/event_sources/`, `/analytics/` and `/siem/`, and any
   path containing `rule`, `group` or `log_source`.
2. **Log-source fields.** Give the full key list of a 7.6 log-source row. For each of
   `group_ids`, `auto_discovered`, `average_eps`, `creation_date`, `modified_date`,
   `last_event_time`, `status`, `enabled`, `type_id` and `protocol_type_id`, say whether it is
   present and how it is populated across the lab's sources: counts, value shapes, and the units
   of the timestamps.
3. **Groups.** Does `/config/event_sources/log_source_management/log_source_groups` exist? Give
   its fields, the lab's groups (`id`, `name`, `parent_id`, `assignable`), how many sources each
   holds, and whether the hierarchy matters (nested groups).
4. **Types.** Give the field list of `log_source_types`. Is there any category or vendor field?
   Give the type ids and names for "SIM Generic Log DSM", the Universal DSMs, and any other
   catch-all types.
5. **SIM Generic.** How many lab sources have a SIM Generic type? How are they named? Were they
   auto-discovered? Run one bounded AQL over the last 60 minutes giving event counts per SIM
   Generic source, and say whether the sender can be identified (for example by identifier,
   source IP, or the log source name). Also count `Unknown` / unparsed events per source type if
   that is cheap: one search.
6. **EPS.** Is `average_eps` on the REST row populated? Compare it, for 3 sources, with
   `SUM(eventcount)/3600` from one bounded AQL over the same hour.
7. **Naming.** List the lab source names, grouped by type. Would a case-insensitive token regex
   such as `\b(waf|ips|linux|windows|fw|firewall)\b` classify them? Report the hits and misses.

### G3 — rules

8. **Rule fields.** Give the full key list of `/analytics/rules` and of `/analytics/building_blocks`.
   For `average_capacity`, `base_capacity`, `base_host_id` and `capacity_timestamp`:
   - how many rules have each, split by enabled and disabled;
   - the value ranges;
   - the units, if the API help or the values reveal them;
   - whether `capacity_timestamp` changes between two reads at least 10 minutes apart.
9. **Groups and statistics.** Does `/analytics/rule_groups` exist, and what are its fields? Does
   the catalog from question 1 list any rule-statistics, rule-performance or rule-test endpoint?
   Give the exact paths, and fetch each one with `GET`.
10. **Rule logic.** Does any `GET` endpoint return a rule's tests, its logic, or its XML? If one
    does, show the shape of the response for one system rule; redact nothing, since rule
    content is not a secret. If none does, say so.
11. **Firing counts.** Find an AQL that gives per-rule match counts over the last 60 minutes from
    `creEventList` (for example with `RULENAME(...)`, or by grouping on the list). For each
    attempt, report:
    - the exact AQL;
    - accepted or rejected, with the error text;
    - the run time;
    - the row count;
    - whether building blocks appear among the rules;
    - whether one event matching several rules is counted once per rule.

    Use at most 6 of your 12 searches on this.
