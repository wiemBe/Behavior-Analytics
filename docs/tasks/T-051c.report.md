## 2. What I did

- Engine: subjects are the active entities of the three dimensions plus the source. A missing metric row uses `observe_entity`'s absence rule. Loads are bulk (facts, entities joined with metrics, cells, states, anomalies, novelty: history, first-appearance bucket, events since first seen). Writes go in one flush; the fingerprint is set at creation.
- Pipeline: all watermarks of the instance load in one statement. Per source, in a savepoint: buckets after the evaluation watermark and not past the collection watermark, oldest first, bounded per run and sized to the cadence; the watermark advances per bucket. A failure rolls the source back, records the sanitized class on its evaluation watermark (`ips_evaluation:<qradar_id>`) and continues with the others. Training follows evaluation.
- Statement count is pinned at 5 and 200 entities with every detector, first run and steady state.

### Inherited work: what was wrong

1. `test_a_new_port_opens_on_a_verified_history` was a wrong test, not an engine bug: it seeded 24 hourly history buckets (its comment said `ips_new_port_history_days=1`) but never set that setting, so the default 7-day history was correctly `INSUFFICIENT_DATA`. Both new-port tests now set `ips_new_port_history_days=1`; expectations unchanged.
2. The pipeline tests passed `engine_factory=None`, overriding the default and crashing; the pipeline now falls back to the real engine and builder.
3. Real defect: `IpsBaselineBuilder.rebuild_due` is not scoped to a source, but training ran per source with that source's own bound. A source ahead of another could teach the other's baseline from buckets not yet judged. Training now runs once per instance with `train_through` = the earliest evaluated bucket end across the instance's sources, and is skipped (`baseline_skipped`) if any source failed or has evaluated nothing. Baseline fields moved to the instance report. New test `test_training_stops_at_the_least_evaluated_source`.
4. One test assertion compared `log_source_id` on entity incidents (always `None`); it now compares `ips_entity_id`.
5. A new mypy error in the pipeline was fixed.
