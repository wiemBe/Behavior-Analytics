# Task B-2.1 — `GET /fleet/eps-series`: the fleet's observed EPS over time, fail-closed

Read `AGENTS.md` at the repository root first and follow it exactly. These rules matter most here:
- **rule 8: fail closed.** A bucket where any in-scope source is not measured has **no value**
  (`null`), never a smaller sum. A fleet sum over a bucket with a missing source understates and
  reads as a drop;
- **rule 9 spirit:** a constant number of SQL statements per request, whatever the number of
  sources or classes. No query per source, per class or per bucket;
- no QRadar call: this reads stored buckets only;
- §4: never weaken a test; stop and report a conflicting test.

  - a **monitored** source is `LogSource.enabled AND LogSource.monitoring_enabled`;

## The endpoint

`GET /fleet/eps-series?window=1h|24h|7d&group_by=none|class`, in `app/api/routes/fleet.py`, under
the existing fleet router (so `read:fleet` guards it already). `window` reuses `FleetWindow`;
`group_by` defaults to `none`. Anything else is a `422`.

### Steps

A chart cannot draw 10,080 one-minute points for 7 days. The server picks a **step** per window:
`1h` → the collection bucket (`collection_interval_seconds`), `24h` → 300 s, `7d` → 3600 s. If the
bucket width does not divide a step, use the bucket width. Put the mapping in one constant with a
one-line comment, and return `step_seconds` in the response.

### One point per step (per series)

```
{ step_start, events, eps, expected_eps,
  cells_complete, cells_expected, sources_expected }
```

- `sources_expected`: the monitored, non-internal sources in the series' scope (the whole fleet,
  or one class).
- `cells_expected = sources_expected × (step_seconds / bucket_seconds)`.
- `cells_complete`: how many of those (source, bucket) cells have a `COMPLETE` metric row.
- `events`, `eps`: the sum over the step's complete cells, **only when
  `cells_complete == cells_expected` and `cells_expected > 0`**; otherwise both are `null`. `eps`
  is events over `step_seconds`.
- `expected_eps`: the sum, over the in-scope sources, of each source's reliable `average_eps`
  median for the step's UTC weekday and hour. **Null unless every in-scope source has a reliable
  cell** for that step. It is "the sum of per-source expected", not a fleet band: **never return
  `p05`/`p95` sums or any band.**
- A metric row of a source that is not monitored now (disabled since) does not count. Say in the
  report how you handle a source that was added during the window (it has no metric rows before
  it existed, so with the rule above those steps are `null`); if you choose differently, justify
  it against rule 8.

### Response

```
{ window, group_by, window_start, window_end, bucket_seconds, step_seconds,
  series: [ { key, label, sources_expected, points: [...] } ],
  coverage: { steps_total, steps_measured } }
```

- `group_by=none`: one series, `key` `"FLEET"`.
- `group_by=class`: one series per `SourceClass` that has at least one monitored source, in
  `SourceClass` enum order, `QRADAR_INTERNAL` excluded.
- Every step of the window is present in `points`, oldest first, even when its values are `null`.
  A missing step is not an empty one.
- `coverage` counts steps with a non-null `eps`, summed across series.

### Statements

A **constant** number: at most one for the sources, one for the metrics (grouped by series and
step, with `COUNT(*) FILTER (WHERE completeness = 'COMPLETE')` and the complete events), and one
for the baselines. Fold in Python. Pin it with the repository's statement-recording helper at two
source counts (for example 3 and 40 sources) and both `group_by` values.

## Tests

- **Unit or integration, as the existing fleet summary tests do** (look at
  `tests/integration/test_fleet_summary*.py` or equivalent):
  - all sources complete → values; one source's bucket `PARTIAL` or missing → that step `null`
    with the right `cells_complete`;
  - `expected_eps` null when one source lacks a reliable cell; the sum when all have one;
  - `group_by=class` splits correctly, excludes `QRADAR_INTERNAL`, and a class with no monitored
    source has no series;
  - a disabled or unmonitored source raises neither `sources_expected` nor any sum;
  - step mapping per window, and every step present;
  - window end at the last closed bucket;
  - a bad `window` or `group_by` is a `422`;
  - a principal without `read:fleet` gets `403`; `read:*` is allowed;
  - the statement count is the same at both sizes.
- Break the code on purpose for at least four guards (for example the completeness rule, the
  reliable-cell rule, internal exclusion, the monitored filter) and confirm a test fails; list
  them.
