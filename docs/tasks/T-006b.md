## The problem

`detect_new_endpoint_access` (`app/waf/behavior.py`) needs `ctx.novelty`, a `NoveltyFacts`, and
nothing produces one. Without it the detector can only ever return INSUFFICIENT_DATA.

Read the detector's docstring. The claim it makes is narrow:

> in every bucket of the history window before the endpoint's first appearance — each recorded,
> with whole discovery and whole admission, under the same profile and normalizer — the endpoint
> was not requested often enough in any one bucket to be admitted.

Its input requirement is in `app/anomaly/capabilities.py`: `ENDPOINT_HISTORY` must be EXACT,
via `HistoryFacts(complete=True)` from `app/waf/inputs.py`.

## What to build

For every endpoint the engine judges in a bucket, compute `NoveltyFacts`
(`app/waf/behavior.py`) **in bulk**:

- `first_seen_at`: from `WafEndpoint.first_seen_at`. A reactivated endpoint keeps its original
  value; that is deliberate.
- `window_end` = `first_seen_at + waf_new_endpoint_window_buckets × bucket_seconds`.
- `within_window` = the judged bucket starts before `window_end`.
- For an endpoint outside its window, nothing more needs loading. Return facts whose
  `within_window` is False. The detector answers "established" from that alone.
- **History.** The history is the window
  `[first_seen_at − waf_new_endpoint_history_days, first_seen_at)` of the endpoint's source. It is
  complete only when all of the following hold:
  - every bucket in it was collected, with no gaps; compare the count against the window length
    divided by the bucket width;
  - each of those buckets has `groups_truncated` False and `admission_truncated` False;
  - each has the same `profile_version` as the first-appearance bucket;
  - each is compatible with the endpoint's normalizer version.

  Otherwise produce `HistoryFacts(complete=False, reason=...)`. The reason names the first
  failing condition, for example "3 of 2016 history buckets were never collected".
- `history_start`, `history_end`, `history_buckets`: as verified.
- `appearance_flood`: set when the first-appearance bucket itself had truncated discovery or
  admission.
- `requests_since_first_seen` and `buckets_with_traffic`: over the endpoint's rows from
  `first_seen_at` through the judged bucket.
- `lower_bound`: True if any of those buckets counted only a lower bound.

Then:
- pass `HistoryFacts` to `waf_input_scope(detector_type, obs, history)`;
- register `detect_new_endpoint_access` in `WAF_DETECTOR_FUNCTIONS`;
- set `ctx.novelty`.

It has no enabling setting: it runs whenever WAF collection runs. Confirm this against the spec. If
you think it should have one, say so in your report rather than inventing one.

## Cost

This is the hard part. Statements per evaluated bucket must stay constant, independent of
endpoint count.
- Load the source's bucket records covering every in-window endpoint's history in one query.
  Select `groups_truncated`, `admission_truncated` and `profile_version`. `BucketFacts.of`
  defaults them to "not whole" when missing, so a loader that forgets them silently fails closed.
- Load per-endpoint traffic since first appearance in one aggregate query per chunk of ids.
- Only in-window endpoints need either query. Skip both when none is in window.
- Extend `tests/integration/test_waf_scale.py` to pin the count, with and without in-window
  endpoints.

RETURNING`, and then relies on `assert state is not None` in `_evaluate`.
- A row lost to a conflict is not returned. In that case the assert fires, or, under `python -O`,
  `None` flows on.
- Replace the assert: after `_ensure_states`, reload any still-missing states with the existing
  bulk `_load_states`, in one statement and only when something is missing.
- If a state is still missing after that, raise a clear `RuntimeError` naming the endpoint and the
  detector.
- Add a test that pre-inserts a conflicting state row, between the load and the ensure step, to
  exercise this path. Monkeypatching `_load_states` to miss it is acceptable.
