# Task T-090 — WAF detection semantics: new-endpoint units, materiality floor, one-sided threshold

Read `AGENTS.md` at the repository root first and follow it exactly, §3a above all. Then read
`docs/PRODUCT-UX-GUIDELINES.md` §4 and §6. Frontend only, plus a test fixture.

## Why

T-087 (merged) built the IPS investigation view. Its second round found and fixed three meaning
defects there. The WAF view, which is on `main`, has the same three. Read
`docs/tasks/T-087.md` §Round 2 and the round-2 part of `docs/tasks/T-087.report.md`: the IPS
fixes in `frontend/src/components/ips/` are the precedent to follow.

In `backend/app/waf/behavior.py`:

1. **New-endpoint access** (`WAF_NEW_ENDPOINT_ACCESS`, around line 700):
   - `observed_value` is the **cumulative** request count across N buckets since the endpoint
     first appeared. It is not a per-bucket rate.
   - `expected_value` is `0.0`, meaning none is expected.
   - `threshold` is `new_endpoint_min_requests`, a request-count **materiality floor**.
   - `deviation_score` is None: there is no robust z or seasonal band.

   Today the UI gets this wrong in three places:
   - `wafSummary.ts` says "received n req / 5 min";
   - `WafIncidentMetrics.tsx` draws the observed value per bucket and the expected value as a
     number;
   - `WafDetectionBlock.tsx:71` labels the floor "Surprise threshold ±n".
2. **The rate and ratio detectors' threshold is one-sided.** The backend's reason says
   `threshold +{deviation_z}`; the UI shows "±3.50".

## Build

Inside `frontend/src/components/waf/`:
- **New endpoint:**
  - observed reads as requests since the endpoint first appeared, for example "320 requests since
    it first appeared"; use the backend `reason` where it says more;
  - expected reads "none", never "0";
  - deviation is the em dash, with "Not defined: nothing was expected";
  - the detection block shows the materiality floor ("material at ≥ n requests") and the
    verified history (`baseline_sample_count` is the verified history buckets for this
    detector);
  - no robust-score line, robust z, surprise threshold or seasonal-baseline items;
  - the list row (`AnomalyRows`, for the WAF branch) uses the cumulative unit too;
  - the chart axis stays per bucket, because the series really is per bucket.
- **Every other WAF detector:** the threshold reads one-sided ("Robust z threshold +3.50"), as T-087
  did for IPS.
- **Check each item in "Against what normal"** for each WAF detector against what the backend's
  evidence means. Fix anything else that misstates it, and list what you checked in the report.
- Reuse the IPS helpers if you can make them shared without changing IPS behaviour or its tests.
  Otherwise mirror them in `waf/`.

## Tests

  - the new-endpoint unit, "none" expected, the materiality wording, and the absence of the
    robust and seasonal items;
