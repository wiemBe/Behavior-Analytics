## Decisions (G-1, the orchestrator's design addendum)

1. **The geo key is the full JSON string.** `GEO::LOOKUP(<field>, 'country')` returns, for
   example, `{"country":{"confidence":null,"name":"United States","iso_code":"US",
   "geo_id":6252001}}`, and its third argument is ignored. Group by the expression as it is, with
   no AQL string extraction, and parse it in the pure fold (Python).
   - Several strings may map to one code (for example if `confidence` varies). The fold sums them
     per code.
2. **Two directions**, `SOURCE` (`sourceip`) and `DESTINATION` (`destinationip`), each a
   separate stored series and **one search per direction per tick**. The setting
   `geo_directions` defaults to both.
3. **No IP is selected.** The search selects only the geo expression, `starttime / <bucket_ms>`
   and `SUM(eventcount)`, and groups by the first two. Do not add an `INCIDR` private-range query
   in this task: the remainder is one `UNRESOLVED` count, "private, internal or unknown to
   GeoIP", and the API says so.
4. **Permission:** a new `PERM_GEO_READ = "read:geo"` in `app/security/rbac.py`, satisfied by
   `read:*`, with a comment in the file's voice. The router is guarded with it.
5. **Default on:** `geo_collection_enabled = True`, at the 1 h default cadence, costing two
   searches per hour per instance. A one-line comment states the cost.

## Build

1. **Provider.**
   - Declare `get_geo_keyed(start, end, *, direction, bucket_seconds, max_rows)` on the
     provider interface. It is a read.
   - Implement it on `QRadarRestProvider` with the AQL shape of decision 3, bounded by `WHERE
     starttime >= …` and `< …` with the padded `STOP`, `ORDER BY SUM(eventcount) DESC`,
     `LIMIT max_rows + 1`.
   - Implement it deterministically on `MockQRadarProvider`.
   - The MCP provider does not support it, as it supports no AQL.
   - Return the rows plus a truncation flag, mirroring `get_ips_keyed`.
2. **Fold** (`app/geo/fold.py`, new, pure):
   - parse each key with `json.loads` inside a guard. If `country.iso_code` is two ASCII
     uppercase letters, the row counts for that code;
   - the exact string `{}`, or a parsed object with no `country`, counts as `UNRESOLVED`;
   - anything else counts as `UNPARSEABLE`. Count it and log it **by count only, never the
     key**;
   - sum per (bucket, code). Keep the top **64** codes per (bucket, direction) by events, ties
     broken by code, and sum the rest into `OVER_CAP`.
3. **Driver.** Split on truncation like the IPS keyed driver: halve the time window first. At a
   single bucket a truncated result is `LOWER_BOUND` for that bucket. The per-tick search cap
   (`search_cadence_max_searches_per_tick`) bounds the splitting. Buckets it never searched get
   no row, and the watermark holds before them.
4. **Model and migration `0022`** (chained after `0021`):
   - `geo_country_bucket`, a **hypertable** on `bucket_start` (add it to `HYPERTABLES`).
   - Columns: `instance_id` (FK), `bucket_start`, `bucket_seconds`, `direction` (`CHECK` in
     `SOURCE`/`DESTINATION`), `country_code CHAR(2) NULL`, `remainder_kind String NULL` (`CHECK`
     in `UNRESOLVED`/`OVER_CAP`/`UNPARSEABLE`), `events BIGINT NOT NULL`, `measurement`
     (`EXACT`/`LOWER_BOUND`), `query_version`, `collected_at`.
   - A `CHECK` that exactly one of `country_code` and `remainder_kind` is set.
   - Uniqueness on (instance, bucket_start, direction, code-or-remainder). Choose a construction
     that works with the nullable pair, and say which.
   - The migration seeds the `search_cadence` row for `GEO_COLLECTION` (1 h), as `0020` seeds
     `CATCHALL_SENDERS`.
   - **The raw JSON string is never stored.**
5. **Family:**
   - `SearchFamily.GEO_COLLECTION`, appended **at the end** of the enum;
   - add it to `_bucket_seconds` in `app/api/routes/search_cadence.py`, returning
     `collection_interval_seconds` (T-079's lesson);
   - add the frontend entries in `frontend/src/lib/api.ts` (`SearchFamily`) and
     `frontend/src/lib/searchCadence.ts` (name "Geography", scope "Events per country, by source
     and destination address"), in enum order.
6. **Collector** (`app/collectors/geo_collector.py`, new):
   - one run per instance claims the cadence slot, as `dispatch_ips_collection` does;
   - per direction, it collects every settled bucket since its watermark. Keep a watermark per
     (instance, direction) in `CollectionWatermark`, the catch-all way;
   - it writes rows in one bulk upsert.
   - Add the Celery task, the beat entry, retention (`geo_retention_days`, default 35, in the
     catch-all batch pattern), and the settings: `geo_collection_enabled`, `geo_directions`,
     `geo_max_rows_per_search` (default 5000), `geo_max_countries_per_bucket` (64), and the
     retention settings. Each setting gets a one-line comment in `config.py`'s voice.
7. **API** (`app/api/routes/geo.py`, new, mounted with `requires(PERM_GEO_READ)`):
   `GET /geo/countries?since&until&direction=SOURCE|DESTINATION`.
   - The range is required, timezone-aware, `since < until`, and bounded by
     `api_max_range_days`. Anything else is a `422`.
   - The response holds:
     - per country `{country_code, events, share}`, sorted by events;
     - `remainders` `{UNRESOLVED, OVER_CAP, UNPARSEABLE}`;
     - `measurement`: `LOWER_BOUND` if any bucket in range is, else `EXACT`;
     - `coverage` `{measured_buckets, expected_buckets}`;
     - `status`: `NOT_COLLECTED` (no row in range), `INSUFFICIENT_DATA` (rows but zero country
       events), `PARTIAL` (measured < expected) or `OK`;
     - a fixed `unresolved_note` saying `UNRESOLVED` covers private, internal and
       GeoIP-unknown addresses.
   - `share` is over country events only; the remainders are reported beside it, never mixed in.
   - Use a constant number of statements (one aggregate and one coverage query).

## Tests

- **Fold (unit):** a valid code; two strings for one code summed; `{}`; a parsed object without
  `country`; malformed JSON; a three-letter or lowercase code (`UNPARSEABLE`); the 64 cap with
  ties; no key is ever logged (use `caplog`).
- **Provider (unit):** the AQL selects no `sourceip` or `destinationip` column outside the
  `GEO::LOOKUP(...)` call; grouping by the geo expression and the bucket key; the padded `STOP`;
  `LIMIT max_rows + 1`; truncation is detected. The mock is deterministic.
- **Collector (integration):**
  - a truncated window splits by time;
  - a single-bucket truncation is `LOWER_BOUND`;
  - a failed bucket has no row and the watermark holds;
  - the per-tick cap leaves later buckets unsearched, with the watermark held;
  - an all-`{}` bucket stores only an `UNRESOLVED` row;
  - both directions run, with separate watermarks;
  - the **statement count** per run is the same at 2 and at 64 countries
    (`recorded_statements`).
- **Migration** `tests/integration/test_migration_0022.py`: upgrade to `0022` and assert the
  table, the `CHECK`s, the uniqueness, the hypertable and the seeded cadence row; downgrade to
  `0021`; upgrade; drift check at `head`.
- **API:** each status; the share excludes the remainders; `measurement`; coverage; a `422` for a
  bad range; `read:*` allowed; a principal without `read:geo` gets `403`.
- **Ruled in advance:**
  - the previous migration test may have its final drift-check upgrade changed to `"head"`, and
    nothing else (the T-076 convention);
  - a test that pins the full `SearchFamily` list or the cadence rows gains `GEO_COLLECTION` at
    the end, and nothing else.
  - Any other conflicting test: stop and report.
- Break the code on purpose for at least five guards and confirm the tests fail; list them.
