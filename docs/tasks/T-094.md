# Task T-094 — WAF caveat line; "Robust z" when the score was not used

Read `AGENTS.md` at the repository root first and follow it exactly, §3a above all. Then read
`docs/PRODUCT-UX-GUIDELINES.md` (§4 and §6 on honesty states) and `frontend/src/app/tokens.css`.

Two small fixes in the WAF and IPS detection blocks of the anomaly investigation page.

## 1. The WAF detection block shows the detector's caveat

The backend is adding `caveat: str | None` to `WafDetectionDetailOut` (task T-093, in parallel).
- `frontend/src/lib/api.ts` `WafDetectionDetail`: add `caveat: string | null`, after
  `percentage_point_change`, mirroring `IpsDetectionDetail`.
- `frontend/src/components/waf/WafDetectionBlock.tsx`: render it the way
  `components/ips/IpsDetectionBlock.tsx` does (`{d.caveat && <p className="subtitle">…</p>}`), in
  both the insufficient-data branch and the main branch, below the robust-score line.
- A missing caveat (`null` or absent in an older payload) renders nothing.

## 2. "Robust z" is not shown as a number when the score was not used

When `robust_score_status` is `DEGENERATE` or `UNAVAILABLE`, the blocks still print the stored
`robust_z` figure (for example "21.4"), and only the status line underneath says the score was not
used. A figure printed as a measurement reads as one. In both `WafDetectionBlock` and
`IpsDetectionBlock`:
- `OK`, or no status: unchanged (the figure, or the existing missing-value rendering).
- `DEGENERATE` or `UNAVAILABLE`: the "Robust z" row shows the existing `Missing` component (or
  whatever the block already uses for a value that is not available) with a reason in words, for
  example "not used: MAD was zero" for DEGENERATE and "not computed" for UNAVAILABLE. Never a zero,
  never the stored figure. The status line below stays as it is.
- `components/behavior/TechnicalDetails.tsx` (Phase A) has the same "Robust z observed" row. Check
  whether its data carries a robust-score status; if it does, apply the same rule; if it does not,
  leave it and say so in the report.
