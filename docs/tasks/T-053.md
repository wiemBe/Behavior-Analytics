## The question each view answers

- **`/admin/ips-sources`**: "Which IPS sources are configured, and which are collected right now?"
  - Columns, per source:
    - the source name and its QRadar type;
    - the profile version;
    - the validation status for the *current* version (VALID, or a stale VALID for an older
      version, as WAF shows it);
    - enabled;
    - pending validation;
    - the last validated time (UTC).
  - An **Add IPS source** picker, from `GET /ips/candidates`: class `IPS` first, then by name,
    searchable.
  - The empty state says that no IPS source has a profile yet, and that adding one starts from a
    preset.
- **`/admin/ips-sources/[logSourceId]`**: "Is this source's field mapping right, and may it be
  collected?"
  - **Two reference kinds per field** (§FM.9):
    - `NORMALIZED`, chosen from the schema's `normalized_options` (never free text);
    - `CUSTOM_PROPERTY`, chosen through the T-058 searchable picker over the catalog for the
      source's DSM type.

    One control per logical field switches between the two kinds. A required field cannot be
    unmapped; an optional one (`PROTOCOL`, `ACTION`, `SEVERITY`) can.
  - **Presets.** On create, offer `CISCO_FTD` and `PALO_ALTO_THREAT` as a prefill. The copy says
    a preset fills in defaults that **must still validate**: a preset is never trusted.
  - **`ACTION`** is unmapped by default. Say why: neither DSM exposes an action, and a site
    authors a custom property for it (§FM.9). Until it is mapped, the block ratio cannot be judged.
    When it is mapped, the value-map editor (BLOCKED / ALLOWED) appears, fed by the values the last
    validation discovered (≤ 20). If the report marks the values truncated, explain that this is
    why validation was INCONCLUSIVE.
  - **Validation report:**
    - per-field population as `%` of events;
    - the generic-QID share as a **warning, not a failure** (for example, "12.4 % of events carry a
      generic 'Unknown …' signature name");
    - reasons, in words;
    - the window in UTC;
    - no query text, ever.
  - **Actions:** save (PUT with `expected_profile_version`; a 409 on a stale version shows who
    changed it and offers a reload, as WAF does), validate (202; pending; 409 while pending),
    enable (only when the current version is VALID; otherwise the reason), disable, and history.
- **Nav:** add one entry, "IPS sources", under Administration after "WAF sources". Update the
  pinned nav test for exactly that entry.
- **Permission:** the routes need `admin:ips`. A 403 is a designed state that names the missing
  permission. `admin:waf` does not grant it.

## Honesty and states (§3a)

Design and test each of these states:
- loading;
- error (what failed, what to do);
- empty;
- 403;
- 404 (an unknown source);
- pending;
- VALID, INVALID and INCONCLUSIVE;
- stale VALID;
- the stale-version 409;
- `SOURCE_BUSY` (validation could not take the source lock; the previous state is kept).

Times are in UTC with the zone. Percentages carry `%`.
