### What the README now says about proxy headers and the rate limiter

The limiter sees whatever uvicorn puts in `scope["client"]`, and with `--proxy-headers` uvicorn
rewrites that **only when the TCP peer is in `forwarded-allow-ips`**, which defaults to
`$FORWARDED_ALLOW_IPS` or `127.0.0.1`. So: a proxy that connects from loopback (a proxy on the
same host reaching the published `127.0.0.1:8000`) has its `X-Forwarded-For` honoured and the
limiter keys on the real client — but if it sends no such header every request looks like
`127.0.0.1` and shares one bucket. A proxy that connects from anything else (another container,
the Docker bridge, a second host) is not trusted: uvicorn ignores the header,
`request.client.host` stays the proxy's address, and every analyst shares that proxy's
`RATE_LIMIT_DEFAULT` bucket. What the operator must set: `FORWARDED_ALLOW_IPS` in `.env` to the
proxy's address or network (uvicorn reads the variable itself, and the `backend` service loads
`.env` wholesale through `env_file: [.env]`, so no change to `docker-compose.yml`) — or
`--forwarded-allow-ips` on the backend command. Never `*`, per the uvicorn warning.
