## `/anomalies` (list)

1. **The table scrolls inside the page at 1280 and 1024.** At 1280, Evidence is hidden behind the
   sticky action column. At 1024, Started and Evidence are both off-screen. This fails the
   standard set by T-024 round 2: at 1440, 1280 and 1024 no table may scroll locally with a column
   hidden. Fold secondary facts into another cell at narrower widths. Example: at ≤ 1280, evidence
   goes under State and deviation goes under Observed → Expected, with the same values and
   accessible names. The capture must report **0 local scrollers** for every route at all three
   viewports.
2. **Units in the mixed list.** On the Phase A-only list the header reads "Observed → Expected
   (EPS)". On the mixed list it has no unit, so a Phase A row shows `6.10 → 2.00` with no unit at
   all. Every cell must carry its own unit, whatever the filter: EPS for Phase A, `req / 5 min`
   for WAF volume, `%` for a ratio. Use one wording consistently.
3. **The header "Observed → Expected" wraps** onto two lines at every width. Keep it on one line,
   or shorten it (for example "Observed / expected") and put the arrow only in the cells.
4. **The Subject cell breaks names at hyphens** ("lab-" / "waf-behavior-01"), and the trailing
   " ·" leaves an orphaned separator at the end of the first line. Stack it instead:
   - line 1: `METHOD /path`, in mono;
   - line 2: the source link;
   - line 3: the virtual host, muted, only when present.

   A source name never breaks at a hyphen. A name too long for the column ellipsizes, with the
   full name in `title`.
5. **Raw enum strings.** The Evidence column shows `NOT_REQUESTED`, `PARTIAL`, `COMPLETE` and
   `UNAVAILABLE`. Show words: Not requested, Partial, Complete, Unavailable. Use the label map
   if one exists in `lib/`.
   - **For WAF rows, evidence collection does not exist.** `app/waf/engine.py` creates every WAF
     anomaly with `NOT_REQUESTED`, and nothing ever changes it. So a WAF row shows "—" with an
     accessible meaning, such as `title`/`aria-label` "Evidence collection does not apply to WAF
     anomalies". It does not show "Not requested", which implies the analyst could request it.
6. **Detector names break at their hyphen** ("Request-" / "rate spike"). Give the detector column
   a sensible minimum width, or use a non-breaking hyphen in the label.
7. **Filter chip: the ✕ needs a space** before it ("Subject: Log sources✕"). It needs an
   accessible name too, if it lacks one (e.g. "Remove filter Subject: Log sources").

## `/anomalies/[id]`, WAF

8. **The expected band is drawn flat "at detection" across the whole range. The data for a
   seasonal band exists.**
   - `GET /behavior/waf/endpoints/{id}/baselines` returns per-(weekday, hour) cells: `median`,
     `mad`, `p05`, `p95`, `is_reliable` and `metric_name` (`WafBaselineCellOut`).
   - Draw the band per bucket from the cell of that bucket's weekday and hour, as the Phase A
     chart does from `sourceBaselines`. Reuse the Phase A convention and component.
   - **Check, do not assume:**
     - the weekday convention, in `backend/app/waf/baseline.py` (which day is 0 or 1, and UTC);
     - how the detector derives `expected_low`/`expected_high` (`backend/app/waf/behavior.py`
       and the volume detector).
   - If the cell reproduces the detector's range, label the band "Expected range". If it does not,
     label it for what it is, for example "Seasonal p05–p95". A bucket whose cell is missing or
     unreliable gets no band there; it never gets a zero band.
9. **Ratio detectors chart the wrong quantity.** A block-ratio spike's chart shows request volume,
   with a note that the proportion is "in the measurements above". The data for the proportion
   per bucket exists in `GET /behavior/waf/endpoints/{id}/metrics` (`WafMetricBucketOut`):
   - block ratio = `blocked_count / action_events`, where `action_measurement` is complete;
   - server-error ratio = `server_error_count / response_code_events`, where
     `response_code_measurement` is complete;
   - client-error ratio = `client_error_count / response_code_events`, likewise;
   - client concentration = `top1_client_requests / client_events`, where `client_measurement`
     is complete. Check the detector for the exact numerator and denominator.

   For a ratio or concentration detector:
   - the primary panel is the detector's own proportion, in %;
   - a bucket whose breakdown was not collected, failed, or is PARTIAL is a gap, never 0;
   - a zero denominator is a gap, not 0 %;
   - the expected proportion comes from the ratio baseline cells, if their `metric_name` /
     `metric_semantics` give it. Check `backend/app/waf/baseline.py`, where ratio baselines are
     pooled sums. If they do not give it, show only the expected value at detection, labelled so;
   - the secondary panel stays coverage (%);
   - the request count per bucket goes in the hover readout, if the chart has one; otherwise
     leave it out.

   Remove the "this detector judges a proportion…" note once the chart shows the proportion.
   Volume and novelty detectors keep the requests chart.
10. **Raw state strings in Lifecycle** (`NORMAL`, `INSUFFICIENT_DATA` with its underscore) and in
    the endpoint inventory's State column (`RESOLVED`, `INSUFFICIENT_DATA`). Use the readable
    labels and badge style that the Phase A pages use for the same states.
11. **Remove the Evidence section for WAF.** It is a Phase A-only shell: "NOT_REQUESTED. No
    evidence collection has been requested…". The spec says Phase A-only sections are absent for
    WAF, not empty. See point 5 for why.
12. **"Against what normal":**
    - "Expected range at detection 22 – 68" needs its unit (`requests / 5 min`);
    - for a ratio detector the field shows a bare "—". Either omit it for ratio detectors (they
      have an expected proportion instead) or give the dash its meaning.

## `/behavior/waf` and `/behavior/waf/sources/[id]`

13. **Admission overflow wording.** The meanings, from design §28.5 and the schema docstring:
    - `rejected_over_quota` counts endpoint keys that met the volume threshold but were refused
      because the per-bucket new-endpoint quota or the source's active ceiling was full;
    - `below_admission_threshold` counts new keys with fewer than `WAF_MIN_ADMISSION_REQUESTS`
      requests in their bucket. That is ordinary noise, not overflow;
    - both are **summed over the collected buckets**, so a key refused in several buckets counts
      once per bucket.

    Word the cell so it says this: for example "1,893 refused for quota (key-buckets)" and
    "702 below admission threshold". Explain "key-buckets" once, in a footnote or `title`.
    Keep "Overflowing" meaning only quota refusals or admission truncation, never the
    below-threshold count.
14. **Small items:**
    - the source page header runs four facts together with no separators ("VALID for profile v3
      Profile enabled 132 of 500 endpoints active"); separate them as the other headers do;
    - on the 404 page, "Open WAF behavior" must be a link to `/behavior/waf`;
    - in the `/behavior/waf` headline, write "valid" rather than "VALID" inside the sentence.
