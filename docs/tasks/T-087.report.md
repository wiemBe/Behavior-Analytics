## 4. What I changed from the inherited code, and why

- `components/ips/ipsDetectors.ts`: `IPS_NEW_DESTINATION_PORT` had `scope: "source"`. The detector judges a destination-port entity (`engine.py`: dimension `DESTINATION_PORT`), its incident is `IPS_ENTITY`. Changed to `scope: "entity"`.
- `components/ips/IpsInvestigation.tsx`: removed the early "nothing to draw" return for the new-port detector. The entity's own events series exists and the spec asks for it on every entity incident; there is simply no seasonal band (no baseline metric). Test added.
- `components/ips/IpsIncidentMetrics.tsx`: the new-port Deviation note read "— events against expected", a unit against an expectation that does not exist. Now "Not defined: nothing was expected". Test added.
- `components/ips/fixtures.ts` and all tests: new (the inherited work had none).
- Out-of-list files, both kept because required:
  - `lib/anomalyQuery.ts`: `parseSubjectQuery` is where `/anomalies` validates the URL (subject kinds, WAF type, UUIDs). `SUBJECT_KINDS` must gain the IPS kinds, and `ips_anomaly_type` / `ips_entity_id` have to be parsed there, or the Phase A allow-list drops an IPS type and `ips_entity_id` is never validated. +9 lines, additive.
  - `lib/home/recentAnomalies.ts`: this is what builds the Home's Recent anomalies rows, and `RecentAnomalies.tsx` renders its output unchanged. Without the edit an IPS row got a Phase A label and linked to the log source's EPS page. IPS rows now link to their own investigation (no IPS behavior page exists yet).
- Everything else inherited was kept as written.

## What changed

1. New-port detector (backend: `detect_new_destination_port`):
   - New unit `since` in `ipsDetectors.ts` and `ipsFormat.ts`: "events since it first appeared". Metrics card, summary sentence and list row use it; the chart axis alone stays "events / 5 min" (`IpsInvestigation` hands the chart `events`).    - `IpsDetectionBlock`: new-port has its own branch with the backend `reason`, "Materiality floor: material at ≥ n events", "Verified history: n buckets below the admission threshold" (`sample_count` is the verified history buckets), the detector's caveat. No robust z, robust-score line, surprise threshold, expected range, baseline samples/completeness/version.
   - The detector confidence "limited" note no longer applies to new-port.
2. Every other detector's items checked against `detector.py` / `behavior.py`:
   - The threshold is `deviation_z`, one-sided ("threshold +3.5" in the backend's own reason). It was shown as "Surprise threshold ±3.50". Now "Robust z threshold +3.50".
   - Real defect found: `percentage_point_change` is already in points (backend `round(rise * 100, 2)`, 45.0 = 45 pp). The UI reused WAF's `formatPoints`, which multiplies by 100 again, so production would show "+4400 pp". IPS now uses `formatPointChange` (no multiplication). My round-1 fixture had used fractions and hid this. The WAF view uses the same `formatPoints` on the same convention; I did not touch it (outside the task), but it looks like the same latent defect there: please check.
3. `/anomalies` clipping: the observed cell is now `ips-figures` (one line, nowrap) with the unit on its own wrappable line (`ips-unit`) beneath; "none expected" is now "none"; distinct-ports unit reads "distinct ports". CSS is in `components/ips/ips.css`, imported by `AnomalyRows`. Measured in Chrome with a script (`measure.mjs`), per viewport, the table-scroll container width against its content and any cell box beyond its right edge: the current build has no scroll overflow and no cut cell at 1440, 1280 and 1024 (container 1129/969/765 px = content). Feat/phase-ce without IPS rows (HEAD archived to the work directory, built, fixture with Phase A and WAF rows only) also did not clip: container 1144/984/780 = content, no cut cell. So the clipping was introduced by the long IPS unit text ("events / bucket", "none expected"), not by Phase A or WAF rows.
4. Fixture payloads (`fixture/fixture_api.py`) now follow the backend's evidence and the `IpsDetectionDetailOut` whitelist: the seven real caveat texts; reasons in the detectors' own wording; one-sided threshold 3.5; share `percentage_point_change` in points; new port: `threshold` 50 (event floor), `baseline_sample_count` 288 (verified history), `baseline_completeness`/`baseline_version` null, `robust_z`/`robust_score_status`/`ratio`/band null, `expected_value` 0.0 on the row, `absolute_delta` = the cumulative count; block ratio now RISES (the backend detects a rise; round 1 had a fall, which no detector emits).
