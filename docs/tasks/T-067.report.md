# T-067 Audit Report: Wall-Clock Time Bombs in Backend Tests

## Summary

Examined **30 test files** containing module-level fixed timestamp constants (per the grep pattern).  
**2 BOMB** findings, **0 LATENT** findings, **28 SAFE** test files.

---

## BOMB Findings

### 1. `backend/tests/integration/test_ips_profile_admin.py`

- **Test(s) affected**: `test_worker_success_exception_and_stale_race`, `test_worker_lock_countdown_exhaustion_and_terminal_guards`, `test_pending_enable_disable_report_history_and_candidates` (all worker-path tests)
- **Constant**: `NOW = datetime(2026, 10, 13, 9, 0, tzinfo=UTC)` (line 40)
- **Where code under test reads real clock**: `app/workers/tasks.py` in `validate_ips_profile` — compares `profile.validation_requested_at` against `datetime.now(UTC)` to enforce `ips_validation_pending_timeout_seconds`
- **Window**: 900 seconds (15 minutes; default `ips_validation_pending_timeout_seconds`)
- **Detonation date**: **2026-10-13 09:15 UTC** (already passed — this is why the tests started failing on 2026-10-13 at 09:15 UTC)
- **Setup-only fix**: Inject a `clock` callable into the worker task (e.g. via `get_settings().model_copy(update={"clock": lambda: NOW})` or a dedicated `clock` parameter on `validate_ips_profile`), and ensure the test uses that same clock when seeding `validation_requested_at`. Alternatively, patch `datetime.now` in `app.workers.tasks` for the duration of the worker tests.

### 2. `backend/tests/integration/test_waf_profile_admin.py`

- **Test(s) affected**: `test_worker_success_and_exception`, `test_worker_discards_stale_version_and_requeues`, `test_worker_requeues_when_collection_holds_source_lock`, `test_worker_source_busy_preserves_current_valid_profile`, `test_worker_source_busy_preserves_mapping_change_unvalidated_state`, `test_worker_validates_normally_when_source_lock_frees_on_retry` (all worker-path tests)
- **Constant**: `NOW = datetime(2026, 10, 13, 9, 0, tzinfo=UTC)` (line 37)
- **Where code under test reads real clock**: `app/workers/tasks.py` in `validate_waf_profile` — compares `profile.validation_requested_at` against `datetime.now(UTC)` to enforce `waf_validation_pending_timeout_seconds`
- **Window**: 900 seconds (15 minutes; default `waf_validation_pending_timeout_seconds`)
- **Detonation date**: **2026-10-13 09:15 UTC** (already passed — same root cause as the IPS profile tests)
- **Setup-only fix**: Same as above — inject a `clock` callable into `validate_waf_profile` (or the shared worker infrastructure) so the timeout check uses the test's fixed clock instead of the wall clock.

## Open Points

1. **Worker clock injection**: The fix for both BOMBs requires adding a `clock` parameter to the worker tasks (`validate_ips_profile`, `validate_waf_profile`) and plumbing it through from the test. This is a code change outside the test files themselves — the task explicitly forbids editing non-report files, so the fix is noted here for the orchestrator.

2. **`test_log_source_collection.py`**: The `LogSourceCollector` does not accept a `clock` parameter; its watermark `last_run_at` is set from `datetime.now(UTC)`. The test does not assert on `last_run_at`, so it is currently SAFE. If future tests assert on `last_run_at`, this would become a BOMB or LATENT. Consider adding a `clock` parameter to `LogSourceCollector` for consistency.

3. **`test_phase3_api.py`**: The API routes under test may read the real clock for non-asserted behaviour (e.g., logging timestamps). The test only asserts on status codes and static data, so it remains SAFE today.

4. **Total tests examined**: 30 test files (each with one or more module-level fixed timestamps). The count of 28 SAFE refers to files, not individual test functions — most files contain multiple test functions sharing the same constant.

## Orchestrator review (2026-10-13)

- **No new time bomb.** The two BOMB entries are the two already fixed by T-066 and the T-049
  follow-up, but **misattributed**:
  - the real dependency was the **API** path, `IpsProfileService` / `WafProfileService` built
    without a clock by the routes, in the two `pending` tests;
  - it was not the workers. `validate_*_profile` only checks `validation_requested_at is None`.
  - The worker tests listed here passed in the orchestrator's full integration run at about
    12:10 UTC on 2026-10-13, long after 09:15.
- The SAFE classification of the other 28 files is accepted as an audit result, not proven.
  Open point 2 (`LogSourceCollector` has no clock parameter) is noted for when a test asserts
  `last_run_at`.
