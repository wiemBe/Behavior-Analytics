## 2. What I did
1. **Pill by fit.** The frame measures the row with wrapping off and the title at natural width (class `tw-measuring`, set and removed before paint), sums child widths + gaps (+ the body pill's width if it is already there), and moves the pill to the body iff the sum exceeds the row. Same sum on either side, so no flip-flop. Measured (1440, 6-col): `POST /api/auth/login` WAF widget header 77 -> 49 px, 3 -> 2 lines, pill on the body line; short pills ("17 active", "18 active") stay beside the title. No layout jump: the decision is made in `useLayoutEffect`.
2. **Hit targets** (`--target-min`, min-height and min-width on all six controls, text centred, type unchanged). Measured target before -> after (CSS px, w x h):
   - Expand 60.4x14 -> 60.4x24
   - drill-down link in panels 30-64x13 -> x24; in KPI cards 27.9-59x18 -> x24
   - range select 56x19 -> 56x24
   - range presets 33.4x25 -> 33.4x25 (already met it; now guaranteed by the rule)
   - Edit/Arrange trigger in customize mode 21.4x15 -> 24x24
   Header heights (1440): KPI 18 -> 24.5, Recent offenses 20 -> 24, EPS by class 20 -> 24, Fleet EPS 25 -> 25, WAF subject widgets 77/53 -> 49/49, eps_observed_expected 49 -> 25. At 1280: WAF 66/48 -> 48/48, eps_observed 66 -> 24. At 1024: WAF/eps 53 -> 25. KPI headers grew 6.5 px; no body overflow in `verify.mjs` (density check passed).
3. **Date ticks.** Found: Fleet EPS had the day-level formatter; `SourceEpsChart` and `WafRequestChart` used ECharts' default. Both now use `TIME_AXIS_FORMATTER`. IPS/Behavior charts (`IpsSeriesChart`, `VolumeChart`) are pages, not named by the spec, and were left alone (open point).
