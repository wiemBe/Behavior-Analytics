## What I did

The README route row, the custom-rules data-model paragraph, the API paragraph and the Phase F roadmap entry now describe what is on the branch. `/custom-rules` lists name, status in words with the engine's reason, subject, condition, severity, enabled and last evaluated (UTC). `/custom-rules/new` is the editor: metrics, subject kinds and preview bounds come from `GET /api/v1/custom-rules/catalog`, and `POST /custom-rules/preview` sits beside the form. The same editor edits a stored rule. `/custom-rules/[id]` shows the stored preview and the breach history. Creating, editing, enabling, disabling and deleting need `custom_rule:write`.

`GET /catalog` is described from `CustomRuleCatalogOut`: `metrics` (`metric`, `subject_kind`, `unit`, `is_ratio`, `measurement` as `EXACT_ONLY` or `LOWER_BOUND_PROVES_INCREASE`, `note`; not `reads` or `bulk_loader`), `subject_kinds` (`subject_kind`, `column`), `source_classes`, `operators`, `evaluation_enabled`, `alerting_mode` (`shadow` or `alerting`), `max_enabled`, `enabled_count`, `preview_hours_min` (1) and `preview_hours_max` (168).

§F.12's "As built" note cites the pages. Status pills are words from `statusLabel` (`authoring.ts`): a null status is "Never evaluated", and the tokens render as "Open", "Recovering", "No verdict", "Stale", "Not collected", "Subject retired", "Disabled" and "Not enabled". `OK` stays "OK". The list columns are Name, Status and reason, Subject, Condition, Severity, Enabled, Last evaluated (UTC). The hours control is a Window field on the draft preview and on the stored preview, bounded by the catalog, starting at 24. A complete draft reloads when the window changes. The stored preview waits for Apply window. The pages' latency sentence says "seconds-level" where §F.12 says "real-time", and the edit disclosure does not repeat it. `editorSummary` recovers with the operator's complement and names the catalog unit.
