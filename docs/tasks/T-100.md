# Task T-100 — make the frontend suite robust to a loaded machine; list the slowest tests

Read `AGENTS.md` at the repository root first and follow it exactly. Mechanical task: **no page,
component or existing test file changes.**

## Why

T-099's agent saw `src/app/rules/statistics/page.test.tsx > statistics sections > shows a
truncated silent list and its excluded rules` fail twice in four full runs with `Test timed out in
5000ms` (elapsed ~6.8 s) while the machine had a load average of 32 on 24 CPUs. It renders 500
table rows; it passes in 0.9 s alone. Several agents and gates run in parallel on this machine,
so vitest's default 5 s per-test timeout turns load into false failures.

## What to do

1. **Measure first.** From `frontend/` (Node at `~/.local/node/bin`; `npm ci` first, the worktree
   has no `node_modules`), run the full suite once with a reporter that gives per-test durations
   (for example `npx vitest run --no-cache --reporter=json --outputFile=<work dir>/before.json`).
   Report the 15 slowest tests (file, name, duration) and the suite's wall time.
2. **Set `testTimeout: 15000`** in `frontend/vitest.config.ts` (the `test` block), with a one-line
   comment saying why (shared, loaded machine; the slowest test's measured time). Nothing else in
   the config changes. Do not touch any test file: no per-test timeouts, no skips.
3. **Prove it**: run the full suite three times (`npx vitest run --no-cache`) and copy each summary
   line verbatim. If any run still fails, report the failing test and its time; do not change the
   test.
4. Gates: `npm run lint`, `npm run typecheck`, `npm run build` (summary lines verbatim).
