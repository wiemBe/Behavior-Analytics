## The defect (found by the orchestrator)

`app/api/router.py` mounts some routers **without any authentication dependency**:
- `log_sources`: 5 routes, including `PATCH /log-sources/{id}` and `POST /log-sources/sync`.
- `overview`.
- Possibly read routes in `searches` and `alerts`, which guard only their mutating handlers.

So anyone who can reach the API can:
- read the inventory;
- **change SOC-owned fields**, such as `monitoring_enabled` and `maintenance_mode`, which
  silently blinds the platform to a source;
- trigger an inventory sync against QRadar.

The routers that are guarded use the router-level `requires(<permission>)` dependency
(`app/api/deps.py`). Its docstring explains why: the guard is a property of the router, so a new
route cannot ship unauthenticated.

(Context: OIDC verification itself is Phase 4 work, and today it fails closed with 501. This task
does not implement OIDC. It makes every route *require* a principal, so that when OIDC lands no
route is left open.)

## What to do

1. **Audit** every route the app serves. Enumerate them from the FastAPI app object, not by
   reading files. For each route record: path, method, the permission it requires today, and the
   permission it should require.
2. **Fix it**, preferring router-level `requires(...)`:
   - Add these permissions in `app/security/rbac.py`, each with a comment in the style of the
     existing ones:
     - `PERM_LOG_SOURCE_READ = "read:log_sources"`;
     - `PERM_OVERVIEW_READ = "read:overview"`;
     - `PERM_LOG_SOURCE_WRITE = "log_source:write"`, for SOC metadata edits.
   - `POST /log-sources/sync` requires `admin:*`, or a dedicated `admin:inventory`. Choose one
     and explain why.
   - Read routes of `searches` and `alerts` that are unguarded get their read permission:
     `read:searches` and `read:alerts`, or whatever already exists.
   - Keep each mutating route's own per-handler checks, and the audit records where they exist.
   - Add `record_audit` to `PATCH /log-sources/{id}`, following the alerts and searches routes:
     who changed which SOC field, from what to what. Redact nothing sensitive, because none of
     these fields are secrets.
3. **Roles.** Find where roles and their permissions are seeded (`app/services/seed.py`). Make
   sure the existing roles get the new permissions they need, so that the read-only role can
   still read and the analyst/admin roles can still edit. The `read:*` wildcard covers the new
   `read:` permissions. Document the role/permission matrix in your report.
4. **Guard test** (the most important deliverable). Add a test that walks **every** route
   registered on `create_app()`:
   - under OIDC auth settings with no `Authorization` header, it asserts each one returns 401;
   - under OIDC it is not 501 for a missing token: `_oidc_principal` raises 401 before 501;
   - the exceptions are an explicit allowlist: `/health*`, and the OpenAPI/docs routes if they
     are mounted. Justify each allowlist entry in a comment.

   Then, under local auth with a read-only bearer token (`read:*`), it asserts that every
   mutating route (POST/PUT/PATCH/DELETE) returns 403, unless it is allowlisted with a reason.

   A new route added later without a guard must fail this test.
5. **Frontend.** Check whether the frontend calls `/log-sources` or `/overview`, and whether it
   would still work in local dev. Local auth with no header gives `admin:*`. Report it; you should
   not need frontend changes.
