# Task T-098 — widget frame polish: pill placement, hit targets, date ticks, link style

Read `AGENTS.md` at the repository root first and follow it exactly, §3a above all. Then read
`docs/PRODUCT-UX-GUIDELINES.md` (§8, §9, §10), `frontend/src/app/tokens.css`, and the reports of
UI-3.3b, UI-3.5b and UI-4.1 in `docs/tasks/`. These are the small defects the orchestrator saw in
their screenshots; none of them is a new feature.

## Build

1. **The status pill moves to the body's first line whenever it would wrap the title row**, not
   only in panels narrower than 28 rem (UI-3.3b's rule). A 6-column subject widget with a long
   title (for example `POST /api/auth/login · api.example.internal` with a "Partial: 278 of 281
   stored buckets collected" pill) reads three header lines at 1440 today: title / pill /
   controls. Decide by fit (measure, for example with a `ResizeObserver` in `WidgetFrame`), not by
   a width breakpoint, so short titles keep the pill beside them. No layout jump after mount
   (measure it). The controls group still wraps as one unit (UI-3.3b).
2. **Hit targets.** The title row's Expand control measures 60×14 CSS px, below WCAG 2.5.8's
   24 px minimum. Bring every interactive control in a widget's title row (Expand, the range
   presets, the compact range select, the drill-down link, Edit in customize mode) to a target of at
   least 24 px tall, through padding or a hit area, without making the visible type larger. Quote
   each control's measured target before and after. The title row may grow by the few pixels this
   costs; quote the new header heights.
3. **Date ticks.** At midnight the subject charts (`waf.endpoint_traffic`,
   `chart.eps_observed_expected`, and the WAF request chart they reuse) label the axis "15", while
   the Fleet EPS chart says "14 Oct". Make every time axis in the widgets and on the WAF page use
   one convention, the Fleet EPS one, through the shared formatter if there is one (find where each
   chart formats its ticks first).
4. **Link style.** The drill-down links are underlined in the KPI cards and in an unconfigured
   widget, and not underlined in the chart and table panels. Pick one style for every widget's
   drill-down link, following the guidelines (links must be distinguishable without colour,
   WCAG 1.4.1, where they sit in text), and apply it everywhere in the widget chrome.
5. **`--danger`** is used by `.dg-arrange-remove` but is not defined in `tokens.css`. Use the
   existing critical token instead, or define `--danger` in terms of it; say which.
