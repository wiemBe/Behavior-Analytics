# Task T-096 — characterization tests for the ten routes that have none

Read `AGENTS.md` at the repository root first. Follow it exactly.

## Why

`docs/UI-REDESIGN-PLAN.md` UR.7 Phase 5 and UR.8.1: a restyle with no test is unguarded, so every
route without a page test gets a render test for each of its states **before** its restyle
(UI-5.5, UI-5.6, UI-5.8). This task writes those tests against the code as it is. It changes no
application code.

## Routes (each `page.tsx` under `frontend/src/app/`)

`offenses`, `offenses/[id]`, `coverage`, `log-sources`, `log-sources/[id]`, `searches`,
`searches/[id]`, `alerts`, `alerts/[id]`, `config-changes`.

## Build

For each route, a `page.test.tsx` beside its `page.tsx`:
- Follow the pattern of the existing server-component page tests, for example
  `frontend/src/app/rules/statistics/page.test.tsx` and `frontend/src/app/rules/[id]/page.test.tsx`:
  mock the `@/lib/api` functions the page calls, render `await Page({ params, searchParams })`, and
  assert with Testing Library queries by role and text.
- **Read each page first and list its states in a comment at the top of the test file.** Cover
  every state the page renders, at least:
  - the normal state with realistic data (shapes typed from `@/lib/api`; values plausible, no
    lorem ipsum);
  - the empty state (no rows), asserting the page's own empty text;
  - the error state (the read rejects with `ApiError` and, where the page distinguishes it, a
    `404` for the detail routes), asserting the page's own error text;
  - each honesty state or qualifier the page renders today (for example a missing value drawn as
    an em dash and not a zero, a truncated or partial notice, a magnitude tone, an "unknown"
    count), and the query parameters the page passes to the API (paging `offset`, filters).
- Assert what an analyst sees and what a restyle must not change: headings, the section order,
  column headers, numbers with their units, timezone suffixes on times, link targets. Do **not**
  assert CSS class names unless the page already exposes one as meaning (for example a severity
  or status class), and then say so in the comment.
- The tests describe the current behaviour. If you find a defect (for example a zero drawn for a
  missing value, a time without a timezone), **do not fix it and do not assert the defect as
  correct**: write the test for the correct behaviour as `it.todo("…")` with a one-line
  description, and list the defect in the report.
- **Break-it:** for each file, change one rendered word or one branch in the page, confirm at least
  one test fails, then restore. Record each in the report.

## Allowed files

- the ten new `page.test.tsx` files
- `docs/tasks/T-096.report.md` (new)

No change to any page, component, `lib` file or existing test. If a page cannot be tested without
changing it (for example a module-level side effect), stop on that page and report why.
