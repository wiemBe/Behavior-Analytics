# Task T-080 — de-flake `PropertyInput.test.tsx` "renders and filters 500 properties without a cap"

Read `AGENTS.md` at the repository root first and follow it exactly. §4 matters most: **never
weaken, skip or delete a test.** Every assertion of this test stays, with the same meaning.

## The defect

`frontend/src/components/fieldmapping/PropertyInput.test.tsx`, the test "renders and filters 500
properties without a cap" (around line 280), failed once in about ten full `npm test` runs on
2026-10-14 while several agents were running test suites on the same machine. The file took
about 9 s that run. The test renders 500 options and types 14 characters with `userEvent`, one
re-render of 500 rows per keystroke, so under load it can pass Vitest's default 5 s per-test
timeout.

## What to do

1. Reproduce: run that file alone ten times and the full suite a few times; record the test's
   duration in each (use Vitest's reporter output). Say whether a failure was a timeout or an
   assertion, with the message.
2. Fix the cause, keeping every assertion:
   - prefer making the test cheaper without changing what it proves. For example, type the filter
     in fewer events (`user.type` with a shorter but still unique query, or `user.paste` for the
     query, as long as the component's filtering path is the same one a typed query takes; check
     the component to be sure), or set up `userEvent` with `{ delay: null }` if it is not already;
   - if the component itself does avoidable work per keystroke for 500 rows, say so in the report
     but **do not change the component** in this task;
   - only if neither is enough: give this one test an explicit, commented timeout (for example
     `15_000`) that states why. Do not change the global `testTimeout`.
3. Prove it: after the fix, run the file alone twenty times and the full suite three times; all
   green. Then break the filter on purpose (for example make it return every option) and confirm
   the test fails; restore it.
