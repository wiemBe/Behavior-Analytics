# Task T-048 Report — Pad the Ariel `STOP` so the last bucket of a span is not short of late-stored events

2. **backend/app/providers/qradar_rest.py** — Added `_ariel_scope` helper method, injectable `clock` and `ariel_stop_pad_seconds` constructor parameters. Updated all 11 queries that have both exact `WHERE starttime` bound and `START…STOP` clause to use the helper.
3. **backend/app/providers/factory.py** — Pass `ariel_stop_pad_seconds` from settings to `QRadarRestProvider` in both `build_provider` and `build_provider_for_instance`.

Added new `TestArielScopeHelper` test class verifying: pad=0 gives exact text; pad applied to STOP; STOP capped at now; WHERE clause unchanged in generated queries.

6. **backend/tests/unit/test_waf_bucketed.py** — Pass `ariel_stop_pad_seconds=0` to provider fixture so existing AQL assertions remain exact.

## What you did

- Implemented the `_ariel_scope(start_ms, end_ms)` helper that renders `START {start_ms} STOP {stop_ms}` where `stop_ms = min(end_ms + pad_ms, now_ms)` (pad from `ariel_stop_pad_seconds`, capped at current time from injectable clock). `pad=0` reproduces the exact pre-change text.
- Added `ariel_stop_pad_seconds` setting (default 60s) in `config.py` with validation `ge=0, le=300`.
- Injected the setting through the provider factory.
- Applied the helper to **every query** that has both an exact `WHERE starttime >= {start} AND starttime < {end}` bound and a `START…STOP` clause:
  1. `get_log_source_metrics` (Phase A metric)
  2. `get_log_source_metrics_bucketed` (Phase A keyed metric)
  3. `_aggregate_one_dimension` / `get_dimension_aggregates` (explanation evidence)
  4. `get_rule_matches` (rule matches single window)
  5. `get_rule_matches_windowed` (rule matches multi-window)
  6. `get_waf_observations` (WAF grouped + total, 2 queries)
  7. `get_waf_breakdown` (WAF breakdown)
  8. `get_waf_observations_bucketed` (WAF grouped + total keyed, 2 queries)
  9. `get_waf_breakdown_bucketed` (WAF breakdown keyed)
  10. `probe_waf_properties` (WAF property probes, total + per-property)
  11. `observe_property_rejection` (WAF rejection probes)
- Queries whose WHERE clause does **not** bound `starttime` exactly to `[start, end)` were left unchanged (none found in the provider).
- **Query versions**: `RULE_MATCH_QUERY_VERSION` ("rule_match/v1") and `RULE_MATCH_WINDOWED_QUERY_VERSION` ("rule_match/v2") are **not bumped** because they are persisted in the database (`RuleMatchRow.query_version`, `ScheduledSearch.query_version`) and used for watermarking/continuity in `rule_match_collector.py` and `search_executor.py`. Bumping would break historical traceability. The WHERE clause (authoritative bound) is unchanged; only the STOP pad widens the Ariel search window to capture late-stored events.
- Existing tests that pinned exact AQL text with `STOP {end}` were updated by passing `ariel_stop_pad_seconds=0` in the test's provider fixture (preferred approach per spec). Tests updated:
  - `test_metric_query_scopes_the_ariel_search_window` in `test_qradar_rest_provider.py`
  - `test_dimension_query_scopes_the_ariel_search_window` in `test_qradar_rest_provider.py`
  - `test_bucketed_aql_has_key_group_limit_and_both_window_bounds` in `test_bucketed_metric_provider.py`
  - `test_the_queries_carry_key_group_by_limit_and_both_bounds` in `test_waf_bucketed.py`
  - `test_every_breakdown_is_scoped_by_start_and_stop` in `test_waf_breakdown.py` (uses shared `build_provider` which defaults to 0)
  - `test_the_query_is_keyed_grouped_bounded_and_probes_one_row_past_the_cap` in `test_rule_match_windowed.py` (uses shared `build_provider`)
- Added dedicated tests for the helper (`TestArielScopeHelper`), then broke the helper on purpose (padded the WHERE bound too), confirmed tests failed, then restored the correct implementation.

## Review round 1

### Fixes applied
1. **BUG in `_ariel_scope`**: Fixed `stop_ms = min(end_ms + pad_ms, now_ms)` → `stop_ms = max(end_ms, min(end_ms + pad_ms, now_ms))` so the pad only ever widens the STOP bound, never shrinks it below the WHERE bound.
2. **Docstring corrected**: Updated to state the pad comes from the `ariel_stop_pad_seconds` setting via the provider factory, and the constructor default of 0 means no pad.
3. **New unit test added**: `test_stop_never_shrinks_below_end_ms` covering three cases:
   - end in the future relative to the clock → STOP equals end exactly
   - end 30 s before now with pad 60 → STOP equals now
   - end long before now → STOP equals end + pad
4. **Break-and-restore verification**: Temporarily removed the `max(end_ms, ...)` guard, confirmed the new test failed, then restored the correct implementation.
