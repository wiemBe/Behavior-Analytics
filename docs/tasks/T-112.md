# Task T-112 — the dashboard saving tests fail under load

Read `AGENTS.md` at the repository root first and follow it exactly (§4 tests, §5 running things).

## Why

`frontend/src/components/home/HomeDashboard.test.tsx` ("layout saving", added by UI-4.2) fails
in a full `npx vitest run` when the machine is loaded. It passes on its own.

The orchestrator measured on 2026-10-15 at load 32–46, on `feat/phase-ce` before T-098:
- two full runs on `feat/phase-ce` before T-098 both failed **2** tests: "saves an
  outside-Customize range change with expected_revision and keeps the new revision" and
  "Discard outside Customize restores the last saved layout without a write";
- with T-098, the first of these failed in both runs;
- the file alone passed 3 of 3 runs on both trees.

The error is `TestingLibraryElementError: Unable to find role="group" and name "Window"`. A
`findBy*` query waits for a lazily loaded widget's range control with the default 1000 ms
timeout. Under load the lazy import takes longer than that.

## What to do

1. Find every query in `HomeDashboard.test.tsx` and its siblings under
   `frontend/src/components/home/` and `frontend/src/widgets/` that waits for something a lazy
   widget renders.
2. Make those waits robust without weakening what they assert. Choose one, and say which and
   why:
   - **(a)** wait for the widget's lazy module to resolve before querying, for example by
     pre-importing the registry's lazy components in the test's setup;
   - **(b)** give those specific `findBy*` calls an explicit timeout that matches the project's
     `testTimeout` budget (`vitest.config` sets 15 s since T-100);
   - **(c)** set Testing Library's `asyncUtilTimeout` once in the vitest setup file, if that is
     the project's pattern.

   **The orchestrator authorises editing these tests' waiting mechanics only.** No assertion may
   be removed, loosened or changed in what it checks. List every edited line in the report.
3. **Prove it.**
   - Run the full suite 3 times while the machine is loaded. One way to create load is a second
     full `npx vitest run` in parallel; say how you did it.
   - Give the failing count before and after your change, under the same load.
   - Then run the file alone 3 times.
