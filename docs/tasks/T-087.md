# Task T-087 — IPS anomalies in the analyst UI (Phase D §D.11.2, frontend)

Read `AGENTS.md` at the repository root first and follow it exactly, **§3a (the frontend quality

## Why

T-085 built the IPS analyst API: `GET /anomalies` now returns IPS rows (`subject_kind`
`IPS_ENTITY` or `IPS_SOURCE`, an `ips_entity` reference, IPS detector types) **whenever no
`subject_kind` is given**, `GET /anomalies/{id}` answers IPS incidents (with `detection` from the IPS
whitelist and `explanation_package: null`), and six `GET /behavior/ips/...` routes serve the series
and cells. The frontend knows only `LOG_SOURCE | WAF_ENDPOINT`. Today, with IPS anomalies present:

- the Home's Recent anomalies, the severity chart, the top-bar search and `/anomalies` receive IPS
  rows and draw them as Phase A rows (source volume wording, Phase A type labels);
- `/anomalies/{id}` on an IPS incident falls through to the Phase A page: it charts the **log
  source's EPS** and draws the IPS expected value (events, distinct ports or a share) **as EPS**.
  That is a wrong unit on an investigation page, the worst honesty failure this UI can make.

The same class of defect happened when WAF rows joined the list (T-057), and was fixed by giving
WAF its own row rendering and its own investigation view. Do the same for IPS.

## Build

### Part A — every existing anomaly surface reads IPS rows correctly

1. **Types** (`lib/api.ts`): `SubjectKind` gains `IPS_ENTITY | IPS_SOURCE`; `ips_entity` on the
   list item and the detail; the seven IPS detector types; `IpsDetectionDetail`; an
   `IpsAnomalyDetail` narrowing with an `isIpsDetail` guard, as WAF has; clients for the six
   `/behavior/ips/...` routes (typed from `schemas/ips_behavior.py`; every nullable field stays
   nullable).
2. **Labels** (`components/ips/ipsLabels.ts`, new): a plain name for each detector type and each
   entity dimension (e.g. "Destination port 445", "Destination 10.0.4.12", the signature's
   `display_name` with its QID when it has one, else "Signature QID n"). An unknown type or
   dimension renders as its raw value, never as a Phase A label.
3. **List rows** (`AnomalyRows`, Home `RecentAnomalies`, top-bar search): an IPS row names its
   subject (the entity, or "Source-level" for `IPS_SOURCE`) and its IPS source, with the IPS
   detector label. **No EPS or volume wording on an IPS row.** The deviation column shows what the
   row really has (the ratio is unitless; when it is null, the em dash).
4. **Filters** (`/anomalies`): the subject filter offers IPS entity and IPS source incidents; the
   type filter offers the IPS types (only with a matching subject, as WAF types are scoped today);
   `ips_entity_id` is passed through when present in the URL (a link from an entity view).

### Part B — the IPS investigation view

`/anomalies/{id}` for an IPS incident renders a new `IpsInvestigation` (dispatched like
`WafInvestigation`; the Phase A and WAF views stay unchanged):

- **Header**: the detector's label, the subject (entity with its dimension, or source-level), the
  IPS source (linked to `/admin/ips-sources/{id}` only if the user can read it; otherwise plain
  text), state, severity, detected/opened/resolved times **with timezone**.
- **What was judged**: from `detection` only, in the detector's own unit: events per 5-minute
  bucket for the rate and signature detectors; distinct destination ports for fan-out; a share
  (with its numerator and denominator) for concentration and block ratio; the new-port detector's
  events since first appearance against "none expected". Show the expected band
  (`expected_low`–`expected_high`) as a band where there is one; the `observed_measurement`
  `LOWER_BOUND` as "at least n"; `robust_score_status` limitations as the Phase A page does. Every
  missing value is the em dash with its reason, never 0.
- **Series**: for an entity incident, the entity's events per bucket around the incident
  (`/behavior/ips/entities/{id}/metrics`), with the seasonal band from its cells
  (`/behavior/ips/entities/{id}/baselines`, the cell of each bucket's weekday and UTC hour), as
  the WAF request chart does; for a source incident, the series its detector judges, from
  `/behavior/ips/sources/{id}/metrics` (the top-1 share for concentration, `max_distinct_ports`
  for fan-out, the blocked share for block ratio), with its band from
  `/behavior/ips/sources/{id}/baselines`. **A bucket with no row, or with a null value, is a gap,
  never a zero**; a bucket whose dimension `measurement` is not exact is marked; maintenance
  buckets are marked. Axis units always shown. If the series read fails, the rest of the page
  stands and the chart area says what failed.
- **Evidence**: an IPS incident has no evidence package. Say so plainly in one line (what the
  analyst can look at instead: the series and the detection block above). No contributor list:
  the API exposes none by design (source IPs never leave their stored lists), so render none.
- **Lifecycle**: the transitions, with the existing `LifecycleTimeline`.

Reuse what exists (the WAF chart's band rendering, `LifecycleTimeline`, `RouteState`, the honesty
pills) rather than copying it; if a WAF helper has to become generic to be reused, keep its WAF
callers' behaviour and tests unchanged.

## Round 2 (orchestrator screenshot review, 2026-10-14 ~22:20)

Accepted as built, apart from the three defects below. Same rules, files and gates as round 1.
Change only what these items need.

1. **The new-port detector is drawn in the wrong unit and against the wrong threshold.**
   In `backend/app/ips/behavior.py` `detect_new_destination_port`:
   - `observed_value` is the **cumulative** count of events since the port first appeared,
     across N buckets. It is not a per-bucket rate.
   - `threshold` is `new_port_min_events`, an **event-count materiality floor**, not a z-score.
   - There is no robust z and no seasonal baseline; `deviation_score` is None.

   Today the UI shows "310 events / 5 min" (metrics card, summary sentence), "events / bucket"
   (list row), and "Surprise threshold ±3.50" with "Robust score OK" (detection block). All of
   these are wrong for this detector. Required:
   - Observed reads as events since first appearance, for example "310 events since it first
     appeared". Use the backend's `reason` text where it says more (it names the bucket count).
   - Expected stays "none".
   - The threshold reads as the materiality floor ("material at ≥ n events"), never "±".
   - Robust-score, surprise-threshold and seasonal-baseline items render only when the payload
     carries them **and** the detector has that concept. For new port, none of them render.
   - The chart keeps its per-bucket series with "events / 5 min" on the axis: that axis really is
     per bucket. The headline must not mix the two units.
   - Apply the same check to every detector. Each item in "What was judged" must mean what the
     backend's evidence means for that detector (the rate and signature detectors are in
     `app/ips/detector.py`, the source and new-port detectors in `app/ips/behavior.py`).
   - Tests: pin the new-port unit, its threshold wording, and the absence of the robust-score
     line. Break-it: give new-port the rate detector's unit; a test must fail.
2. **`/anomalies` at 1024×768 clips numbers.**
   - The Observed → Expected column runs under the actions column. "Deviation 7.83x" shows as
     "Deviation 7.", the header as "Expe", and units are cut mid-word.
   - Guidelines §9 local scroll does not cover a clipped value: **no number, unit or header may be
     cut at 1024, 1280 or 1440**.
   - Fix it in the row layout. For example, let the unit wrap under its number, or shorten "none
     expected" to "none" (the header already says Expected). Keep tabular right alignment.
   - Check whether the Phase A and WAF rows were already clipped on `feat/phase-ce` without IPS
     rows, and report it. Either way, they must not clip after this round.
   - Add a test for the wrapping class or element if one is practical. Re-capture
     `anomalies-mixed` at all three viewports.
3. **The fixture's detection payloads must match what the backend actually sends** for each
   detector.
   - Read the evidence each detector writes, and the whitelist in `IpsDetectionDetailOut`.
   - Use each detector's real `caveat` text. Today every detector shows "Volume, not intent."
   - Set the real fields: new port carries no `robust_z` or `robust_score_status`, and its
     `threshold` is an event count.
   - Leave out what the whitelist does not forward.
