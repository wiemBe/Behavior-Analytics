## 2. What I did

`/anomalies/summary` reads its own clock at request time (`app/api/routes/anomalies.py:249`,
`now = datetime.now(UTC)`) and judges every source against the `(isoweekday, hour)` cell of
that instant. `/behavior/sources` keys the cell off each bucket's own `bucket_start`, so it is
already immune to the wall clock. The old file froze `NOW` at import; pytest imports every
module at collection, so in a ~13-minute suite a module imported at `:59` was judged at `:00`
and the seeded cells fell out of the hour the summary was reading. That is exactly the reported
failure.

There is **no existing seam** for this clock in the anomalies routes: the route calls
`datetime.now(UTC)` inline, and the only clock seam in the codebase (`_utcnow()` in
`app/api/routes/fleet.py`) belongs to a different router. Adding one to `backend/app/` is
forbidden by the task, so I used the task's first option instead:

- `_utcnow()` is a one-line module-level clock source, so a proof can patch it.
- `_now_and_earlier()` reads `_utcnow()` when the test starts (not at collection). If fewer
  than `_HOUR_GUARD_SECONDS = 60` seconds remain before the next UTC hour, it sleeps past the
  boundary and re-reads, so seeding and the request see the same hour. The wait is bounded: at
  most 60 s plus a 0.2 s skid.
- The `clock` fixture returns `(now, earlier)`; the identical `EARLIER = NOW - 2h` invariant is
  kept (`now - timedelta(hours=2)`, always a different `(weekday, hour)` cell).
- `_seed_mixed_fleet(session, now, earlier)` receives the pair; the four routes-driven tests and
  the direct-repo test unpack it from the fixture.

No assertion, message or test intent changed. §3 verifies that mechanically.

## 4. Proof — the clock moved across a UTC hour

The proof is an out-of-tree pytest plugin (`-p proof_clock_plugin`) that:

- patches the test module's own clock source `_utcnow` (this is the "test's own clock source"
  the task names), and
- patches `app.api.routes.anomalies.datetime` so the request-side read is deterministic. The
  plug-in's `datetime` subclass delegates its Pydantic schema back to `datetime`, because the
  route's `datetime | None` parameter annotations are resolved per request and would otherwise
  fail to build.

Two modes:

- `PROOF_MODE=old` — `_utcnow` never leaves **18:59:59** (the old collection-time `NOW`), while
  the route reads **19:00:01**. This is the defect: seeding and the request disagree about the
  hour.
- `PROOF_MODE=fixed` — `_utcnow` returns **18:59:59** on its first call, then **19:00:01**,
  while the route reads **19:00:01**. The fixed test's guard must notice the near boundary, wait
  past it, re-read 19:00:01, and seed into the hour the request will read.

Commands (from `backend/`; `PYTHONPATH` adds the work dir so the plugin imports):

```
cd /home/efe/Documents/QRadar-Dash-wt/t092/backend
PROOF_MODE=old   ENCRYPTION_KEY=... PYTHONPATH=.:/home/efe/Documents/QRadar-Dash-work/t092 \
TEST_DATABASE_URL=postgresql+asyncpg://test:test@localhost:5433/qradar_obs_t092 \
.venv/bin/pytest -o addopts="--strict-markers" -q -m integration -p proof_clock_plugin \
tests/integration/test_behavior_bulk_reads.py

PROOF_MODE=fixed ENCRYPTION_KEY=... PYTHONPATH=.:/home/efe/Documents/QRadar-Dash-work/t092 \
TEST_DATABASE_URL=postgresql+asyncpg://test:test@localhost:5433/qradar_obs_t092 \
.venv/bin/pytest -o addopts="--strict-markers" -q -m integration -p proof_clock_plugin \
tests/integration/test_behavior_bulk_reads.py
```

Results, verbatim:

```
# PROOF_MODE=old
FAILED tests/integration/test_behavior_bulk_reads.py::test_summary_counts_reliable_unreliable_and_missing_cells
1 failed, 5 passed, 2 warnings in 9.79s

# the failure body:
>       assert body["insufficient_data_sources"] == 4
E       assert 6 == 4
tests/integration/test_behavior_bulk_reads.py:351: AssertionError

# PROOF_MODE=fixed
6 passed, 2 warnings in 4.68s
```

Interpretation: with the clock frozen in the previous hour and the request in the next, the
summary counts all six sources as `INSUFFICIENT_DATA` (`assert 6 == 4`) — the reported defect,
reproduced. With the fixed file, the seeding clock starts one second before the boundary, the
guard waits for the hour to turn, re-reads 19:00:01, and all six tests pass. The
counterfactual (`old`) and the fix (`fixed`) differ only in the patched clock sequence, so the
guard is what commits the pass. Logs: `logs/proof_old.log`, `logs/proof_fixed.log`.

The old file itself was not run: its fixture-less collection-time `NOW` cannot be moved by
patching `_utcnow`, and running a copy from outside `tests/` would not pick up
`tests/conftest.py`. Freezing the new file's clock source in old-mode is the same scenario and
is what the task's fallback asks to show.

## 6. Scan of other test files (report only, nothing changed)

I searched all of `backend/tests` for module-level clock reads (regex for
`^NAME = ... datetime.now(...)`, `.utcnow()`, `date.today()`, `time.time()`, and indentation-0
`datetime.now`). Three other files match. Only the first is the same pattern; the other two are
not.

1. **`backend/tests/integration/test_phase_a_api.py:61`** —
   `NOW = (datetime.now(UTC) - timedelta(hours=1)).replace(microsecond=0)`. **Same shape.**
   `_seed` writes a `LogSourceBaseline` keyed on `(NOW.isoweekday(), NOW.hour)` (line 124) and a
   `LogSourceMetric` bucket at `NOW` (line 132); the file calls `/api/v1/anomalies/summary`
   (lines 596, 604, 613) and `/api/v1/behavior/sources` (line 471). It is **not currently
   exposed**: `/behavior/sources` keys the cell off the bucket's own `bucket_start`, and none of
   the `TestSummary` assertions read the hour-dependent `insufficient_data_sources` (they read
   `open_anomalies`, `spikes`, `drops`, `silent_sources`, `monitored_sources`,
   `highest_deviation`, `evidence_*`). The `/api/v1/anomalies` default window is a rolling 24 h
   and the seeded anomaly is at `NOW - 1 h`, so an hour straddle keeps it in range. Left
   unchanged, as instructed.

2. **`backend/tests/integration/test_ips_analyst_api.py:57`** —
   `NOW = (datetime.now(UTC) - timedelta(minutes=30)).replace(microsecond=0)`. **Not the same
   pattern.** `NOW` stamps detection times and builds explicit `since`/`until` query windows
   (`window()`, line 72). The routes judge the caller-supplied range, not their own current
   hour/day; calls that omit a range fall back to the rolling 24 h default, and the seeded
   detection times (`NOW - 30 min` .. `NOW - 10 min`) stay inside it. Left unchanged.

3. **`backend/tests/integration/test_waf_analyst_api.py:50`** —
   `NOW = (datetime.now(UTC) - timedelta(minutes=30)).replace(microsecond=0)`. **Not the same
   pattern**, for the same reason as (2): explicit `since`/`until` windows and detection
   timestamps, not a route-side current-hour/day lookup. Left unchanged.

Adjacent, and deliberately not the same: `test_fleet_api.py` and `test_fleet_eps_series.py` use a
module-level *fixed* `NOW = datetime(2026, ...)` plus `monkeypatch.setattr(fleet_routes,
"_utcnow", lambda: NOW)`. Those routes read their clock through that seam and the literals are
not clock reads, so they carry no exposure.

  practice, needed only by `/anomalies/summary`; it is applied uniformly to every test that
  seeds at `now`, which is harmless.
