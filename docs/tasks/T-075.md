## Why

The WAF analyst UI (T-060) cannot draw the ratio detectors' pooled expected proportion per bucket.
`GET /api/v1/behavior/waf/endpoints/{endpoint_id}/baselines` serves `WafBaselineCellOut`, which
leaves out the two columns the detector divides. Those columns are `WafEndpointBaseline.numerator_sum`
and `WafEndpointBaseline.denominator_sum` (see `backend/app/models/waf.py`). They are `NULL` for
count metrics and filled for ratio and share metrics (`backend/app/waf/baseline.py`, T-005).

## Build

In `backend/app/schemas/anomaly.py`, class `WafBaselineCellOut`, add two fields after `p95`, each
with a one-line `#:` comment in the file's style:

```python
    #: Ratio and share metrics only: the pooled sums the detector divides
    #: (expected proportion = numerator_sum / denominator_sum). None for count metrics.
    numerator_sum: float | None = None
    denominator_sum: float | None = None
```

Change nothing else in the schema or in the route. The route already builds the cell with
`model_validate(..., from_attributes=True)`, so the fields fill from the ORM row.
