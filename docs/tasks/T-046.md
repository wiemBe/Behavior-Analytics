## Build (§E.3)

1. **Capacity history.**
   - The provider DTO and the REST mapping gain `base_capacity`, `base_host_id` and
     `capacity_timestamp` (the 7.6 payload has them, PHASE3-HANDOFF §11.2); the mock gains
     realistic values. Read-only, no new request.
   - A new table `rule_capacity_sample` (migration `0016`): `rule_id` FK → `analytics_rule`
     (cascade), `capacity_timestamp` (timestamptz), `average_capacity`, `base_capacity`,
     `base_host_id`, `recorded_at`; PK `(rule_id, capacity_timestamp)`. A sample is stored **only
     when `capacity_timestamp` changes** (`ON CONFLICT DO NOTHING`); a row without a timestamp is
     not stored. Written in the rule sync with **one bulk statement** regardless of the rule count.
   - Migration: upgrade → downgrade → upgrade clean; `alembic check` clean; a round-trip test in the
     style of `tests/integration/test_migrations.py`.
2. **`GET /api/v1/rules/statistics?instance_id=&days=7&top=10`** (`days` 1–30, `top` 1–50), under
   the existing `read:rules` router guard:
   - `counts`: enabled/disabled × `rule_type` × `origin` × building block, as rows
     `{enabled, rule_type, origin, is_building_block, count}`.
   - `window`: the requested span, the expected and COMPLETE `rule_match_window` counts, and
     `complete: bool` (every window COMPLETE). Collection disabled or no windows → `complete:
     false` and the measured sections say "not measured" (null), never 0.
   - `silent`: enabled rules with **no** measured match over the span, **only** where
     `match_evidence` proves a zero (EVENT rules and EVENT building blocks) **and** the span is
     complete. Otherwise the section is null with a reason. COMMON, FLOW and OFFENSE rules are never
     listed as silent; report how many were excluded and why.
   - `top_by_matches` and `top_by_events`: top N by `match_records` / `matched_events` summed over
     the span, with each rule's `match_rate_per_second` (matched events ÷ span seconds) and, for
     COMMON rules, a `lower_bound: true` flag.
   - `costliest_by_benchmark`: the N enabled rules with the **lowest** non-zero
     `average_capacity`; zero or null is "no benchmark" and excluded (report the count). The
     response labels this section as QRadar's capacity benchmark (lower = costlier to evaluate),
     **not** a firing rate (§E.1).
   - **Constant SQL:** a fixed number of grouped queries regardless of the rule count; pin it with
     a statement-count test at two sizes (e.g. 20 and 600 rules).
3. **`GET /api/v1/rules/{rule_id}/capacity-history`**: the samples, newest first, at most 100.

## Tests

  stored; one statement for the batch; the migration round trip.
- Statistics: counts grouping; incomplete span → silent null with reason; complete span → EVENT
  rule without matches is silent, a COMMON rule is not (and is counted as excluded); a disabled
  rule never silent; top lists ordering and the COMMON lower-bound flag; match rate arithmetic;
  benchmark section excludes zero/null and sorts ascending; parameter validation (422); 401/403
