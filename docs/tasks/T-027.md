## Questions

1. **Which sources are IPS?** List the lab log sources whose type is an IPS or IDS DSM (T-015 §7:
   McAfee Network Security Platform, Snort, and others), with their ids, names, enabled flag and
   `last_event_time`. Which of them sent events in the last 24 hours?
2. **Volume shape.** For the IPS sources with events, give `SUM(eventcount)` and `COUNT(*)` per
   source per hour over the last 24 hours, in one search. How bursty is it, and how coalesced
   (records against events)?
3. **Field population.** For each active IPS source, measure the share of events with a non-null,
   non-zero value in each of `destinationport`, `sourceport`, `sourceip`, `destinationip`,
   `protocolid`, `qid` / `QIDNAME(qid)`, `category` / `CATEGORYNAME(category)`, `severity` and
   `magnitude`, and any custom property that looks like a signature id, action or direction. Use
   one or two aggregate searches, such as `SUM(CASE ...)` style or `COUNT(field)`. Say whether
   Ariel accepts each form.
4. **Cardinality.** Over 24 hours, per active IPS source: the distinct counts of
   `destinationport`, `sourceip`, `destinationip` and `qid`, plus the top 20 of each by
   `SUM(eventcount)`. Use bounded `GROUP BY` searches, and say where the 500 cap truncated.
5. **Port semantics.** Are the destination ports service ports (80, 443, 22 …) or ephemeral
   ports? Is the "attacker" in `sourceip` (inbound) or in `destinationip`? Is a direction field
   or custom property available?
6. **Action.** Is there a blocked/allowed (prevent/detect) signal per event, as a QID category,
   a custom property or a field? Which values occur?
7. **Synthetic lab generator.** Read `docs/LAB-SYNTHETIC-TELEMETRY.md`, but do not run the
   generator. Which IPS scenarios can it produce (for example port scan, new destination port,
   source-IP concentration)? What would a later live validation of Phase D need from it?
