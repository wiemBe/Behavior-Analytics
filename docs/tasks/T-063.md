# Task T-063 — live research: SIM Generic Log and unknown events, for Phase C.2 (G1)

Read `AGENTS.md` at the repository root first. Follow it exactly.

This is a **research task**. Write no application code, and change no repository file except your
report. Throwaway probe scripts go only in your scratch directory (below).

## Why

Goal G1 (PLANNER §0) asks to **track SIM Generic Log**: its volume, and a bounded list of the
senders feeding it. Those senders are candidate devices that nobody has configured as log
sources. T-015 §5 found one SIM Generic source on the lab, `SIM Generic Log DSM-7 :: qradarce2`
(id 62, type 67). It was silent, so **how a sender can be identified was never measured**. Read
`docs/tasks/T-015.report.md` §5, `docs/PHASE-C-LOG-SOURCE-FLEET.md` §C.0–§C.1, and
`docs/LAB-SYNTHETIC-TELEMETRY.md` (destination, rate limits, why unparseable events "fall through
to SIM Generic Log DSM as `Unknown log event`").

## Method

1. Send **unparseable** syslog to the lab destination given in `docs/LAB-SYNTHETIC-TELEMETRY.md`
   (default `192.168.122.50:514/UDP`). The payload is free text that matches no DSM, for example
   `<134>Oct 13 12:00:00 t063-unknown-a probe: free text 42`. Use a throwaway script in your
   scratch directory, or the repository's generator if it already has a suitable raw format; do
   not modify the generator. Use **two or three distinct syslog hostnames**, for example
   `t063-unknown-a`, `t063-unknown-b` and `t063-unknown-c`. Send **at most 2 EPS in total**, for
   **at most 15 minutes**. Then stop and confirm nothing is left running.
2. Observe with read-only REST and Ariel. Do not create, change or delete anything in QRadar.

## Questions

1. **Where did the events land?**
   - In the existing SIM Generic source (id 62)?
   - In a new auto-created source? If so, give its type, name and identifier.
   - Or nowhere, because they were dropped?

   Answer for each hostname, with timings: how long until the first event was visible, and
   whether that changed as more events arrived.
2. **Sender identification.** Which Ariel fields, if any, tell the senders apart on these events?
   Check `sourceip`, `destinationip`, `"Log Source Identifier"` (or whatever QRadar 7.6 calls the
   per-event identifier field; find the right name) and `LOGSOURCENAME(logsourceid)`. Check
   whether anything on the event carries the syslog hostname. **Do not select or print
   `UTF8(payload)` or any payload field.** If the hostname is reachable *only* through the
   payload, say so, and stop there.
3. **QID / category of these events.** What do `QIDNAME(qid)`, `CATEGORYNAME(category)` and
   `LOGSOURCETYPENAME(devicetype)` return? Is there a stable marker for "unparsed / unknown
   event" that does not depend on the English wording?
4. **The bounded senders search.** Validate, against your own events, the AQL shape a collector
   would use. It would be one search per tick, `START`/`STOP` bounded, over the catch-all types
   (`devicetype` in 67, 39, 212, 367, 4000, or by type name), grouped by `logsourceid`, the sender
   field from Q2 and the bucket key `starttime / 300000`, with `SUM(eventcount)` and `COUNT(*)`,
   `ORDER BY` volume, `LIMIT n+1`. Does it work, and how long does it take? Does a `WHERE` on
   `devicetype` IN (…) get accepted?
5. **Unknown events on parsed sources.** T-030 saw "Unknown Snort Event" on FTD. Is there a
   cheap, bounded way to count events per log source whose QID is a generic "unknown" one,
   without `SUM(CASE …)` (rejected) and without a payload? One search over all sources, grouped
   by `logsourceid` and with a `WHERE` on the QID marker from Q3. Run it once over the last hour.
