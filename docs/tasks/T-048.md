# Task T-048 — Pad the Ariel `STOP` so the last bucket of a span is not short of late-stored events

Read `AGENTS.md` at the repository root first and follow it.

## Background (T-040 Finding 1, [report](T-040.report.md) lines ~112–125 and ~200–210)

QRadar's `START`/`STOP` clause filters on the time an event was **stored**, slightly later than its
`starttime`. Every bounded search in `backend/app/providers/qradar_rest.py` has both an exact
`WHERE … starttime >= {start_ms} AND starttime < {end_ms}` and `START {start_ms} STOP {end_ms}`.
An event with `starttime` just before `end_ms` but stored just after it is dropped, so the last
bucket of every span undercounts by a handful of events (live: 5 in 2.4 M). The keyed path (one
search per tick) and the per-bucket path disagree on that edge, which breaks the "persisted rows
equal per-bucket rows" bar.

The fix: widen only `STOP` (never the `WHERE` bound) by a small pad. The `WHERE` clause still
decides which events count, so nothing outside `[start, end)` is ever counted.

## What to do

1. One helper in `qradar_rest.py` that renders the scope clause, e.g.
   `_ariel_scope(start_ms, end_ms) -> "START {start_ms} STOP {stop_ms}"`, with
   `stop_ms = min(end_ms + pad_ms, now_ms)` — never in the future. `now_ms` comes from an injectable
   clock (follow whatever clock pattern the provider or its callers already use; if there is none,
   add a constructor parameter defaulting to UTC now, so tests can pin it).
2. New setting `ariel_stop_pad_seconds` in `app/core/config.py`: default `60`, `ge=0`, `le=300`.
   `0` reproduces today's text exactly.
3. Use the helper in **every** query that has both the exact `WHERE starttime` bound and a
   `START … STOP …` clause (Phase A metrics and keyed metrics, rule matches and windowed rule
   matches, WAF observations / breakdowns / bucketed variants / totals, validation probes, anomaly
   explanation, and any other). First list them all in your report (function, line). A query whose
   `WHERE` does **not** bound `starttime` exactly to `[start, end)` must **not** be padded — list it
   and leave it.
4. Query versions: where a version string identifies the query text (e.g.
   `RULE_MATCH_WINDOWED_QUERY_VERSION`, WAF or Phase A query versions), decide whether to bump it.
   Bump it only if nothing keys continuity, deduplication or a watermark on that string; if
   something does, **do not bump it**, and explain in the report.
5. The mock provider models no stored-time skew: leave its semantics alone.

## Tests

- The helper: pad applied; capped at now; `pad = 0` gives today's exact text.
- For each padded query, the AQL text has `STOP {end + pad}` and the unchanged `WHERE … < {end}`.
- Existing tests that pin the exact AQL text with `STOP {end}`: this spec changes that text on
  purpose, so you may update **only the `STOP` value** in those pins (or set `pad = 0` in that
  test's settings — prefer this when the test is about something else). List every such test and
  which way you chose. Any other conflicting assertion: **stop and report**.
- Break the helper on purpose (pad the `WHERE` bound too, or drop the cap), see tests fail, restore.
