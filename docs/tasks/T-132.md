## Items

1. **`.qradar-dash/` is not ignored by git.** The runbook says the state directory is ignored;
   `.gitignore` lists `.env` but not `.qradar-dash/`, so an operator's checkout shows it untracked
   and a `git add -A` would commit the state file. Add it to the "Installer" block of
   `.gitignore`. Check with `git check-ignore -v .qradar-dash/state.json`.
2. **Runbook, host preparation order.** `useradd -m -G docker qdops` fails before Docker is
   installed (the `docker` group does not exist yet), and the runbook gives no Docker install
   commands. In "Kurulum", give the order: Docker Engine and the Compose v2 plugin from Docker's
   RHEL repository first (the commands OPS-11 used: `dnf config-manager --add-repo
   https://download.docker.com/linux/rhel/docker-ce.repo`, `dnf install docker-ce docker-ce-cli
   containerd.io docker-compose-plugin`, `systemctl enable --now docker`), then the account with
   the `docker` group. Turkish prose, English commands.
3. **Preflight prints a free-space "ok" for a directory it is about to refuse.** For a
   `BACKUP_DIR` that cannot be created, `[ ok ] 91 GiB free for backups at <path>` comes right
   before the T-130 `[FAIL] cannot create the backup directory …`. Make the free-space line come
   after the creatable/writable check and only when that check passed (on failure, print only the
   failure). Pin it through `install --dry-run`.
4. **`status` shows the wrong backup age.** After a rollback, `Last upgrade backup: … (age 0 min)`
   for a backup taken about 4 minutes earlier (`qradar-dash` ~871). Find the cause (from the
   backup name's stamp, a touched mtime, a time-zone or unit error) and fix it; pin it with a test
   that runs `status` on a fixture whose backup is N minutes old.
5. **`doctor` redacts a watermark family name.** The failing-watermarks line printed
   `geo_countries_source, ***redacted***, catchall_senders` (`doctor.py` ~92–100,
   `app/security/redaction.py`). Find which family name trips the redaction and why. Fix it so
   family names (a fixed, known set) print as they are **without weakening the redaction of any
   real secret**: every existing redaction test must stay green, and add one that proves a secret
   inside the same line is still masked.
6. **Runbook, `previous_images`.** In "Durum dosyasını okuma", one sentence: `previous_images`
   stays in the state file after a successful upgrade because `rollback` needs it.
7. **Investigate: `GET /api/v1/users` right after a sign-in once returned a non-list body**
   (OPS-11 step 7; OPS-10 saw the users list miss a just-created user once). Try to reproduce it in
   an integration test on your database: sign in (with the `Origin` header), then immediately
   `GET /api/v1/users`, in a tight loop (for example 200 iterations), also right after creating a
   user and right after a password change; record every non-200 or non-list body. If you find a
   cause, fix it with a test that fails before the fix. If you cannot reproduce it, keep the
   reproduction test only if it is fast (under 5 s) and deterministic, and report exactly what you
   tried; do not guess a cause.
