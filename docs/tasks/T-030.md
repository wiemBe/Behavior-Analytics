# Task T-030 — lab IPS sources through QRadar auto-discovery, and what they parse (G2, Phase D, D-8)

Read `AGENTS.md` at the repository root first. Follow it exactly.

This is a **live lab task**. Write no application code, and change no repository file except your
report. Throwaway scripts go only in your scratch directory.

## Why

Production IPS is **Cisco Firepower Threat Defense** and **Palo Alto (THREAT logs)**. The lab has no
live IPS telemetry (T-027). T-029 built vendor-native generator profiles (`pan_threat`, `ftd_ips`).
The user asked the orchestrator to create the lab IPS sources; because the platform is read-only
and the lab guide forbids creating log sources over the API, they are created **only** by QRadar
auto-discovery from the generator's syslog. The Phase D design and the D-8 IPS field-mapping
contract ([`docs/FIELD-MAPPING.md`](../FIELD-MAPPING.md) §FM.9) need to know what these DSMs parse.

## Do

1. Read `docs/LAB-SYNTHETIC-TELEMETRY.md` (the safety contract and "Vendor-native IPS (Phase D)"
   are binding) and `docs/tasks/T-029.report.md`. Preview each profile with `--dry-run --stdout`.
2. Check read-only first whether sources with identifiers `pa-fw-01` and `ftd-01` already exist
   (`GET` log sources). If they exist, do not send more than needed.
3. Send, one profile at a time, scenario `ips-baseline`, `--format vendor`, to the lab console's
   default destination, **at most 5 EPS** and **at most 30 minutes per profile** (stop as soon as the
   source appears). RFC 5737 sources and `10.10.20.0/24` destinations only, as the guide requires.
4. Poll (read-only `GET`, at most once a minute) for the auto-discovered sources. For each: QRadar
   id, name, type id and **type name**, `auto_discovered`, enabled, creation time.
5. Measure with read-only Ariel, each search bounded by `START`/`STOP` to the send window:
   - event count per source (`SUM(eventcount)`, `COUNT(*)`);
   - population of `sourceip`, `destinationip`, `destinationport > 0`, `protocolid` (use `> 0`
     shares, T-027 §3; ports are 0 when absent);
   - the `QIDNAME(qid)` distribution (top 20) and how many events are unknown / stored /
     "SIM Generic" — i.e. did the DSM parse them;
   - which custom properties apply to each new type (the T-041 join:
     `GET .../custom_properties/property_expressions?fields=regex_property_identifier,log_source_type_id,log_source_id,enabled&filter=log_source_type_id=<n>`
     joined to `regex_properties` names), and for any action-, signature- or severity-like property
     among them, its population and its top values (≤ 20) on these events;
   - whether a block/allow distinction is visible anywhere (a property, the QID name, the category).
6. If `pan_threat` is **not** auto-discovered within 30 minutes (IBM documents only LEEF and CEF for
   the PA DSM), stop that profile and record it. Do not create anything by hand or over the API.
   Say in the report what the user would need to create manually in the QRadar UI (name,
   identifier, type, protocol), so the orchestrator can ask them.
