## 2. What I did

- The fix is exactly what the task specifies: the parameter became optional, `None` resolves the
  default instance the way `rules.py::_resolve_instance` does (first `QRadarInstance` via
  `select(QRadarInstance.id).limit(1)`), and an empty fleet yields 404 with
  `"no instance registered"` — the detail and status `GET /rules/statistics` uses. An explicit
  `instance_id` is returned unchanged by the helper, so that path behaves exactly as before.
- **No shared place exists** for this helper: `_resolve_instance` is already a private duplicate in
  `rules.py`, `coverage.py` and `offenses.py`, and `app/api/deps.py` holds only session/provider/
  settings dependencies. Moving it into a shared module would mean touching a file this task does
  not name (plus refactoring three other routes), so I followed the task's stated fallback and
  added **one small private helper per module**, matching `rules.py` line for line.
- Frontend untouched (task is backend only); `frontend/src/lib/api.ts` and
  `AddSourcePicker.tsx` already call the picker without `instance_id`, which now works.
