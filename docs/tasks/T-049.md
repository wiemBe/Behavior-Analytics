## Build

1. **Model + migration `0017`** (chained after `0016`): `ips_source_profile` exactly as §D.3 (the
   columns listed there, `log_source_id` UNIQUE with FK cascade, `mapping` and `action_value_map`
   JSONB, `preset` nullable, the validation and pending columns). Enums for the validation status
   and the preset are new IPS enums (or reuse the WAF validation-status enum type only if that does
   not alter it). Upgrade → downgrade → upgrade clean; `alembic check` no drift; a migration test in
   the existing style.
2. **`app/ips/profile.py`** — `IpsFieldMapping`:
   - logical fields `SOURCE_IP`, `DESTINATION_IP`, `DESTINATION_PORT`, `PROTOCOL`, `SIGNATURE`,
     `ACTION`, `SEVERITY` with required/optional as §D.3's table;
   - a reference is `{"kind": "NORMALIZED", "name": <allowlist>}` or
     `{"kind": "CUSTOM_PROPERTY", "name": <PROPERTY_NAME_PATTERN>}` or `null` (optional only);
     normalized allowlist exactly `sourceip, destinationip, destinationport, sourceport, protocolid,
     qid, severity, category` — never free text; reject anything else with a safe message;
   - action value map `{BLOCKED: [...], ALLOWED: [...]}`: values bounded in count and length like
     WAF's; a value in both lists, or a non-empty map with `ACTION` unmapped, is an error;
   - presets `CISCO_FTD` and `PALO_ALTO_THREAT` (§D.3 defaults; `ACTION` unmapped) as data, used
     only to prefill; a preset is never trusted (the profile still validates).
3. **Provider (read-only):** add one method to `app/providers/base.py`, REST and mock, e.g.
   `probe_ips_fields(...)`, mirroring `probe_waf_properties`: bounded Ariel searches (count them;
   at most the WAF validation's budget), returning **counts only** plus the bounded ACTION value set
   (≤ 20 values). IPS semantics (§D.3 "Validation", T-027): port population is the `> 0` share,
   protocol the `> 0 AND < 255` share, an IP field's population excludes loopback, `SIGNATURE` by
   QID reports the share whose `QIDNAME` is generic ("Unknown …") as a **warning, not a failure**.
   A normalized field is quoted as a normalized identifier, a custom property as a quoted property
   name, both only after validation. `SUM(CASE …)` is rejected by QRadar: use separate aggregates or
   `WHERE` filters. MCP provider: unsupported (fail closed, as for WAF).
4. **`app/ips/validation.py` + `app/services/ips_profiles.py`:** `IpsProfileService` with upsert,
   set_enabled (enable only when the current version is `VALID`), validate, the async request and
   worker, audit records with `object_type = "ips_source_profile"` — all as WAF, including the
   stale-version guard and the lock-busy countdown/retries. IPS collection does not exist yet:
   define the per-source IPS pipeline lock key now (one helper) so T-050 reuses it.
5. **Permission `admin:ips`** in `app/security/rbac.py` (granted to the same roles that hold
   `admin:waf`; `read:*` does not satisfy it). Router guard on the whole `/api/v1/ips` router.
6. **Routes `/api/v1/ips/…`** mirroring §FM.4 with the IPS schema: `mapping-schema` (fields with
   `kinds` and `normalized_options`, the presets, `min_coverage_ratio`), `candidates` (class `IPS`
   first, then name; `instance_id` on each item), profile `GET`/`PUT` (optimistic concurrency,
   201/200/409/422 exactly as WAF, including the structured `detail` shapes), `validate`, `enable`,
   `disable`, `history`, and the property catalog for the source's DSM type (reuse T-043's provider
   method and cache). `GET /ips/sources` lists profiles with status and the pending fields. The
   served validation report never contains query text.
7. Settings in `app/core/config.py`, bounded, in the WAF style (validation min ratio, pending
   timeout, lock retry countdown and max retries, ACTION value bound).
8. CORS: nothing to do (T-042 added `PUT`).
9. `tests/unit/test_route_auth_guard.py`: add `_BODIES` entries for the new mutating routes if the
   guard test needs them. Change nothing else there.

## Tests (pin every guard and exit path)

- Mapping: every allowlisted normalized name accepted; a non-allowlisted normalized name, a free
  text normalized reference, a custom name failing the pattern (`x"; DROP`), a missing required
  field, overlapping action values, an action map without `ACTION` → rejected with a safe message.
- Presets: both prefill §D.3's defaults; a preset-created profile is `UNVALIDATED` and disabled.
- Provider: REST AQL text for each kind (normalized vs custom quoting), the `> 0` / `< 255` /
  loopback filters, the bounded ACTION value set, the search budget; mock parity; MCP unsupported.
- Validation: VALID; a required field below the min ratio → not VALID; generic QID names → warning
  only; ACTION unmapped → still VALID (block ratio will be INSUFFICIENT_DATA later); a failed or
  truncated probe → never VALID.
- API: 401 / 403 (`read:*`, and `admin:waf` alone does not grant `admin:ips`) / 404 / 422 / 409
  (stale version, pending, enable refused) / 201 / 200, with the exact `detail` shapes; history
  ordering and limit; candidates ordering, limit, `q` with `%`/`_` literal.
- Worker: success; stale-version race (discard + re-enqueue); exception clears pending, no VALID;
  lock busy → countdown re-enqueue, bounded retries, exhaustion → busy outcome, pending cleared.
- Audit actor is the principal on every mutation.
- Break each guard on purpose, see a test fail, restore.
