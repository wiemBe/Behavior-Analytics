## 2. What you did

For each route I read its `page.tsx` and the components it renders, listed the states it
can produce in a comment at the top of the test, mocked the `@/lib/api` functions the page
calls, rendered `await Page({ params, searchParams })`, and asserted with Testing Library
by role and text. The tests describe the current behaviour and pin what a restyle must not
change: headings, section order, column headers, numbers with their units, UTC time
suffixes, link targets, query parameters passed to the API, paging links, and the honesty
states the page draws today (em dash for a missing value, "never", "unknown", lower-bound
"≥", "no verdict"). Tone/status pill class names are asserted only where the page uses the
class as meaning, and each such file says so in its header comment. The client islands
(`next/navigation`, ECharts) are the only things stubbed; `searches/[id]` and `alerts/[id]`
mock `useRouter` and the trend's read to its empty state.

Defects found are **not** asserted as correct. Each is written as an `it.todo` with a
one-line description and listed under gate 3 below.
