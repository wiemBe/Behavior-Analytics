## 2. What I did
- Preflight: an existing directory needs `-w` and `-x`, else `fail "the backup directory <path> is not writable by this account; give it to this account (see docs/OPERATIONS.md, Kurulum)"`. A missing path walks up to its nearest existing parent, which must be a writable, enterable directory, else `fail "cannot create the backup directory <path>: <parent> is not writable by this account; create it first (see docs/OPERATIONS.md, Kurulum)"`. Both set `bad=1`. The check writes nothing and runs under `--dry-run`. The existing-directory check lives in `preflight_network`, not `preflight_host`, so I put it there.
- Install step: `mkdir -p ... || die "cannot create the backup directory <path>"`, then `chmod 700 ... || die "cannot set mode 0700 on the backup directory <path>"`.
- Runbook: only that one sentence changed (Turkish prose, English messages copied from the script).
- Tests:
  - existing dir at 0500 refused;
  - missing dir under a 0500 parent refused;
  - `--dry-run` with an unwritable dir refused;
  - a missing dir under a writable parent installs and ends up 0700;
  - a `mkdir` stub in PATH that fails only for the backup path, so the preflight passes and the `die` is reached: exit 1, message, no `.qradar-dash`.
  - The three refusal tests assert exit 1, the message on stderr, and neither `.env` nor `.qradar-dash/`. Every chmod is restored in `finally`.
  - Skips added: 3 (`skipif(os.geteuid() == 0)` on the three permission tests). They do not skip on the host or in CI as a non-root user. The mkdir-stub and 0700 tests do not depend on file permissions and are not skipped.

## 4. Open points
- The `chmod ... || die` branch has no test of its own. `chmod` fails only on a directory the account does not own, which a unit test cannot set up as a non-root user. If it is broken, the install would continue with a wrong mode. It is a one-line `|| die`.
- The check tests the running account's access with `-w`/`-x`. ACLs and read-only mounts are not modelled beyond what bash `-w` reports. A read-only filesystem is reported as writable by `-w` only if the kernel says so; normally it does not.
- The existing-directory refusal is in `preflight_network`, so it runs after the host checks. A host that fails earlier checks reports those first.
