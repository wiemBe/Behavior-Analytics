## 2. What I did
- Followed the spec. `EndpointCategory`: reused `LOG_SOURCE_LIST` (as `list_log_source_groups` does); no new category was added to `telemetry.py`.
- `log_source_id` in the route is the internal log source UUID (like `/waf/sources/{profile_id}`). 404 for an unknown log source or one without an instance.
- The service takes a provider factory, so a cache hit builds no provider; on a miss the provider is built and closed. Any exception (including factory failure such as a missing token) becomes `UNAVAILABLE` with `"<ClassName>: the property list could not be read from QRadar. Property names can still be typed."`. Nothing upstream is echoed; failures are not cached (a failed refresh keeps the previous good entry).
- `applies_to_source_type`: true/false/null (null, and `filtered_by_source_type=false`, when the log source has no `type_id`). Sort: applies true first, then name (case-insensitive).
- Mutation checks: dropping the `enabled` filter failed `test_only_enabled_whole_type_known_expressions_count`; caching before a failed fetch failed `test_failure_is_unavailable_safe_and_not_cached`. Both restored.
- `test_route_auth_guard.py` passes unedited with the new route.

## 4. Open points
- The cache is process-local per API worker, as specified; the singleton is created from `get_settings()` at first use, so the TTL setting is read once per process.
- The catalog fetches the whole console list (no `filter=`), then filters in memory, so one cached entry serves every source of the instance. The provider's `log_source_type_id` filter is implemented and tested but unused by the service.
- Expressions with `log_source_id != -1` are ignored, as spec'd; a property only extracted for one specific source will show `applies_to_source_type=false`. Not seen in the lab.
- `ruff`'s `RUF100` rejected a `# noqa: BLE001`, so the broad `except Exception` carries a plain comment.
