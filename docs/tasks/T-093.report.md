Meets the task's acceptance criteria:

- `WafDetectionDetailOut.caveat` is a new whitelist field defaulting to `None`, placed between
  `percentage_point_change` and `ratio`, with a comment matching the IPS block's wording. This is
  a plain whitelist field, so the existing `set(dumped) == set(WafDetectionDetailOut.model_fields)`
  test keeps passing unedited: `caveat` is now in both sets (dumped as `None`).

  returns the value only when it is a `str` and `None` otherwise — so a missing key and a
  non-string (e.g. `{"caveat": 3}`) both yield `None`, never a coerced value.

  40)` run through `detect_block_ratio_spike` via `run`) to produce a real anomalous ratio
  verdict, then runs `verdict.evidence.to_dict()` (the persisted `details` form) through
  `waf_detection_detail` and asserts the projected caveat equals `BLOCK_RATIO.caveat`. This is the
  task's fourth test; the new-endpoint detector's evidence is also covered textually by the
  "forwarded" test, which uses the new-endpoint caveat string.

  projection. `test_caveat_is_forwarded_from_the_evidence` and
  `test_a_real_detectors_evidence_projects_its_own_caveat` both failed
  (`assert None == "..."`), confirming the tests pin the behavior;
  `test_caveat_is_none_when_absent_and_when_malformed` stayed green because it asserts `None` on
  both sides. I then restored the line and re-ran the suite (green; `git diff` confirms only the
  additions above).
