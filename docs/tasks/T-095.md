# Task T-095 — the test runner: vitest 2 → 4

Read `AGENTS.md` at the repository root first. Follow it exactly.

## Why

T-088's audit ([report](T-088.report.md), "vitest 2.1.8 → 4.1.11+") found that the whole test
chain (`vitest`, `@vitest/mocker`, `vite`, `vite-node`, `tinypool`) carries critical and high
advisories, none reachable here (tests run with `vitest run`; no UI or API server). Only
**vitest ≥ 4.1.11** clears all of them. T-091 did the in-range updates and left this major.
This is a dev-dependency upgrade. It changes no application code and no test meaning.

## Build

1. In `frontend/`, upgrade `vitest` to the latest 4.x that is at least 4.1.11 and at least two
   weeks old. Upgrade what it requires to stay consistent: `@vitejs/plugin-react` to a version
   whose `vite` peer range matches the `vite` vitest 4 pulls in, and `jsdom` only if vitest 4
   requires it. Pin exact versions in `package.json`, as the file already does. Regenerate
   `package-lock.json` with `npm install` (Node is at `~/.local/node/bin`, v22).
2. Adapt `vitest.config.ts` and `vitest.setup.ts` to vitest 4's configuration, if needed (read
   the official vitest 3 and 4 migration guides; quote the breaking changes you acted on in the
   report).
3. **Tests:** the same test files and the same number of tests must pass as before the upgrade.
   Record the before count first, on the untouched worktree
   (`npx vitest run --no-cache`, summary line verbatim).
   - A test file may be edited **only** where a vitest API changed (for example a renamed `vi.*`
     function, mock typing, fake-timer defaults). Never change an assertion, never skip, `xfail`
     or delete a test, never loosen a matcher. List every test edit in the report with the
     breaking change that forced it.
   - If a test fails for a reason you cannot trace to a documented breaking change, stop and
     report it; do not work around it.
4. `npm audit` before and after (`npm audit --json` summary counts by severity, for the full tree
   and with `--omit=dev`). The production count must not grow.

## Allowed files

- `frontend/package.json`, `frontend/package-lock.json`
- `frontend/vitest.config.ts`, `frontend/vitest.setup.ts`
- test files under `frontend/src/**/*.test.{ts,tsx}`, only as item 3 allows
- `docs/tasks/T-095.report.md` (new)

No application source change (`frontend/src/**` outside test files). No other dependency upgrade
(`echarts` 6 is a separate task).
