## 2. What I did
- **Provider:** REST AQL has WHERE half-open bounds, GROUP BY creEventList, `ORDER BY COUNT(*) DESC`, LIMIT, START/STOP. Only validated bounds and the integer cap are interpolated. The cap is `min(max_rows, page_size*max_pages)`. `truncated = raw page rows >= cap`. A null id is excluded and not counted. A missing or non-integer id, or a bad count, is dropped and counted in `malformed_rows`.
- **Tables:** exactly the §E.2 columns plus check constraints. The migration has no backfill, so there are no transient defaults.
- **Fail-closed addition:** a window with `malformed_rows > 0` is stored as TRUNCATED, because a dropped row could have been any rule.
- **Collector:**
  - Advisory lock, watermark, settle lag, at most N windows per run (oldest first), one search per window.
  - Per window: one delete of that window's rows, one bulk upsert, one window upsert. That makes re-collection idempotent with no stale rows.
  - A provider failure writes a FAILED window and no rows, stops the run, and does not advance the watermark, so the next run retries. A failed retry never downgrades an existing COMPLETE window.
  - A provider without AQL records nothing (`unsupported`).
- **Rule health:**
  - EVENT with COMPLETE coverage: the count is the measured `matched_events` and the zero is real. This makes NEVER_OBSERVED, INACTIVE and NOISY provable.
  - EVENT with incomplete coverage: the count is a lower bound and `observation_complete` is forced False, so the result is INSUFFICIENT_DATA when silent.
  - COMMON: matches are a lower bound, so silence is never proven.
  - Other types are untouched. If the instance has no match windows at all, behaviour is identical to before.
  - A recent measured match overrides a stale offense-based `last_fired_at`, so a firing rule is not called INACTIVE.
  - Coverage = every grid window in the span that has settled must be COMPLETE at the current width. A missing window counts as incomplete.
- **Scheduling:** `rule_match_collection_enabled=false` by default, so the task returns `{"status":"disabled"}`. Other settings: interval 900 s, window 3600 s, settle 300 s, 6 windows per run, row cap 2000 (max 5000, so one bulk upsert stays under asyncpg's 32,767-parameter limit).
- **Statement counts:**
  - Collector run of one window: 9 statements at both 50 and 1,000 matched rules (3 per window plus lock, watermark and rule-map statements).
  - Rule health: `rule_match_*` queries are 3 per instance evaluation, at both 3 and 30 rules.

### Behaviour
- **Bounded retries:** the attempts for a window are read in one query per run (FAILED rows only). Each failure writes FAILED with `attempts` and `last_error`.
  - Below the limit, the run stops and the watermark stays, so the next run retries.
  - At the limit, the FAILED record stays, the watermark advances past the window, and the run continues with the next window, still within `max_windows_per_run`.
  - Rule health keeps reading a span that holds that window as INSUFFICIENT_DATA.
  - A successful window records `attempts = prior + 1`.
- **Bounded catch-up:** the horizon is `floor(settled_until - catchup)`, capped so the newest settled window is always collectible. If the first window after the watermark lies before the horizon, every window in between is recorded as FAILED by one `INSERT ... SELECT generate_series(...) ON CONFLICT DO NOTHING`.
  - The statement has constant parameters whatever the number of windows.
  - The skipped rows get `attempts=0` and `last_error='skipped: beyond the catch-up horizon'`.
  - The watermark then jumps to the last skipped window, so collection resumes at the horizon.
  - The skip never writes metric rows, and never overwrites an existing window (it does nothing on conflict, so a COMPLETE one stays).
  - A first run (no watermark) is unaffected.

### Tests and statement counts
- **Exhausted window:** three runs fail on the 10:00 window (the first two hold the watermark). The third records it FAILED with attempts=3 and its last error, collects 11:00 in the same run, and leaves only the 11:00 row in the metrics.
- **Transient failure:** a window that fails once and then succeeds ends COMPLETE with attempts=2, and is not skipped.
- **Attempts limit of 1:** it skips on the first failure.
- **Far-behind watermark:** 10 windows are skipped and recorded FAILED with the reason. No search is made for them, and collection resumes at the horizon.
- **Statement count of a whole run:** it is equal at 10 skipped windows and at 500.
- **No overwrite:** the skip does not overwrite a COMPLETE window.
- **Rule health:** a skipped window in the span gives INSUFFICIENT_DATA for an EVENT rule.
- **Mutation checks, each failed as expected and was restored:**
  - Retry bound removed (the window never skipped): the "keeps failing" test fails.
  - Skip on the first failure: `test_provider_failure_writes_a_failed_window_and_no_rows` fails.
  - Horizon check disabled: the horizon test and the constant-statement test fail.
  - `ON CONFLICT DO UPDATE` instead of `DO NOTHING`: the no-overwrite test fails. The `windows()` test helper now uses `populate_existing`, because the raw skip statement was otherwise hidden by the ORM identity map (the test was vacuous before that).
