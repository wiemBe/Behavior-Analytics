# Task T-109 — replace Starlette's deprecated `HTTP_422_UNPROCESSABLE_ENTITY`

Read `AGENTS.md` at the repository root first and follow it exactly (§1 scope, §3 style, §4
tests, §5 running things).

## Why

The integration suite prints `StarletteDeprecationWarning: 'HTTP_422_UNPROCESSABLE_ENTITY' is
deprecated. Use 'HTTP_422_UNPROCESSABLE_CONTENT' instead.` once per 422 response. There are 18
uses in 7 route files (`grep -rn HTTP_422_UNPROCESSABLE_ENTITY backend/app backend/tests`).
When Starlette removes the old name, those routes fail at import. The status code itself (422)
does not change.

## What to do

1. Replace every `HTTP_422_UNPROCESSABLE_ENTITY` in `backend/app/` with
   `HTTP_422_UNPROCESSABLE_CONTENT`. Use the same `status` import each file already has. Touch only
   those lines and reformat nothing.
2. **The dependency floor.** `backend/pyproject.toml` says `fastapi>=0.115`, and the Dockerfile
   runs `pip install .` without a lock file. A fresh install at the floor could therefore pick up
   a Starlette that lacks the new name.
   - Find the first Starlette release that defines `HTTP_422_UNPROCESSABLE_CONTENT`, from the
     installed package's source or changelog, or from PyPI metadata if you have network access.
   - Find the first FastAPI release whose Starlette requirement guarantees that release.
   - Raise the `fastapi` floor in `pyproject.toml` to it. If you cannot establish it with
     evidence, raise the floor to the installed version (`.venv/bin/python -m pip show fastapi`).
   - Say which way you went and why.
   - Change no other dependency.
3. Tests. If any test uses the old name, replace it the same way; a constant rename is not a
   weakening. Add one unit test that fails if the old name comes back anywhere under `app/`: a
   source scan in the style of the existing contract tests in `tests/unit/`.
4. Break-it: put one old name back, confirm the new test fails, then restore.
