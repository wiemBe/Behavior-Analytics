# Task T-056 — WAF anomaly alerts carry the source's Phase C class, so class routing reaches them

Read `AGENTS.md` at the repository root first and follow it.

## Background (T-023 open point)

Alert routing can match a source class: `app/alerts/routing.py` reads
`alert.context["source_class"]`. Phase A alerts set it (`app/anomaly/engine.py`, `_alert_input`
and `_source_class`, around lines 689–720): added to `context` **only when known**, and **never part
of the fingerprint**. Inventory alerts set it too.

WAF anomaly alerts do not. `WafAnomalyEngine._alert_input` (`app/waf/engine.py`, around line 1010)
builds `context` without `source_class`, so a route restricted to, say, `WAF` never matches a WAF
incident.

## What to do

1. In `app/waf/engine.py`, add `"source_class": <class>` to the WAF alert `context` when the
   source has a `LogSourceClassification` row (`app/models/fleet.py`); omit the key when it has
   none. Same string form as Phase A (`str(source_class)`).
2. **No new SQL per endpoint and no new statement per run, if at all possible.**
   `_apply_alert_actions` already issues one lazy lookup per run, only when there are opens:
   `session.get(QRadarInstance, log_source.instance_id)`. Fetch the instance name and the class in
   that same single round trip (e.g. one `select(QRadarInstance.name, LogSourceClassification.source_class)`
   with an outer join on the log source), still only when `opens` is non-empty.
   - Then check the statement-count pins: `tests/integration/test_waf_scale.py`,
     `tests/integration/test_waf_keyed_collection.py` and `tests/integration/test_waf_alerting.py`.
     If any pinned count changes, **stop and report** (test, assertion, old and new count). Do not
     edit an existing test.
3. The fingerprint (`_fingerprint`, `waf_anomaly_fingerprint`) must not change. Phase A code must
   not change.

## Tests

- A classified WAF source: the opened alert's `context["source_class"]` equals the class; a route
  with `source_classes={"WAF"}` matches it (use the existing routing test helpers/patterns).
- An unclassified WAF source: `source_class` is absent from `context` (not `None`, not `""`).
- A route restricted to another class does not match.
- The fingerprint is identical with and without a classification row.
- Statement count of a run with opens is unchanged from before your change (measure it before
  editing, record both numbers in the report).
- Break the change on purpose (drop the key), see the tests fail, restore.
