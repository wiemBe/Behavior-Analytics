# Task T-101 — lab generator: IPS scenarios never reach their change phase with two profiles

Read `AGENTS.md` at the repository root first and follow it exactly. Then read
`docs/tasks/T-054.report.md`, section "Defect D-1": the live validation found this defect, and the
section states it precisely.

## The defect

`tools/qradar_lab_loggen.py`: `_scenario_event` round-robins the selected IPS profiles and passes
`local_index = index // len(profiles)` to `_ips_event`. `_ips_event` computes
`planned = self.options.count` and `transition = max(1, planned // 2)`, then
`anomaly = index >= transition`, with `index` being the **per-profile** index. With
`--types pan_threat ftd_ips --count 9000`, each profile emits 4500 events (`local_index` 0…4499)
while `transition` is 4500, so `anomaly` is never true. The phase-gated scenarios
(`ips-signature-burst`, `ips-source-concentration`, `ips-new-port`, `ips-block-shift`) never
change shape. `ips-port-sweep` is not gated and is unaffected. The same arithmetic applies when
`planned` comes from `--duration × --eps`.

## Fix

The transition must be half of **this profile's** planned events: the per-profile planned count is
the total divided over the profiles in the round-robin (account for a remainder: with an odd total
the profiles do not get equal counts; the transition must still fall inside each profile's own
run). Keep the single-profile behaviour exactly as it is today (same events, same order, same
transition), and keep the `planned == 0` fallback (`1_000`) unchanged. Change nothing else in the
generator: no new option, no change to event content, rate, bounds or the output formats.

  in each profile's first half and the scenario's change shape in its second half (for example:
  `ips-new-port` emits port 8443 only in the second half of each profile's events, and does so for
  **both** profiles; `ips-signature-burst` concentrates on signature 0 in the second half;
  `ips-source-concentration` puts about 70% of second-half events on one source).
- An odd total (e.g. `--count 9001`) with two profiles: both profiles reach their change phase.
- The `--duration`/`--eps` path with two profiles behaves the same.
- One profile: the transition is unchanged from today (pin the index where the change begins).
