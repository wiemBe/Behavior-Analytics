# Task T-051d — IPS training per source, bounded by that source's own evaluation

Read `AGENTS.md` at the repository root first and follow it exactly. Rules 8 (fail closed) and 9
(constant statements) and §4 (never weaken a test) matter most.

T-051c (merged) runs collect → evaluate → train for IPS. Its `_train` in
`backend/app/services/ips_pipeline.py` trains **once per instance**, bounded by the **earliest**
evaluated bucket end across every IPS source of the instance, because
`IpsBaselineBuilder.rebuild_due` (`backend/app/ips/baseline.py`, T-051b) has no source or instance
scope. Read `docs/tasks/T-051c.report.md` ("What was wrong" and "Open points") first.

## The defects

1. **Stall.** One source whose evaluation watermark stops moving holds back training for every
   IPS source of its instance, indefinitely. That source can be one whose profile was disabled,
   whose validation went stale, or whose collection fails every tick. Its watermark stays where it
   stopped, so `min(ends)` stays there too. One misconfigured sensor silently freezes every IPS
   baseline.
2. **Cross-instance leak.** `rebuild_due` is not scoped to an instance, so instance A's bound can
   train instance B's baselines on buckets B has not yet judged. That breaks evaluate-before-train
   on B.

## Build

- **Scope `rebuild_due`.** Give `IpsBaselineBuilder.rebuild_due` a scope: the source(s) whose
  subjects (entity cells and source cells) it may rebuild, each with its own `train_through`
  bound. Choose the shape: one call taking a mapping `{log_source_id: train_through}`, or one call
  per source. Either way, **the number of statements must not grow with the number of entities**.
  If you take one call per source, the per-source cost must be a constant number of statements, and
  the scale test must pin it at two sizes. Say which shape you chose and why.
- **Train per source** in `_train`: each source that evaluated successfully this run (or has an
  evaluation watermark from an earlier run and did not fail this run) trains through **its own**
  evaluated bucket end. A failed or never-evaluated source is skipped **alone**, with its reason in
  its own report entry. Others are not held back.
- Keep everything T-051c pinned: evaluate before train; never train past a source's evaluation
  watermark; the savepoint per source; the sanitized error; the `baseline_rebuilt_at` /
  `baseline_train_through` metadata (now per source).
- Keep `rebuild_due`'s existing callers working (look for them with grep). If one depends on the
  unscoped form, keep that form available or update the caller, and say which.

## Tests

Add (do not weaken any existing test; `test_training_stops_at_the_least_evaluated_source` pins the
old instance-wide rule, so **change only its expectation** to the per-source rule and say so in
the report):
- a source whose evaluation watermark is far behind (a disabled profile) does **not** hold back
  another source's training; each trains through its own bound;
- a source that failed this run is skipped alone;
- two instances: training instance A never rebuilds a cell of instance B's sources;
- `rebuild_due` scoped to one source never touches another source's cells;
- the statement count of training is constant in the number of entities (two sizes), and, if you
  chose one call per source, constant per source.

Break each guard on purpose and confirm a test fails; list them.
