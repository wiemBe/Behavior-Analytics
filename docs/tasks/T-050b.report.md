## 2. What I did

- Added migration 0018 after 0017 with `ips_source_bucket` and `ips_entity_metric` hypertables,
  the exact four-column `ips_entity` natural key, additive cadence seeding, clean downgrade and
  model parity.
- Persisted only folded aggregates. Source IPs leave folds only in the two contributor lists,
  each bounded to ten; AQL and raw keyed rows are never written.
- Reused the WAF admission decision unchanged per `(source, dimension)`. Quota, threshold and
  active ceiling refusals retain only aggregate counts; refused names create no entity row.
  Retired entities re-enter through admission without resetting first sighting.
- Planned all eligible sources fleet-wide, grouped sources by their own watermark window, shared
  one tick-wide search budget, and held each source's IPS pipeline lock across search and writes.
  Entities, metrics, buckets, watermarks and retirement use a fixed bulk-statement shape.
- **Watermark rule:** a source bucket is written and its watermark advances whenever its `TOTALS`
  cell is `COMPLETE`. An optional dimension that is `FAILED`, `REJECTED` or `NOT_COLLECTED` is
  stored with that explicit measurement and `NULL` facts/coverage, and does not hold the
  watermark. A missing or non-`COMPLETE` `TOTALS` cell writes no bucket and holds the watermark.
  This follows WAF's optional-breakdown precedent and cannot turn missing evidence into zero.
- Coverage is nullable when unmeasured and clamped to 1.0 when searches taken at different times
  produce a ratio above one. `LOWER_BOUND`, maintenance and safe provenance propagate to storage.
- Added the global `IPS_COLLECTION` cadence claim before provider construction, a 60-second beat,
  and one bounded retention task.
- Measured **12 SQL statements** for both scale fixtures: 2 sources with 10 pre-existing entities,
  and 20 sources with 400 pre-existing entities. A deliberate per-source lookup changed these to
  14 and 32 respectively and was killed by the test.
- Added the approved frontend family type and copy. No frontend family-list or `FAMILY_INFO` key
  test required a change.
