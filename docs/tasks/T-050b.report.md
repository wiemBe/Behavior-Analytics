## 2. What I did

- Added migration 0018 after 0017 with `ips_source_bucket` and `ips_entity_metric` hypertables,
  the exact four-column `ips_entity` natural key, additive cadence seeding, clean downgrade and
  model parity.
- Persisted only folded aggregates. Source IPs leave folds only in the two contributor lists,
  each bounded to ten; AQL and raw keyed rows are never written.
- Reused the WAF admission decision unchanged per `(source, dimension)`. Quota, threshold and
  active ceiling refusals retain only aggregate counts; refused names create no entity row.
  Retired entities re-enter through admission without resetting first sighting.
- Planned all eligible sources fleet-wide, grouped sources by their own watermark window, shared
  one tick-wide search budget, and held each source's IPS pipeline lock across search and writes.
  Entities, metrics, buckets, watermarks and retirement use a fixed bulk-statement shape.
- **Watermark rule:** a source bucket is written only when its `TOTALS` cell is `COMPLETE` and
  every planned dimension was searched. A structurally unplanned dimension, such as `ACTION` for
  a profile without an action mapping, is permanently stored as `NOT_COLLECTED` with `NULL`
  facts/coverage and the watermark advances. A planned dimension whose outcome has
  `searched=False` is transient: the bucket is not written, the watermark stops at the last
  contiguous fully collected bucket, and the next tick re-collects it. `FAILED` and `REJECTED`
  were searched, so they keep the WAF precedent: their explicit state and `NULL` coverage are
  recorded and the watermark advances. Missing or non-`COMPLETE` totals still hold the watermark.
- A window's base plan is now preflighted against the remaining tick budget. If it does not fit,
  no search in that window starts. The collector skips that window but continues considering later
  windows, so one permanently oversized oldest window cannot starve sources whose plans fit the
  remaining budget. Split searches may still exhaust the budget after a window starts; the
  transient rule above prevents those partial results from advancing a watermark.
- A base plan larger than the entire per-tick budget produces a warning, a
  `budget_blocked_windows` report entry, and `budget_blocked_reason` in each affected watermark's
  collection metadata. The chosen remedy is explicit configuration: raise
  `search_cadence_max_searches_per_tick` to the reported required count before the next tick. This
  preserves atomic dimension coverage instead of staging unsafe partial buckets.
- Coverage is nullable when unmeasured and clamped to 1.0 when searches taken at different times
  produce a ratio above one. `LOWER_BOUND`, maintenance and safe provenance propagate to storage.
- Added the global `IPS_COLLECTION` cadence claim before provider construction, a 60-second beat,
  and one bounded retention task.
- Measured **12 SQL statements** for both scale fixtures: 2 sources with 10 pre-existing entities,
  and 20 sources with 400 pre-existing entities. A deliberate per-source lookup changed these to
  14 and 32 respectively and was killed by the test.
- Added the approved frontend family type and copy. No frontend family-list or `FAMILY_INFO` key
  test required a change.

Break-it verification used the original 24 temporary mutants plus five review-round-3 mutants;
every effective mutant made its focused test fail and was then restored. The five new kills were:
allowing transient unsearched dimensions to persist, treating structurally unmapped `ACTION` as a
hold, bypassing remaining-budget window preflight, suppressing the oversized-plan report entry,
and making a searched `FAILED` dimension hold the watermark. The original kills were:
profile-validity bypass, missing totals written as zero, missing coverage written as zero, lost
lower-bound state, lost maintenance state, merged unequal watermark windows, reset tick budget,
bypassed pipeline lock, disabled stale-metric replacement, inclusive admission threshold, excess
quota, ignored active ceiling, removed deterministic tie-break, persisted refused entities,
suppressed reactivation, disabled active retirement, added per-source SQL, bypassed the
collection-enabled exit, bypassed the early-tick exit, removed the atomic claim predicate,
bypassed the retention-enabled exit, skipped metric retention, skipped the 0018 table drop, and
removed coverage clamping.
