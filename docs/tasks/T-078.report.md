## 2. What I did

- `validation_fields` is built from `report["fields"]`, keeping only `dict` entries (the WAF
  pattern) and taking `field`, `status`, `detail` from each; `validation_reasons` keeps only the
  string items of `report["reasons"]`. Non-list containers (`fields: 5`, missing keys) fall back to
  an empty list rather than raising, and a missing report (`{}` / `None`) yields two empty lists.
- Nothing else leaves the report: no `discovered_values`, `populated_events`, `reference`,
  `queries` or any other key. The report is shown as stored; `validated_profile_version` and
  `profile_version` on the row stay the row's own values, so a client can tell that the report
  describes an older version.
- Everything is read from the profile already loaded by the list's single joined `SELECT`.

Acceptance criteria, one by one:

| Criterion | Test |
| --- | --- |
| each field's `field`/`status`/`detail` and the report's `reasons` on the row | `test_sources_row_carries_the_field_results_and_the_report_reasons` (also pins `(validated_profile_version, profile_version) == (1, 2)`, i.e. an older report shown as stored) |
| no report yet → both lists empty | `test_sources_row_without_a_report_has_two_empty_lists` (`{}` over HTTP) and `test_source_status_without_any_report_has_two_empty_lists` (a transient profile with `validation_report=None`) |
| non-dict field item / non-string reason item skipped, rest kept | `test_sources_row_skips_report_items_that_are_not_dicts_or_strings` |
| no `discovered_values` anywhere in the row JSON | `test_sources_row_carries_no_discovered_values` (also asserts the raw IP `203.0.113.9` is absent and pins the row's exact 22-key shape) |
| same statement count for two and for five profiles | `test_sources_list_statement_count_is_the_same_for_two_and_five` |

Statement counting reuses `recorded_statements` from
`tests/integration/test_rule_match_collection.py` (as `tests/integration/test_rule_statistics.py`
does). It listens on `session.bind.sync_engine`, and the TestClient in this file builds its own
engine, so `client()` now exposes that engine on the returned client and the test opens an unused
session on it as the anchor. Measured count: **1** statement for two profiles and **1** for five —
identical to the count with `_source_status` reverted to its pre-task body (measured the same way),
so the change adds no SQL.

### Deliberate break checks (AGENTS.md §4)

Each break was introduced, the test run, the failure confirmed, then the code restored.

1. `validation_reasons=[]` (reasons never reach the row) →
   `test_sources_row_carries_the_field_results_and_the_report_reasons` **FAILED**
   (`assert [] == ['ACTION: MISSING (no QRadar field is mapped to the logical field)', ...]`,
   `1 failed, 13 deselected`).
2. removed `if isinstance(entry, dict)` from the field comprehension →
   `test_sources_row_skips_report_items_that_are_not_dicts_or_strings` **FAILED**
   (`AttributeError: 'str' object has no attribute 'get'`, `1 failed, 13 deselected`).
3. added `discovered_values` to `IpsFieldStatusOut` and filled it from the entry →
   `test_sources_row_carries_no_discovered_values` **FAILED**
   (`assert 'discovered_values' not in ... "203.0.113.9" ...`, `1 failed, 13 deselected`).

All three breaks were reverted; the final gates below ran against the restored code.
