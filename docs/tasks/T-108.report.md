The design answers all twelve questions of `docs/tasks/T-108.md` §"Questions the design must
answer", each in a marked section, with the decisions summarized as:

- **F.1** — threshold rules over the ten already-collected metrics (source `event_count`/EPS,
  fleet-class EPS, WAF endpoint requests + block/5xx/4xx ratios, IPS entity events, IPS source
  totals + blocked share); new enums and a new `custom_rule_breach` fingerprint (never
  `AnomalyType`); a DB-only 60 s evaluator with per-kind watermarks, bulk loaders (constant
  statements, ≤ 100 rules cap); alert lifecycle only, no fourth incident lifecycle, breaches kept
  out of `/anomalies`; preview as a replay over stored buckets with unmeasured buckets as gaps.
- **WAF admission (Q2)** — a rule pins an admitted `waf_endpoint` chosen at authoring; a
  not-admitted URI is rejected with the reason; retirement and a disabled family become visible
  runtime statuses (`SUBJECT_RETIRED`, `NOT_COLLECTED`), never silence.
- **Latency (Q3)** — worst case ≈ 1 h 13 min at default cadences, stated in the UI with "this is
  not a real-time correlation engine".
- **F.2** — the AQL editor on `/searches` (save as disabled stored version → preview = "Run now"
  on the stored draft → enable), the validator's reasons surfaced inline, caps (25 enabled
  searches, 5-minute cron floor, existing timeout/time-range/rows/concurrency), `search:write`
  stays admin-only, every version audited, plus a new 90-day `search_result_metric` retention.
- **Chart (Q8)** — per-`metric_key` time series, top-N table, single value; `PIE`/`HEATMAP` not
  offered; a new `chart.search_results` widget with every UR.5.4 state designed, and the same
  component on `/searches/[id]`.
