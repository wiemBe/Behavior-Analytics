## Doc / behaviour mismatches
1. OPERATIONS.md says `.qradar-dash/state.json` is "ignored by git" (git tarafindan yok sayilir); in the v0.1.1 checkout `git status` shows `?? .qradar-dash/` and .gitignore has only `.secrets/`. Not harmful on a server, but `git status` is dirty and the claim is wrong (or .gitignore is missing the entry).
2. Runbook names Docker Engine + Compose v2 "from Docker's RHEL repository" nowhere with commands (Kurulum has only useradd for the account); an operator on Rocky needs `dnf config-manager --add-repo https://download.docker.com/linux/rhel/docker-ce.repo` etc.
3. Runbook "useradd -m -G docker qdops" assumes the docker group exists first (it exists only after Docker is installed): order not stated.
4. `status` after rollback prints "Last upgrade backup: ... (age 0 min)" for a backup taken 4 minutes earlier (age appears computed wrongly or from a touched mtime).
5. `doctor` prints one watermark family as `***redacted***` in the failing-watermarks line (the name should be printable).
6. After a successful upgrade `state.json` keeps `previous_images` set (non-null); runbook's example shows it as data of the last upgrade, so consistent, but release notes/runbook never say it stays.
7. v0.1.0 install summary still says "Runbook docs/OPERATIONS.md (arrives with OPS-9)" (v0.1.0 script text; fixed in 0.1.1).
8. Runbook "Yeniden calistirma" example: the 0.1.1 notes tell to `git checkout v0.1.1` before `upgrade`; worked exactly as written, no mismatch.
9. First-run doctor on 0.1.1 shows `FAIL watermarks`/`errors_recent` because the stand-in console 404s everything but /system/about: stand-in artefact, not a defect.
