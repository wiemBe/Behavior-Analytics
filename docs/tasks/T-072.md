# Task T-072 — `instance_id` optional on `/waf/candidates` and `/ips/candidates` (live defect)

Read `AGENTS.md` at the repository root first. Follow §4: never weaken, skip or delete a test.

## The defect (found by T-053, confirmed by the orchestrator)

`GET /api/v1/waf/candidates` (T-042) declares `instance_id: uuid.UUID` as a **required** query
parameter. The "Add WAF source" picker (`frontend/src/app/admin/waf-sources/AddSourcePicker.tsx`)
calls it **without** `instance_id`. So on a live install the picker gets a 422 and can never list a
source. The frontend fixture did not enforce the parameter, so the tests missed it.
`GET /api/v1/ips/candidates` (T-049) has the same signature.

## The fix (backend only)

In `backend/app/api/routes/waf.py::list_waf_candidates` and
`backend/app/api/routes/ips.py::list_ips_candidates`:
- make the parameter `instance_id: uuid.UUID | None = Query(default=None)`;
- when it is `None`, resolve the default instance exactly as `backend/app/api/routes/rules.py::_resolve_instance`
  does (the first `QRadarInstance`). If there is no instance at all, return **404** with the detail
  `"no instance registered"`, as `GET /rules/statistics` does;
- when it is given, behave exactly as today.

Do not duplicate the helper a third time if a shared place exists. If none does, a small private
helper in each module, matching the `rules.py` one, is acceptable. Change nothing else in either
route.

## Tests

In `backend/tests/integration/test_waf_profile_admin.py` and
`backend/tests/integration/test_ips_profile_admin.py`, **add** new tests. Do not change existing
ones. For each route:
- without `instance_id`, it returns the default instance's candidates, with the same ordering as
  with the explicit id;
- without `instance_id` and with no instance registered, it returns 404 with that detail;
- with an explicit `instance_id`, it returns the same as before (an existing test may already
  cover this; then do not add a duplicate).

Break-it: restore the required parameter on one route, see the new test fail, then restore the fix.
