## 2. What I did

- **Provider:** AQL is the T-063 section 4 shape with a half-open `starttime` bound, `ORDER BY SUM(eventcount) DESC LIMIT n+1` and `_ariel_scope` padding. Type ids are validated ints, 1 to 100000, at most 32, bools refused. Bucket key and `logsourceid` guards are as in T-050a. Read-only.
- **Fold and admission:** sender text is sanitized (printable, stripped, 1 to 255). An invalid value counts as untracked, with its events. Admission reuses `app.waf.admission` (threshold, quota, ceiling, deterministic order). Tracked senders always pass. A refused sender is never stored by name, neither in `catchall_sender` nor in `top_senders`. The top list is bounded by `catchall_top_senders`. `LOWER_BOUND` propagates.
- **Collector:** one keyed search per tick per instance. Time is split first. One truncated bucket gives `LOWER_BOUND` with its top kept. `FAILED`, `REJECTED` and `NOT_COLLECTED` write no bucket. The watermark holds at the last contiguous measured bucket. The budget is `search_cadence_max_searches_per_tick`. A catch-all source with no rows gets a measured zero in a `COMPLETE` bucket and nothing in a `LOWER_BOUND` one.
- **Bootstrap and review:** first run gives `REVIEWED` (`reviewed_by = bootstrap`); later new senders are `NEW`. The alert (`NEW_CATCHALL_SENDER`, `LOW`, inventory class, own fingerprint, through `apply_bulk`) is raised only when the setting is on. Default is off (D-9).
- **SQL:** constant per run (bulk loads, chunked bulk upserts, one retire, one `events_24h` update). Pinned at 3 against 40 senders, before and after bootstrap. With alerts on, each new alert costs a bounded few statements because `AlertService.apply_bulk` inserts each new alert in its own savepoint (existing concurrency guard). That cost is bounded by the test (at most 4 per new sender).
- **Retention:** buckets older than `catchall_retention_days`; senders retired longer than that. Active and unretired senders are never deleted. Bounded batches, each committed.
- **API:**
  - `GET /senders` (filters `review_status`, `catchall_log_source_id`, literal `q`; paged; NEW first, then `events_24h` descending, unknown last).
  - `GET /buckets` (since and until required, timezone required, at most 7 days, 404 for an unknown source).
  - `POST /senders/{id}/review|dismiss` (`log_source:write`, audited with the principal as actor, idempotent, also resolves an open new-sender alert).
- **Migration** `0020`, `down_revision = "0017"` (`alembic heads` at start returned `0017`). The orchestrator re-chains it.
- **Guards broken on purpose** (mutation run, each restored, no `.bak` left). All mutations that were run were caught (about 47; the harness lived outside the repo). Two survived at first and I added tests for them (retire too early; one-statement bucket upsert). Mutations covered:
  - provider: LIMIT, window key guard, type-id guards, source guard, mock validation;
  - fold: printable, length, ledger, top bound, LOWER_BOUND flag, untracked events;
  - split driver: containment, split, budget;
  - collector: bootstrap in both directions, alert gate, watermark break, LOWER_BOUND zero, unmeasured skip, chunk sizes, retire cutoff, reactivation;
  - retention cutoffs; task slot gate; settings defaults;
  - API: permission, ordering, `nulls_last`, `%`/`_` escape, range bound, range inversion, 404, idempotence, audit action, `reviewed_by`, alert fingerprint.

## 4. Open points

1. **Conflicting existing test (not changed, per AGENTS.md section 4).** `test_migration_0013.py` asserts that `search_cadence` holds exactly four families at head (`PHASE_A_VOLUME`, `WAF_COLLECTION`, `ANOMALY_EXPLANATION`, `RULE_MATCH`). The spec requires a seeded `CATCHALL_SENDERS` row, so this test fails. The fix is one line: add `"CATCHALL_SENDERS"` to the expected set (T-050b or T-068 may add more at merge). The orchestrator decides. Alternative: drop the seed (the service treats a missing row as 1 h and restores it on first claim), but that contradicts the spec.
2. The mock has no true catch-all log source (no type 67 template), so by default it yields rows only for its type-212 source. Tests drive it with `catchall_script`. I did not add a mock template because it would change counts in other tests.
3. Rows of a QRadar log source that is not in the instance's inventory (or not of a catch-all type) are counted in the report (`unmapped_rows`) and are not stored.
4. After a long outage the collector catches up in batches of `cadence + collection_max_backfill_intervals` buckets from the watermark, as other collectors do. `last_seen_at` then follows bucket time, so a very old catch-up can retire a sender on the next run, and a later sighting reactivates it. Review state is never changed by that.
5. `events_24h` is a lower bound (sum over stored top lists), null when no top list names the sender. This follows the model docstring and the "unknown, never zero" rule.
6. Added the `search_cadence.py` one-line change (see section 1).
