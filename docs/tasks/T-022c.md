## The problem

Next-generation firewalls are multi-role: the same DSM carries firewall, IPS and threat logs.
The user runs **Cisco Firepower Threat Defense** and **Palo Alto** as IPS in production. Today the
built-in type rule 3 in `app/fleet/seed_rules.py` pins these DSMs to `FIREWALL`. Because a type
rule outranks a name rule, a site that names its source `…-ips-…` only gets a conflict, never IPS.

## Build

1. In `app/fleet/seed_rules.py`, remove these five DSM names from rule 3 (`suffix=3`):
   `Fortinet FortiGate Security Gateway`, `Palo Alto PA Series`, `Check Point`,
   `Cisco Firepower Threat Defense`, `Juniper SRX`.
   - Keep `Linux iptables Firewall`, `Netgate pfSense` and `Cisco ASA` in rule 3.
   - Keep the rule's id (`suffix=3`) unchanged, so the existing upsert in
     `app/fleet/service.py::ensure_seed_rules` updates the stored definition on existing installs.
   - Add a short comment above the rule that says why the multi-role DSMs are absent: the site's
     naming convention decides their class. Match the module's existing comment voice (see its
     docstring about catch-all DSMs).
   - Do not add any other rule, and do not change any other rule.
2. Update the existing classification name matrix in `tests/unit/test_fleet_classification.py`
   (the realistic-DSM-name guard test, about 62 names). For each of the five DSMs:
   - with a neutral source name (no class token), the expected class becomes `UNCLASSIFIED`;
   - add cases showing the name decides: e.g. `Palo Alto PA Series` + a name containing `ips`
     → `IPS`; `Cisco Firepower Threat Defense` + a name containing `fw` → `FIREWALL`.
   These pinned values change **because this spec changes them on purpose**. Change no other
   expectation. If any other expectation in any test changes outcome, stop and report it.
3. Add one integration test (in `tests/integration/test_fleet_inventory.py`) proving the upgrade
   path: a database whose stored rule 3 still has the old pattern, after `ensure_seed_rules`, holds
   the new pattern, and a source of type `Palo Alto PA Series` named `pa-ips-01` then classifies as
   `IPS` on the next classification run. Keep the rule's `enabled` flag as stored.
