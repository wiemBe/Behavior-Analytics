## Why

`IPS_BLOCK_RATIO_SHIFT` answers `INSUFFICIENT_DATA` ("no action property mapped") on the lab
because QRadar extracts no action value from the lab's vendor-native IPS syslog. On 2026-10-15
the user authorised the orchestrator to create the property **through the QRadar API**. This is
a one-off operator action on the **lab console**. The application stays read-only; nothing in
`backend/app/` changes.

The generator already varies the action (`tools/qradar_lab_loggen.py`, around line 1030):
- `pan_threat`: blocked = `drop`, `reset-client`, `reset-server`, `reset-both`, `block-ip`;
  otherwise `alert` or `allow`;
- `ftd_ips`: `Blocked`, `Would block`, `Allowed`.

Read `render_pan_threat` and the FTD renderer to see exactly where the value sits in each line.
