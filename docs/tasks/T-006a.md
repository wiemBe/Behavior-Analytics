## The problem

`app/waf/behavior.py` holds four pure detectors that nothing calls:
- `detect_block_ratio_spike`
- `detect_error_ratio_spike`
- `detect_client_error_ratio_spike`
- `detect_client_concentration_spike`

`app/waf/engine.py` registers only `WAF_REQUEST_RATE_SPIKE` in `WAF_DETECTOR_FUNCTIONS`.
`WafDetectionContext` (`app/waf/detector.py`) already has fields for them (`observation`,
`behavior`, `baselines`), but the engine never fills them.

A fifth detector, `detect_new_endpoint_access`, is **out of scope here**; it is task T-006b.

## What to build

In `app/waf/engine.py`:

1. **Register** the four detectors in `WAF_DETECTOR_FUNCTIONS`.

2. **Respect the enabling settings.** Each spec in `app.anomaly.capabilities.WAF_DETECTORS` names
   one: `waf_outcome_collection_enabled` or `waf_client_collection_enabled`.
   - A detector whose setting is off is not evaluated at all. That means no state rows, no
     cells loaded for it, no statements.
   - Both settings default to off. With defaults, the engine must behave exactly as it does today,
     and every existing test must pass unchanged.
   - Apply this filter to the default registry and to an injected `detectors=` mapping alike.

3. **Build the context** for B.2 detectors:
   - `observation=obs`.
   - `behavior`: a `WafBehaviorThresholds` (`app/waf/behavior.py`) built from settings:
     | threshold field | setting |
     |---|---|
     | `deviation_z` | `anomaly_deviation_threshold` |
     | `min_coverage` | `waf_min_endpoint_coverage` |
     | `mad_floor_ratio` | `baseline_mad_floor_ratio` |
     | `ratio_*` | `waf_ratio_*` |
     | `concentration_*` | `waf_concentration_*` |
     | `new_endpoint_*` | `waf_new_endpoint_*` |
     | `admission_min_requests` | `waf_min_admission_requests` |
   - `baselines`: every cell loaded for the endpoint, keyed by metric name.
   - `baseline`: the cell of the detector's own metric.

   Build the thresholds once per evaluation, not once per endpoint.

4. **Scope from the declared inputs.** For a spec that declares `inputs`, use
   `waf_input_scope(detector_type, obs)` instead of `waf_verdict_scope`. Keep the current path for
   `WAF_REQUEST_RATE_SPIKE`, so its behaviour is unchanged.

5. **Semantics, failing closed.** For a breakdown detector, compare the observation's breakdown
   identity with the cell's `metric_semantics`:
   - ratio detectors on ACTION read `obs.breakdowns.action_semantics`;
   - ratio detectors on RESPONSE_CODE read `response_code_semantics`;
   - concentration reads `client_semantics`.

   A `None` identity on either side, or a mismatch, sets `baseline_incompatibility`. Use
   `app.waf.semantics.semantics_incompatibility`, as the request-rate path does.

6. **Carry the cell fields.** `_cell` must carry `numerator_sum`, `denominator_sum` and
   `metric_semantics` into `WafBaselineCell`.

7. **Persistence.** Check that an incident opened by each new type persists and transitions
   through the existing `_apply_hysteresis`, `_create_incident` and `_touch` path. That includes
   its `extra` evidence and the deviation fields read from `facts`. Fix only what breaks.

8. **Cost.** The statements per evaluated bucket must stay constant: independent of the number of
   endpoints, and independent of how many detectors are enabled.
   - Cells for all enabled metrics come from the existing single query per weekday/hour.
   - States come from the existing single query.
   - Extend `tests/integration/test_waf_scale.py` to pin this with every B.2 setting on.

## The baseline-cell contract

Task T-005 is building the trainer in parallel. Do not touch `app/waf/baseline.py`; in your tests,
insert `WafEndpointBaseline` rows directly. A ratio cell looks like this:
- `metric_name` is one of `block_ratio`, `server_error_ratio`, `client_error_ratio`,
  `top1_client_share`.
- `metric_semantics` is the breakdown identity from `app.waf.semantics.breakdown_semantics`.
- `median`, `mad`, `p05` and `p95` are over per-bucket proportions.
- `numerator_sum` and `denominator_sum` are pooled over the training buckets.

## Tests to add

Integration tests in a new file. With outcome and client collection enabled:
1. A bucket with exact breakdowns and a reliable ratio cell, whose proportion clears every guard,
   opens an incident after `anomaly_open_after_intervals`. Its evidence `extra` is persisted.
2. With the breakdown `NOT_COLLECTED` or `FAILED`, the verdict is `INSUFFICIENT_DATA`, and the
   state does not advance toward open.
3. A lower-bound numerator (uncertain values > 0) over an exact denominator can open an incident
   but is never judged healthy.
4. A semantics mismatch between bucket and cell gives `INSUFFICIENT_DATA`.
5. With the settings off, no `WafDetectorState` rows are created for the B.2 types.
6. The concentration detector opens on a top-client share rise.
