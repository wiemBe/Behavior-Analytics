## 2. What I did
- Window ends at the last closed bucket; steps are anchored at `window_start = end - window`. Step map: `1h` = bucket, `24h` = 300 s, `7d` = 3600 s; fallback to the bucket width when it does not divide.
- Statements: sources (monitored, non-`QRADAR_INTERNAL`), metrics grouped by class and step index (`COUNT(*) FILTER COMPLETE`, complete events), reliable `average_eps` baselines. `group_by=none` is folded from the same per-class rows, so both modes cost 3 statements.
- Step is summed only when `cells_complete == cells_expected > 0`; otherwise `events`/`eps` are null. Every step is present. `expected_eps` is the sum of per-source medians, null unless every in-scope source has a reliable cell; no p05/p95 or band anywhere.
- Source added during the window: it has no rows before it existed, so those steps are null (rule 8 kept; no special casing). A source disabled or unmonitored since is excluded from sources, cells and sums.
- Choices the spec did not rule (please confirm):
  1. Only metric rows with `bucket_seconds == collection_interval_seconds` count as cells. A row of another width is not a cell of the grid (it would otherwise inflate `cells_complete`).
  2. The 7d window ends at a 5-minute boundary, so its 1-hour steps usually straddle two (weekday, hour) baseline cells (e.g. 10:05-11:05). `expected_eps` is then the overlap-weighted mean of the touched cells, and is null if any touched cell is not reliable for any source. When a step is aligned to the hour this equals the single cell the spec describes. The alternative (cell of `step_start` only) would mislabel half the step.
  3. `coverage.steps_total` = steps x series (0 when there is no series).
- Cross-module import: `series.py` imports `EPS_METRIC` and the private `_class_of` from `app/fleet/summary.py` (same pattern, no edit to that file).

- `build_fleet_eps_series` floors `now` (the last closed bucket the route passes) to `step_seconds`; `window_start = window_end - window`. Up to one step minus one bucket of the newest data is left out; stated in the route docstring and the `window_end` field comment.
