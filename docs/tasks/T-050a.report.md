## 2. What I did

- **Plan:** `plan_searches` groups per dimension by the exact references the dimension reads. TOTALS is one group of all sources. ACTION covers only sources with an action field. PORTS add PROTOCOL only when mapped. Groups are chunked into consecutive sorted runs of `max_sources_per_search`. Order is dimension, sorted reference tuple, source id. A custom reference sorts before a normalized one (`CUSTOM_PROPERTY` < `NORMALIZED`).
- **AQL:** the §D.5 table. Every IP filter and the port, protocol and signature filters come from `_ips_population_condition`; there is no `LIKE` and no `CASE`. A custom property named `qid` is passed to the helper with an empty name, so it gets `IS NOT NULL`, not `> 0`. Protocol is grouped but not filtered, so protocol 255 stays a row and folds to `unknown`. `QIDNAME` appears only for a normalized `qid`. Fan-out also applies the source-IP population filter (the spec only names the port filter); that is consistent with the SOURCE_IP dimension.
- **Provider guards:** window via `validate_bucketed_metric_window`; source count against `ips_max_sources_per_search`; every reference re-validated (allowlist or `PROPERTY_NAME_PATTERN`), including unused ones. Row guards: key outside the window, non-integer key, `logsourceid` outside the set, malformed volume. They raise a constant-message `ProviderError`. Truncation is `rows > cap`, where `cap = min(max_rows, page_size * max_pages)`; the first `cap` rows are kept.
- **Driver:** per the spec. Extra fail-closed checks: a result with rows outside its own sources or buckets, or more rows than `max_rows`, marks the cells `FAILED`. `IpsCellOutcome.__post_init__` refuses rows on a non-measured state, so a zero can only come from a `COMPLETE` cell.
- **Folds:** per the spec. An unmeasured outcome folds to `None`, never to a zero. `IpsTotalsFact.measurement` has no default, so exactness is never assumed.
- **Equivalence:** `TestEquivalence.test_split_equals_alone` runs 12 random trials per dimension (random sources, windows, row caps and forced wide truncation). It checks that the split path equals every `(source, bucket)` run alone, apart from provenance. It also asserts the comparison is not vacuous (a split happened; `LOWER_BOUND` occurred).

- Fan-out under `LOWER_BOUND`: the rows are ordered by the distinct count, so the maximum is in fact exact. The fold still carries `LOWER_BOUND` (conservative), as the spec asks for a measurement on every fact.
- `coverage` is not clamped at 1.0; the dimension and totals searches run at different moments and a ratio above 1 is possible. T-050b decides.
- The mock's events are synthetic; its custom `ACTION` and `SIGNATURE` values do not depend on the property name.
- `app.ips.keyed_rows` imports the private `_integer_bucket_key` from `app.collectors.bucketed_metrics` (the WAF bucketed fold does the same).
