## 5. Defects
None blocking found. Observations for the orchestrator (low severity, none verified as wrong against the spec):
1. After the seed run the rule's `last_status` stays NULL until the first judged bucket (the API shows null status for a fresh enabled rule).
2. `consecutive_under` accumulates while the rule is OK (5, 6, 7 in the baseline). It is reset by a breaching bucket and only matters with a breach, so no effect, but the API exposes it.
3. Preview versus live disagree after a late-collected bucket (see above); a UI note may be warranted.
4. `python -I` ignores PYTHONPATH and the venv's editable install points to the main checkout; the task text's run recipe imports the main tree unless the script inserts the worktree path (done here, verified `app.__file__`).
5. Dry-run with long phase durations is paced in real time (a 2700 s dry run does not return).
Note: the preview calls in this run report `alerting_mode: shadow` because my preview script did not export the alerting flag; that is the harness, not the API.
