## Known defects to fix

Each was observed by the orchestrator in `docs/screenshots/ui/anomaly-detail-1440x900.png` or in
the code.

1. **`VolumeChart.tsx`.**
   - **Markers.** The observed series draws a marker on every point (`showSymbol: true`,
     `symbolSize: 5`), so a dense series reads as a beaded string. Draw a clean line. Show a
     marker only on hover, or on a bucket that needs one (for example a single isolated
     measured point between gaps).
   - **Expected range.** It is drawn as three green lines (expected, low, high). Draw it as one
     band (`areaStyle` between low and high, for example a stacked pair) with the expected
     median as a single subtle line.
   - **Colour.** Green is a status colour. `tokens.css` reserves status colours for status, so the
     expected range must not be green. Use a neutral or `info` family token.
   - **Literals.** The chart hard-codes hex literals (`#263048`, `#4f8cff`, `#3fb950`, `#8b98b0`,
     `#1a2336`, …). Every colour must come from a token. ECharts cannot read CSS variables
     directly, so read them once via `getComputedStyle(document.documentElement)` in a small
     shared helper, or define a typed chart palette module whose values are documented as
     mirroring `tokens.css`, with a unit test asserting they match. Pick one, and say which in
     your report.
   - **Legend.** It uses the library's default line-with-circle symbols. Make it compact and
     match the series as drawn.
   - **Axes.** The y axis must carry its unit, and the time axis must state its timezone.
2. **Incident header and KPI row** (`/anomalies/[id]`).
   - **Title.** A long source name becomes a two-line, roughly 30 px title. Set the source name at
     a sane size, wrap it safely (guidelines §9), and keep the incident's identity line (type,
     state, severity, time range) visually primary.
   - **KPI row.** Four identical cards (Observed / Expected / Deviation / Duration) are the
     "row of identical KPI cards" pattern that §3a bans. Replace it with one compact
     comparison block: observed vs expected with the unit, the deviation as a ratio and as an
     absolute delta, and the duration. Keep it dense, aligned, with tabular figures. If you keep
     separate cells, they must differ in weight according to importance.
   - **Confidence.** It floats as a bare "Confidence 0.42" line. Integrate it into that block,
     with a label that says what it means.
3. **Audit every behavioral route against §3a and the guidelines,** and fix what you find within
   these routes and their shared components. Typical findings:
   - copy that restates a heading;
   - an inconsistent date or time format, or one with no timezone;
   - a missing unit;
   - a number that is not tabular;
   - a missing loading, empty or error state;
   - an inline style;
   - a literal colour or spacing value.

**Do not change product semantics:**
- the evidence-honesty states (guidelines §4 and §6) must render exactly as they mean today;
- deterministic summary text stays deterministic;
- no prohibited language (guidelines §7).

When a guideline itself seems wrong, report it rather than changing the guideline.
