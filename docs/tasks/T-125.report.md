of both parts. Nearly all pointed at what the text claimed. The corrections:

1. **G.3 allowlist was garbled and self-contradictory.** It wrote a constant with `eventdirection`,
   then said v1 ships `username` and `category`, while excluding numeric fields in the same
   paragraph. `category` is numeric. Now: `username` only; `event_name` is a v1.1 candidate (Q9).
2. **"Validated live" claims had no source.** G.1.3 said the Phase A `username` grouping "was
   validated live (Phase A section 11)"; that section holds no such record. G.1.4 called the
   `devicetype` filter "live-proven"; no document records a live run. Both are now
   "[verify on the lab]" (L3, L6).
3. **The `!= '::1'` precedent was over-read.** It is a literal on an IP-typed field. A string
   equality, `IN`, and quote escaping are unproven (L4). Added `PW_PINNED_VALUE_PATTERN`: pins with a
   quote, backslash or control character are rejected, not escaped (rule 4).
4. **G.6 grouped `logsourceid` into every search.** That multiplies rows by the member count for no
   output and forced a per-source split. Removed; truncation now splits by time, and at one bucket
   stores `LOWER_BOUND`. Chunk sums are exact only when every chunk was whole.
5. **G.5 refused a save when no type in scope defined the property.** That contradicts "the catalog
   is a suggestion, never a gate", and the catalog only lists enabled type-wide expressions
   (`qradar_rest.py:567-575,602-606`), so a per-source property would be wrongly refused. Now a
   warning; the preview decides. Added `name_allowed` handling. `NOT_APPLICABLE` now needs
   `total_events > 0`.
6. **G.4 membership churn and staleness.** Groups are a tree (`parent_qradar_id`); descendants are
   now walked, and whether QRadar lists parents in `group_ids` is L2. Staleness is now the group row's
   `synced_at`, because `inventory_sync.py:73-75` swallows a failed group listing and never deletes a
   group. Churn: a grace window of verdict-free, untrained buckets instead of a vague "relearn".
7. **G.6 "first run judges nothing" cited SC.6 lines that say Phase A evaluates the latest bucket.**
   Reworded: seed at the latest closed bucket, no replay, no backfill.
8. **G.6 preview** invented `/preview/draft` and claimed a "rate-limited" precedent without a cite.
   Now one `POST /{id}/preview` on the stored watch (the browser never sends AQL), limiter cited
   (`core/rate_limit.py:1-8`), needs write plus values permission.
9. **Citations fixed:** `fleet/service.py` 233,248 to 232-253; a "36 statements" claim now says it is a database-only
   measurement.

Kept as written: the dedicated-collector decision (not F.2), the three-search design, coverage and

Findings worth the orchestrator's attention (code facts the design rests on):
- No API lists log-source types or groups today; `PropertyCatalogService.catalog` filters by one
  type id. PW-5 adds both.
- `custom_rules/engine.py:643-652` `_family_collected` returns "collected" for any kind it does not
  name; an unhandled `PW_VALUE` would be evaluated with the family off. PW-6 adds a branch and a
  guard test.
- Existing F.1 foreign keys to `waf_endpoint`/`ips_entity` are `ON DELETE CASCADE`; the new one is
  `RESTRICT`, and a watch delete or version bump is refused while a rule pins a value.
- A stored top-N of a `username` field can hold a mistyped password; admission (3 events in a bucket)
  is what bounds it. This drives Q1.
