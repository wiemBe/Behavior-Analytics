## What is wrong today

There are two problems:
- `RuleMatchCollector` runs **one Ariel search per window**. The window is
  `rule_match_window_seconds`, default 1 h.
- It collects at most `rule_match_max_windows_per_run` windows per run, default 6.

So at an 8-hour cadence, 8 windows accrue per tick, but only 6 are collected. The watermark falls
behind until windows pass the catch-up horizon and are recorded as FAILED.

## Build

### 1. Provider: one keyed search for many windows

Add `get_rule_matches_windowed(window_start, window_end, *, window_seconds, max_rows)` to the
provider interface. Implement it in the REST provider and the mock. It is read-only.

**REST AQL:** today's `get_rule_matches` query with these additions:
- `starttime / {window_ms} AS "k"` in `SELECT`;
- `GROUP BY creEventList, starttime / {window_ms}`;
- `ORDER BY COUNT(*) DESC LIMIT {max_rows + 1}`.

Keep the half-open `WHERE` and `START`/`STOP`.

**Return:** one `RuleMatchBatch` per window, keyed by window start, plus a whole-search
`truncated` flag. Truncated means more than `max_rows` raw rows.

**Fold:**
- It is a **pure function** in `app/rules/matches.py`, beside the existing fold.
- A `k` outside the window, or a non-integer `k`, fails the whole search, raising the provider's
  existing error type.
- Malformed-row handling must match `parse_rule_match_rows`.

**Validation:** the window must be a whole number of windows, aligned exactly as
`floor_to_window` aligns them. Reject anything else.

**Mock:** its per-window output must equal calling its `get_rule_matches` once per window.

### 2. Collector: one search per tick, split on truncation

**Windows per run:**
- The number of windows `RuleMatchCollector.collect` may collect per run becomes
  `cadence_windows + rule_match_max_windows_per_run`.
- Here `cadence_windows = ceil(cadence_seconds / rule_match_window_seconds)`, with the cadence
  read through `SearchCadenceService.get(SearchFamily.RULE_MATCH)`.
- So `rule_match_max_windows_per_run` becomes the backfill **beyond** one cadence (design
  §SC.5.2). Update its comment in `config.py`; that is a comment-only edit.

**The search:**
- Collect those windows with **one** windowed search, with `max_rows = rule_match_max_rows`.
- **If it is truncated, keep nothing from it.** Split into two halves of whole windows and search
  each, recursively.
- **The single-window base case is today's `get_rule_matches` call**, with today's TRUNCATED
  semantics unchanged: top rows kept, status TRUNCATED, `row_cap` recorded. A single window
  never splits further.
- The number of searches per run is bounded by the split tree, at most `2n - 1` for `n` windows.
  No new cap is needed. State this bound in a comment.

**Keep every T-025 and T-025b guarantee:**
- every attempted window leaves a `rule_match_window` row;
- a provider failure writes FAILED and **no** rows;
- bounded attempts, then skip;
- the catch-up horizon with its bulk skip;
- a failed retry never downgrades COMPLETE;
- idempotent re-collection, with constant statements per window.

**Failure attribution:**
- A failed multi-window search must not mark windows FAILED that a later split would have
  answered. Split first.
- Attribute a provider failure the way today's loop does. The windows of the failed search
  count one attempt each.
- Make the rule explicit in a docstring, and pin it with a test.

**The equivalence bar (design §SC.5.4).** For any run, the `rule_match_metric` and
`rule_match_window` rows this path writes must equal, column for column, what the old
per-window path writes. Only `collected_at` and `duration_ms` may differ, and `query_version`
if you bump it. Prove it with a test that runs both paths over the mock, with at least 8 windows
and at least one empty window.
