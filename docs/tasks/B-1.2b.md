# Task B-1.2b — record when the QRadar instance was health-checked, and its failure

Read `AGENTS.md` at the repository root first and follow it exactly. In particular rule 1:
read-only against QRadar; rule 5: no secret reaches an API response; and §4: never weaken a test.

This task is small. B-1.2 added `instance_last_health_check_at` to `GET /overview` for the top bar.
Its report found that **nothing writes `qradar_instance.last_health_check_at`**, so the field is
always `null`. Worse, `instance.status` is set only when inventory sync **succeeds**
(`InventorySyncService.sync` in `backend/app/services/inventory_sync.py`). If QRadar becomes
unreachable, `get_instance_info()` raises, `LogSourceCollector.sync` catches the `ProviderError`,
and the instance keeps saying `HEALTHY` indefinitely. That breaks AGENTS.md rule 8 (fail closed).

## Build

In `backend/app/services/inventory_sync.py`, `InventorySyncService.sync`:
1. After `get_instance_info()` returns, set `instance.last_health_check_at = now`, where `now` is
   the service's `_clock()` read once at the start of `sync`. Set `instance.last_error = None`.
   Set `status` as today: `HEALTHY` if reachable, else `UNREACHABLE`.
2. If `get_instance_info()` raises a `ProviderError`, then before re-raising:
   - set `instance.status = InstanceStatus.UNREACHABLE`;
   - set `instance.last_health_check_at = now`;
   - set `instance.last_error` to a sanitized text: the exception class name and its message,
     truncated to 512 characters. `ProviderError` text comes from this codebase's own vocabulary;
     see `sanitized_error` in `app/services/waf_pipeline.py` for the rule. Reuse that function if
     importing it creates no cycle; otherwise apply the same rule.
   - **Re-raise the same exception**, so `LogSourceCollector` keeps its failure handling, report
     and watermark behaviour exactly as today.
   - Make sure the instance change is flushed with the collector's session, which flushes on
     that path, so it is committed with the watermark update. If it is not, say so in the report
     and explain how you made it persist.
3. Any other exception (not `ProviderError`) is not caught here; the behaviour is unchanged.

`last_error` is **never** returned by any API. B-1.2's test pins that for `/overview`.

## Tests

In `backend/tests/integration/`, in the existing inventory-sync or log-source collector test
file (find it with `grep -ln "InventorySyncService\|LogSourceCollector" backend/tests/integration/*.py`):
- a successful sync stamps `last_health_check_at` with the injected clock's time and clears
  `last_error`;
- `reachable=False` sets `UNREACHABLE` and stamps the time;
- `get_instance_info` raising a `ProviderError` sets `UNREACHABLE`, stamps the time and sets a
  sanitized `last_error` (class plus message, at most 512 characters). The collector still
  reports `partial_failure`, does not advance its watermark, and the instance change is
  persisted after the session commits;
- after a failure, a later success restores `HEALTHY` and clears `last_error`.

Use the mock provider, or a stub that raises, as the existing tests do. Break the stamping on
purpose, confirm a test fails, and restore it (AGENTS.md §4).
