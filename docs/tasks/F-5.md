## Build (§F.8.1, §F.12 "The AQL editor")

1. **`/searches/new`**: AQL text, the seven cron presets of `docs/SEARCH-CADENCE.md` (5 min …
   8 h; reuse `ScheduleControl` / `ScheduleLabel` where they fit), threshold with operator and
   severity, the guardrails (window, rows, timeout, within the platform caps), and
   `visualization_type`. **Save** creates the search with `enabled=false`.
2. **Edit on `/searches/[id]`**: the same form for the stored search. An existing cron that is no
   preset shows as **Custom** and is sent back verbatim (never rewritten). A changed query mints
   a version; show the version diff in the existing code panel (code is text, never markup).
3. **Validation feedback**: a 422 `reasons` list renders inline under the editor as a list, each
   reason as sent, never paraphrased; the cron-floor 422 string renders beside the schedule
   control; the 409 cap message names the limit and says what to do (disable another search).
4. **Preview = Run now** on the stored draft (`POST /searches/{id}/run`, `search:execute`), then
   the run's result and status on the detail page with its honesty states (failed, truncated,
   empty, never run).
5. **Enable / disable** with the cap's 409 handled.
6. **Permissions**: without `search:write` the editor is hidden and the page says which roles can
   grant it (`admin`, and the new `detection_engineer` role, D-17). Read-only viewing stays.
7. **The latency statement** of §F.12, once on the editor.
8. Navigation: the entry point is the existing Searches page (Operations); add a "New search"
   action there for callers who may write. No new navigation entry.

Not in this task: the result-chart widget (F-7), custom rules (F-6), any backend change.
