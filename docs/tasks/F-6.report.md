## 2. What I did

- Added `/custom-rules`, `/custom-rules/new` and `/custom-rules/[id]` using the existing shell,
  `PageHeader`, table scroller, form patterns, ECharts wrapper and design tokens.
- The list answers which rules are breaching or not being judged. It carries each required status
  and reason, UTC evaluation time, evaluation-off and shadow notices, the collection-latency
  statement, and a writer-only New rule action.
- The editor filters catalog metrics by subject kind, shows units and honesty notes, searches
  existing sources, consumes all pages of admitted WAF/IPS inventories, explains empty admission,
  and sends debounced, non-persisting previews. Creates and optimistic PATCHes render exact 422
  reasons, the configured cap/remedy, and a named version conflict with reload instead of overwrite.
- The rule page shows the stored preview, active breach and history, shadow/alerting behavior,
  subject investigation link, writer actions, and explicit delete/open-alert consequences.
- The chart keeps `NOT_MEASURED` values as unbridged gaps, uses diamonds and “at least” for lower
  bounds, labels the threshold with its unit, shades breach and maintenance ranges, states the
  measurement counts and majority condition, carries UTC on time, and provides a text alternative.
  Operator/QRadar labels in tooltip HTML pass through `echarts.format.encodeHTML`.
- Readers retain all read views while write UI is hidden and the granting roles are named. A denied
  `read:custom_rules` response renders the forbidden state rather than a generic error.
- Responsive fixture captures showed a clear operational hierarchy, readable local table scrolling
  at 1024 px, a usable side-by-side editor at wider sizes, a focused preview at 1024 px, explicit
  admission and validation failures, and honest lower-bound/retired/shadow states. Every capture
  reported document scroll width equal to client width; there was no page-level horizontal overflow.
