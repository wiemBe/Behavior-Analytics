# Task T-088 — triage the frontend `npm audit` findings (read-only)

Read `AGENTS.md` at the repository root first. **Change no repository file.** This task produces a
report only. Run no install, `npm audit fix` or upgrade.

## Why

`npm audit` in `frontend/` reports 22 findings: 6 moderate, 13 high, 3 critical. The counts are
the same on `main` and on `feat/phase-ce`. Nobody has triaged them. Before any upgrade task, the
orchestrator needs to know what they are and whether they matter for this application.

The application:
- an on-premises Next.js app, built with `npm run build` and served by `next start` behind a
  proxy;
- used by authenticated SOC analysts;
- no user uploads, and no server actions that take untrusted input beyond query parameters.

## Do

From `/home/efe/Documents/QRadar-Dash/frontend`, with `~/.local/node/bin` on `PATH`:
1. `npm audit --json > /home/efe/Documents/QRadar-Dash-work/t088/audit.json`. Also run
   `npm audit --omit=dev --json` to its own file.
2. `npm ls <package>` for each affected package, to show the dependency path.

Then, for **each advisory**, give:
- the package and installed version;
- the advisory id and title, and its severity;
- whether it is direct or transitive, and through which direct dependency;
- whether it is **runtime** (in the production server or the browser bundle) or **dev/build
  only** (test, lint or build tooling);
- the first fixed version, and whether reaching it needs a **major** upgrade of a direct
  dependency;
- whether the vulnerable code path is reachable in this application. Say why: for example, a
  Next.js image-optimizer advisory matters only if `next/image` with remote patterns is used, so
  grep `src/` and `next.config.*` to check. When you are not sure, say so.

End with a short **recommendation**:
- what to upgrade now, in one small task;
- what needs a planned major upgrade;
- what is dev-only and low priority.
