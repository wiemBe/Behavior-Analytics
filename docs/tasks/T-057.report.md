## 2. What I did

Unified list: `GET /anomalies` now takes `subject_kind` and `waf_endpoint_id`; `anomaly_type` accepts either enum. Phase A and WAF rows come from one `UNION ALL` ordered by `detected_at desc, id desc` (the id tiebreak is new, so a page boundary inside a tie is stable). Log-source name and endpoint identity are joined inside the branches, so there is no resolution query: a list request is exactly 2 statements (count + page) at any size. `virtual_host_available` = the endpoint has a stored host OR the source's profile maps a virtual host property.

Detail: `GET /anomalies/{id}` tries Phase A, then WAF (404 if neither). WAF detail: transitions from `waf_anomaly_transition`, `detection` = `WafDetectionDetailOut` built by named keys only (no `queries`, contributors, entity block, source IPs). `explanation_package` is null for WAF (not faked). `observed_measurement` (EXACT/LOWER_BOUND) is exposed so "at least n" can be rendered; it is null for Phase A.

Behavior routes (all GET, `read:anomalies` via the router, 404 on unknown id, `limit` clamped to `api_max_page_size`, `_validate_range` on every route that takes a time range): `/behavior/waf/sources`, `/sources/{id}` (validation report counts only), `/sources/{id}/endpoints`, `/endpoints/{id}/metrics`, `/endpoints/{id}/baselines`. Each returns `{items,total,limit,offset}`.

Fail-closed choices: endpoint `state` is the worst detector state from `waf_detector_state`, with INSUFFICIENT_DATA ranked above NORMAL; no detector row gives `null`. Admission-overflow sums are `null` when no bucket was collected in range. A metric row with no source bucket record reports `request_count_measurement`, `in_maintenance` and the breakdown statuses as `null`. The metric/bucket sparse absence is not synthesized as zero.
