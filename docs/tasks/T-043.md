## Build

1. **Provider capability and method.**
   - `app/providers/base.py`: a new `ProviderCapability.CUSTOM_PROPERTY_CATALOG`, and
     `async def list_custom_properties(self, *, log_source_type_id: int | None = None)
     -> list[CustomPropertyDTO]` following the `list_log_source_groups` pattern (require the
     capability, else `CapabilityNotSupportedError`). Read-only.
   - `app/providers/dto.py`: `CustomPropertyDTO` exactly as T-041 recommends (`qradar_id`,
     `identifier`, `name`, `property_type`, `use_for_rule_engine`, `auto_discovered`,
     `log_source_type_ids: tuple[int, ...]`, `name_allowed`). **No** regex, payload,
     format_string, capture_group or expression field — not even optional.
   - `app/providers/qradar_rest.py`: two paginated GETs through the existing `_paginate`, both with
     `fields=` (never without):
     `config/event_sources/custom_properties/regex_properties`
     (`fields=id,identifier,name,property_type,use_for_rule_engine,auto_discovered`) and
     `config/event_sources/custom_properties/property_expressions`
     (`fields=regex_property_identifier,log_source_type_id,log_source_id,enabled`, plus
     `filter=log_source_type_id=<n>` when a type is given). Join on `identifier` in memory; count
     only enabled expressions with `log_source_id == -1`; one DTO per property; type ids sorted and
     de-duplicated; `name_allowed` from `PROPERTY_NAME_PATTERN`. Add the capability to the REST
     provider's supported set. Pick the right `EndpointCategory` from the existing ones.
   - `app/providers/mock.py`: a fixed, realistic catalog that includes the T-041 lab shape: on type
     212 `HTTP_Method`, `URL`, `WAF_Action`, `WAF_ResponseCode`, `WAF_USERAGENT`; `WAF_URL` only on
     type 232; `IPS_Action` on type 2; one property with no expression; one name that fails the
     pattern (e.g. `Bad.Name(1)`).
   - `app/providers/qradar_mcp.py`: **does not** gain the capability.
2. **Service** `app/services/property_catalog.py`: per-instance cache of the whole slim joined list
   (TTL from a new setting `qradar_property_catalog_ttl_seconds`, default 600, `ge=60`,
   `le=86400`); `refresh=True` bypasses it. For a log source, compute `applies_to_source_type`
   (true / false / null when the source's `type_id` is unknown) and sort as §FM.6 says.
   - Unsupported capability, `ProviderError`, or any failure → `status = "UNAVAILABLE"` with a
     short, safe `detail` (class name and a fixed sentence; never a response body, header, token or
     console address). A failure is not cached.
   - The cache is process-local (a dict keyed by instance id with a timestamp), guarded for
     concurrent coroutines; keep it simple and testable with an injectable clock.
3. **Route** in a new module `app/api/routes/waf_catalog.py`:
   `GET /waf/log-sources/{log_source_id}/property-catalog?refresh=false` → `PropertyCatalogOut`
   (new schema module `app/schemas/property_catalog.py`). 404 for an unknown log source. Include it
   in `app/api/router.py` with `dependencies=[Depends(requires(PERM_WAF_ADMIN))]`, next to the WAF
   router, with a one-line comment. The provider is built for the log source's instance the same
   way other routes or the WAF CLI build one; close it after use.
