   - `rows`: `(qradar_rule_id: int, records: int, events: int)`;
   - `truncated`;
   - the `query_version` / AQL identity.

   Implement it:
   - **REST:** the §E.2 AQL with explicit `START`/`STOP`, run through the existing Ariel lifecycle
     and helpers. Follow `get_log_source_metrics`, including its START/STOP and `eventcount`
     lessons. Store the AQL as a versioned constant, never built from input other than the
     validated window bounds and the integer cap. Parse defensively:
     - a non-integer or missing id row is dropped and counted;
     - a null id row (events that matched nothing) is excluded;
     - `truncated` is `len(rows) >= max_rows`.
   - **Mock:** deterministic rows that cover rules, building blocks and an unknown id.
   - **MCP:** unsupported.
2. **Migration `0012` and models:** `rule_match_metric` (hypertable) and `rule_match_window`,
   exactly as §E.2. Follow the transient-default convention (see migrations `0004` and `0010`).

     Treat an unknown or `None` type as `NOT_MEASURED`.
   - A fold from `RuleMatchBatch` plus the id→rule map to rows to write and a window record.
     Count the unknown ids.
4. **Collector `app/collectors/rule_match_collector.py`.**
   - Advisory lock and watermark, like the other collectors.
   - Window-aligned, with a settle lag (setting).
   - Catches up at most N windows per run (setting).
   - One Ariel search per window.
   - A bulk upsert of the rows, with a constant number of statements per window.
   - A `rule_match_window` row written with COMPLETE, TRUNCATED or FAILED.
   - A provider failure writes a FAILED window and never zero rows.

   - **Other types:** unchanged.

   - Keep the fail-closed contract.
   - Load the windows and sums in bulk: no query per rule.

  - a COMPLETE window writes sparse rows and a window record;

  - re-collection is idempotent;
  - catch-up is bounded;
  - a constant statement count at 50 versus 1,000 matched rules.

  - a COMMON rule absent is **not** `NEVER_OBSERVED`;
