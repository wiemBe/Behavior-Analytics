## 3. Decision
Reused `IPS_Action` (id 260); created no new regex property. Added one expression per lab type, with
regexes anchored on each DSM's action field (checked locally against 30 generated lines of each profile first):
- PAN THREAT CSV: the action is the field after the IP protocol, which follows the `flags` field `0x0`.
- FTD: `InlineResult:` carries `Blocked` / `Would block` / `Allowed` (not `AccessControlRuleAction`, which only says Block/Allow).

**Parse at ingest: not chosen.** The only API switch is `use_for_rule_engine` on the existing property (id 260),
which is an update of an existing QRadar object. The task forbids that. So the property is evaluated at search
time, which works (section 5) but is slower than ingest-time parsing. Open point for the user: a one-off
manual or approved update of `use_for_rule_engine` on id 260 would make it indexed at ingest.
