## 4. Open points

- **The WAF request-rate detector never stores a `caveat`.** `detect_request_rate_spike`
  (`app/waf/detector.py:275-339`, the `WAF_REQUEST_RATE_SPIKE` volume detector) builds its `extra`
  without a `caveat` key; only the ratio detectors (`app/waf/behavior.py:305/322/339`), client
  concentration (`:593`) and new-endpoint (`:717`) set one. So for the detector type this test
  seeds, `evidence.extra["caveat"]` is absent in production and the value asserted here exercises
  the *projection*, not a detector path. `app/` is out of scope (task item 4), so I did not change
  it. The `WafDetectionDetailOut.caveat` field is still correct and used by the other detector
  types.
- **Union serialization masks a missing projection assignment.** As noted in Gates, a `caveat=
  assignment removed from either projection is not observable at the HTTP boundary while the other
  union member still carries the field. A future key-set pin on the IPS projection (as the WAF one
  has) would close this.
- No IPS key-set pin existed, so there was no IPS key-set defect to fix; I only added the absent
  case, as the task allowed.
