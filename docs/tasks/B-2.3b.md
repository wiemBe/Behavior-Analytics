# Task B-2.3b — the anomaly histogram counts IPS anomalies

Read `AGENTS.md` at the repository root first and follow it exactly. Backend only: no frontend
file. The route stays `GET` and writes nothing.

## Why

B-2.3 built `GET /anomalies/histogram` over Phase A and WAF, and its spec promised "IPS joins
when task T-085 lands". T-085 (the IPS analyst read API) is now merged into this branch:
`GET /anomalies` lists IPS anomalies, and `AnomalyRepository._applicable_kinds` now takes a
required `ips_entity_id` and returns three flags `(phase_a, waf, ips)`. The histogram still calls
it the old way, so **the histogram is broken on this branch** (a `TypeError`) until this task is
done. Its population must again equal the list's: `total` from the histogram equals `total` from
`GET /anomalies` for the same `since`, `until` and `subject_kind`, for every `subject_kind`.

## Build

In `backend/app/repositories/anomaly_histogram.py` only:

1. Call `_applicable_kinds(subject_kind=..., waf_endpoint_id=None, ips_entity_id=None,
   anomaly_type=None)` and unpack three flags.
2. Add `_ips_branch(since, until, subject_kind)`: one `GROUP BY` over `IpsAnomaly`, on
   `date_trunc` hour of `detected_at` and `severity`, exactly like `_waf_branch`, with the same
   half-open range. When `subject_kind` is `IPS_ENTITY` or `IPS_SOURCE`, filter
   `IpsAnomaly.subject_kind == subject_kind.value`, as the list does. It joins nothing (the
   histogram counts rows; it needs no entity or source name).
3. `families` lists the `SubjectKind` values actually counted. With no `subject_kind`, the IPS
   branch adds `"IPS_ENTITY"` and `"IPS_SOURCE"` (in that order, after `"LOG_SOURCE"` and
   `"WAF_ENDPOINT"`); with `subject_kind=IPS_ENTITY` it is `["IPS_ENTITY"]`, and likewise for
   `IPS_SOURCE`. State this rule in the `families` docstring of `AnomalyHistogramOut` in
   `backend/app/schemas/anomaly.py` (a comment or docstring change only, no field change).
4. The request is still **one SQL statement** for any range and any data size (one more branch in
   the same `UNION ALL`).
5. Bring the stale text up to date: the module docstring (T-085 is no longer "in parallel") and the
   `# Unreachable through the API: SubjectKind has two members.` comment (it now has four; say why
   the empty case is still unreachable, or why it is reachable, whichever is true).
