## The question the view answers

**`/admin/outage-policy`: "Which silent sources page someone, and which are only recorded?"**

1. **Classes table.** One row per `SourceClass` that has at least one monitored source, plus any
   class that has a policy row. Columns:
   - the class;
   - the resolved mode (`ALERT` or `RECORD_ONLY`), and where it comes from: a class row, or "the
     default". The default is the `outage_mode` of a class with no row;
   - the grace: the class row's `silence_grace_buckets`, or "default". Show buckets **and**
     minutes. Take the bucket width from the API; never assume 5 min if the API gives it, and if it
     does not, list that as a contract question;
   - the monitored sources the class covers (`governed_monitored_sources` for a class row; the
     summary's source counts otherwise);
   - the source overrides in it (`outage_overrides`);
   - actions: set the mode, set or clear the grace, remove the class row.
2. **Source overrides list.** Every `SOURCE` row: the source name, its class, the mode, the grace,
   who changed it and when (UTC), and remove. "Add override" opens a **searchable source picker**
   over `GET /fleet/sources`, which shows the name, class and QRadar type.
3. **Impact, before saving.** Every change states what it does in numbers before it is saved, for
   example "12 monitored sources in FIREWALL will no longer raise outage alerts. 2 sources keep
   alerting through their own overrides." Switching back to `ALERT` says the opposite. Explain once,
   in plain words, that `RECORD_ONLY` still records the outage on the source and on `/behavior`,
   that an alert already open still resolves normally, and that only `NO_EVENTS` is affected
   (volume drops and spikes still alert).
4. **Instance scope.** The API supports instance-specific rows. Show them when they exist (an
   "Instance" column, or a badge on the row). Creating them is **not** needed in this task: create
   only global rows, and say so in the report.

## Honesty and states (§3a)

- loading;
- error (what failed, what to do);
- empty (no policy rows: say that every monitored source alerts on an outage by default, D-9);
- 403;
- a save in flight (no double submit);

- 404 on remove (the row was removed by someone else: reload, and say so);
