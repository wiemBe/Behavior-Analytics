# Task B-1.3 — `GET /api/v1/me`: who the caller is and what they may do

Read `AGENTS.md` at the repository root first and follow it exactly. In particular rule 5: secrets
never go into an API response.

This is a small, self-contained backend task from the approved redesign plan
([`docs/UI-REDESIGN-PLAN.md`](../UI-REDESIGN-PLAN.md) UR.5.5, UR.5.6, UR.10 Q4). The widget
catalog and the top bar need to know which permissions the caller holds, so they can hide what a
role cannot read instead of waiting for a `403`.

## Build

1. **`backend/app/schemas/me.py`** (new): `MeOut` with
   - `subject: str`;
   - `email: str | None`;
   - `permissions: list[str]`: the principal's granted permissions as they are, wildcards
     included (`read:*`, `admin:*`), sorted;
   - `effective_permissions: list[str]`: every permission **constant defined in
     `app/security/rbac.py`** (the `PERM_*` names, whose values are strings) that
     `principal.has(...)` grants, sorted. This list saves the browser from re-implementing the
     wildcard rules. Collect the constants from the module, for example every module-level
     `PERM_*` string, and leave `PERM_ADMIN` (`admin:*`) out of the effective list, because it is
     a wildcard, not a capability. Do **not** keep a hand-written list that can drift.
2. **`backend/app/api/routes/me.py`** (new): `router = APIRouter(prefix="/me", tags=["me"])` with
   `GET ""` returning `MeOut` for the resolved principal (`Depends(get_principal)`). Read-only;
   no database access.
3. **`backend/app/api/router.py`:** mount it with `dependencies=[Depends(get_principal)]`, which
   means authenticated with no particular permission. Add a one-line comment in the file's voice
   saying why no permission is required: it returns only the caller's own identity and grants.

Nothing secret appears in the response: no token, no header, no setting. `Principal` carries only
`subject`, `email` and `permissions`; return only those and the derived list.

## Tests

`backend/tests/integration/test_me_api.py` (new), following the client and override patterns of an
existing API test such as `tests/integration/test_search_cadence_api.py`:
- an `admin:*` principal gets `permissions == ["admin:*"]`, and `effective_permissions` contains
  every non-wildcard `PERM_*` value;
- a `read:*` principal gets every `read:` constant in `effective_permissions` and **none** of the
  write or admin ones (`log_source:write`, `admin:waf`, `admin:outage`, …);
- a principal with exactly `{"read:fleet", "alert:ack"}` gets exactly those two;
- `email` is passed through, and is `null` when absent;
- without a principal the route returns `401`, as the route-auth guard
  (`tests/unit/test_route_auth_guard.py`) expects of every route. That guard walks every route
  automatically and must pass **unchanged**. If it needs an edit, stop and report.

Break the code on purpose (for example, return `permissions` as `effective_permissions`), confirm a
test fails, and restore it (AGENTS.md §4).
