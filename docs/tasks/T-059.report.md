## 2. What I did

In each of the two named tests only:

- The mock is now `mockReturnValue(new Promise((res) => { release = res; }))` — one promise per
  test, with its `resolve` captured in a local `release`. Nothing resolves until the test says so,
  so no `user.click` can ever race a 50 ms timer under load.
- Every click is performed while the request is still pending (AlertActions clicks three times on
  the same node; RunSearchButton clicks `Run now` and then the `Running…` button).
- The in-flight state is asserted before settling: `findByRole("button", { name: "Acknowledging…" })`
  `toBeDisabled()` in AlertActions (an assertion that test did not previously have, and the one the
  mutation proof below needs), and the pre-existing
  `findByRole("button", { name: "Running…" })` `toBeDisabled()` in RunSearchButton.
- Only then is the promise released, inside `await act(async () => { release(...) })` — the pattern
  the neighbouring AlertActions test "disables controls while a request is in flight" already uses —
  followed by the unchanged `waitFor(... queryByRole("status") ...)` and `expect(...).toHaveBeenCalledTimes(1)`.

Every pre-existing assertion is still there with its original expected value. No retries, no longer
timeouts, no `vi.useFakeTimers`, no `.skip`/`.todo`, no component change.
