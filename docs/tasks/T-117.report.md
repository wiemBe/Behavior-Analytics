## What I did

Reachability first, then the one fix that stays inside the allowed set: a transitive override, no major of `next`, `echarts`, or `eslint-config-next`.

### echarts

The advisory is the Lines series (`series-lines`), not the line chart (`series-line`). In `echarts@5.5.1`, `LinesSeriesModel.formatTooltip` returns `name` as a raw string, which the HTML tooltip writes with `innerHTML`, when the option sets no `tooltip.formatter`. The 6.1.0 fix (apache/echarts@1e39b00, `src/chart/lines/LinesSeries.ts` only) sends that name through `createTooltipMarkup`, which escapes.

This frontend never registers that series. Production chart modules and what they import:

- `components/behavior/VolumeChart.tsx` — `LineChart`
- `components/waf/WafRequestChart.tsx` — `LineChart`
- `components/ips/IpsSeriesChart.tsx` — `LineChart`
- `components/catalog/SourceEpsChart.tsx` — `LineChart`
- `components/ResultTrend.tsx` — `LineChart`, `BarChart`
- `components/home/EpsChart.tsx` — `LineChart`
- `components/home/EpsByClass.tsx` — `PieChart`
- `components/home/SeverityChart.tsx` — `BarChart`
- `app/fleet/catchall/BucketChart.tsx` — `BarChart`

`import type { EChartsOption } from "echarts"` is erased at compile time. Runtime imports are `echarts/core`, `echarts/charts`, `echarts/components`, and `echarts/renderers`. `LegendComponent` is not registered.

Every tooltip sets `formatter` and returns a string joined with `<br/>` (default `renderMode` is HTML). The interpolated values are numbers, UTC timestamps from `formatDateTime`, and fixed phrases (`kindMeaning`, ratio labels from `RATIO_SPECS`, IPS `quantity` from `ipsDetectors.ts`, axis unit text). They do not include a WAF path, a log-source name, a signature, or an IPS entity value. The condition for a chart-code follow-up in this task is not met, and no chart file was edited.

A 6.1.0 upgrade is the only way to clear the advisory. Published breaks that touch this code (ECharts 6.0.0 notes and the v5→v6 upgrade guide):

- Default theme colours and default component placement change. Legend's default position moves to the bottom. We never register `LegendComponent`, and series colours are set from tokens (`readChartPalette`, `HomePalette`, `sliceColors`). `echarts.init` is called with no theme argument in `VolumeChart.tsx`, `WafRequestChart.tsx`, `IpsSeriesChart.tsx`, `ResultTrend.tsx`, `BucketChart.tsx`, and `useEChart.ts`. Restoring the v5 theme would be `echarts.init(el, 'v5')` after `import 'echarts/theme/v5'`.
- Cartesian overflow and axis-name/label overlap prevention turn on by default, so axes with a `name` inside our fixed `grid` insets can shift. The charts set names such as `Time (UTC)` and `Events per second (EPS)`. The documented opt-out is `grid.outerBoundsMode: 'none'` and disabling `nameMoveOverlap`. That is a layout change on every chart and would need the three-viewport check. It is not a compile break.
- Rich-text styles (`label.rich` / `textStyle.rich`) inherit plain label font styles. This tree sets no `rich` text. `richInheritPlainLabel: false` restores the old rule.
- The percent base of `center` changes for `geo`, `map`, `graph`, and `tree`. None of those series are used.
- `import echarts = require('echarts')` stops working. This tree already uses `import * as echarts from "echarts/core"` and named chart imports, which is the v6 form. Option typings and zrender 6 were not typechecked here, because installing `echarts@6` is a major this task does not take.

### postcss

`next@15.5.28` depends on `postcss@8.4.31` exactly. `npm explain postcss` before the override showed that copy, plus a dev-only `postcss@8.5.30` nested under `vite@6.4.4` (already outside `<=8.5.22`). The four advisories are in PostCSS's own `PreviousMap` / stringify, and they run when `postcss().process()` sees CSS. Next's production server does not call that. The build pipeline does, via `require('postcss')` on stylesheets this repo imports. There is no `next/dist/compiled/postcss` package; compiled files under `next/dist/compiled/postcss-*` are plugins. The processor those build files call is the external package, so the override is the copy `next build` loads.

`8.5.23` is the smallest version outside every current range (`8.5.23` release note: do not load a source map without `opts.from`). `8.5.30` (12 Oct 2026) is the latest 8.5 and includes the later `</style>` escaping fixes (8.5.29, 8.5.30). Pinning `8.5.30` matches the copy Vite already used and stays on major 8. Gates below stayed green, including `next build`, which is the path that loads this package.

### braces

Confirmed dev-only with `npm ls --omit=dev` and `npm explain braces`. No published fix. The force remedy the audit prints is a downgrade to `eslint-config-next@14.2.35`, and moving the plugin forward through `16.4.2` still depends on `fast-glob@3.3.1`. Nothing to apply inside the allowed set.

## Open points

- `echarts@6.1.0` and a braces release past `3.0.3` are the only remaining audit clears. Both are outside this task: the first is a major of a direct dependency whose vulnerable series is not imported, and the second does not exist.
- Tooltip formatters return HTML. Two fallbacks pass an unknown key through unchanged: `classLabel` (`frontend/src/lib/fleet.ts`) into the home donut tooltip (`chartOptions.ts`), and `detectorLabel` (`frontend/src/lib/behavior.ts`) into `VolumeChart`'s anomaly line. Those keys are our class and detector identifiers. `ResultTrend` also inserts `execution_status`, which is our search-execution enum. None of those are the QRadar-shaped strings named in the task, so no formatter change is proposed. If a later chart starts putting a path, a log-source name, a signature, or an IPS value into a tooltip string, escape `&`, `<`, `>`, and `"` before the `<br/>` join, or set the tooltip `renderMode` to `richText`.
- `next/dist/compiled/postcss-*` plugins bundle their own parser. The override does not rewrite those bundles. The build path that `npm audit` flags, and that `next build` calls, is `require('postcss')`, now `8.5.30`.
- No UI file changed, so there is no browser pass. `next build` is the check that the CSS pipeline still accepts `postcss@8.5.30`.
