# Task T-059 — Make the two double-submit tests deterministic (orchestrator ruling)

Read `AGENTS.md` first. This task **is** the orchestrator's explicit permission to edit two existing
tests, within the limits below.

## Problem

Two frontend tests flake under load (seen 2026-10-13: 1 of 1,095 failing in most full runs, a
different one each time):
- `frontend/src/components/AlertActions.test.tsx` — "does not submit twice when clicked repeatedly"
- `frontend/src/components/RunSearchButton.test.tsx` — "disables the button while running so one
  click buys one Ariel query"

Both mock the API with `new Promise((res) => setTimeout(() => res(...), 50))`. Under load, the
`user.click` calls take longer than 50 ms, the request resolves mid-test, the button re-enables and
the test fails (or the "Running…" button is already gone). The components are not at fault.

## What to do

In those two tests only, replace the 50 ms timer with a **manually controlled deferred promise**:
create the promise and keep its `resolve`; perform every click while the request is still pending;
assert the in-flight state (button disabled / "Running…") where the test already does; **then**
resolve it and wait for the status. Every existing assertion stays, with the same expected values
(`toHaveBeenCalledTimes(1)`, `toBeDisabled()`, the status check). Do not add retries, longer
timeouts, `vi.useFakeTimers` for this, or `.skip`/`.todo`. Do not touch any other test or any
component.

Then prove it: temporarily remove the component's in-flight guard (e.g. let the button stay
enabled while pending) and confirm each test fails deterministically; restore.
