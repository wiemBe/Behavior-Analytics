## What I did

1. **Dockerfile.** The deps stage is the only stage edited:

   ```dockerfile
   COPY package.json package-lock.json ./
   # The lockfile is committed, so install from it. `npm ci` fails on any drift
   # between package.json and package-lock.json and resolves nothing fresh — the
   # image installs exactly the dependency tree the frontend gates tested.
   RUN npm ci
   ```

   `package-lock.json` is not excluded by `frontend/.dockerignore`, so it reaches the build context.

2. **`npm ci` once** in `frontend/` (the worktree's own `node_modules`), then the upgrades.

3. **Direct upgrades** (no major):
   * `next` 15.5.22 → **15.5.28** (still the 15.5.x patch line; T-088's current patch).
   * `echarts-for-react` 3.0.2 → **3.0.6** (non-major; its `echarts` peer range widens to `^6.0.0`).
   * **`sharp`** is in the lockfile as Next's optional dependency. `next@15.5.28` declares
     `sharp: "^0.34.3 || ^0.35.5"`, so `0.35.5` is inside Next's declared range with no direct-dep
     bump; `npm update sharp` moved `node_modules/sharp` **0.34.5 → 0.35.5** (and its `@img/*`
     platform/`libvips` packages).

4. **`npm update` within existing ranges** for the T-088 transitives fixable that way:
   `nanoid`, `source-map-js`, `browserslist`, `baseline-browser-mapping`, `js-yaml`,
   `brace-expansion`, and the vite-nested `postcss`. All reach a version at or above T-088's first
   fix (details below).

5. **No `overrides` entry** was added. Next's exact `postcss: "8.4.31"` pin stays as it is; it is
   build-time only and unreachable. Recorded as **accepted** (see Open points).
   **No `npm audit fix`** (plain or `--force`). **No `vitest` 4** and **no `echarts` 6** — both are
   the separately planned majors.
