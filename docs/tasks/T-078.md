# Task T-078 — `GET /ips/sources`: per-field validation status and reasons on each row

Read `AGENTS.md` at the repository root first and follow it exactly. In particular §4: never weaken
a test.

This task is small and mechanical. Change only what is listed here.

## Why

T-053's report, open point 2: the `/admin/ips-sources` list can show "Invalid" or "Inconclusive"
but not **why**, because `GET /ips/sources` (`IpsSourceStatusOut`) carries no per-field result. The
editor has the reasons, through `GET /ips/sources/{id}/profile`. The WAF list already does this:
`WafSourceStatusOut.validation_fields`, built in `app/services/waf_status.py` from the stored
`validation_report["fields"]`. Give the IPS list the same, plus the report's top-level reasons.

## Build

1. `backend/app/schemas/ips.py`:
   - add `IpsFieldStatusOut` with `field: str`, `status: str`, `detail: str | None = None`;
   - add to `IpsSourceStatusOut`, after `validation_requested_by`:
     - `validation_fields: list[IpsFieldStatusOut] = Field(default_factory=list)`;
     - `validation_reasons: list[str] = Field(default_factory=list)`.
2. `backend/app/api/routes/ips.py`, `_source_status`: fill both from the stored
   `profile.validation_report` and **nothing else**, so no new SQL statement is issued.
   - `validation_fields` comes from `report["fields"]`: take `field`, `status` and `detail` from
     each entry that is a `dict`. Skip any entry that is not a `dict`, as the WAF code does.
   - `validation_reasons` comes from `report["reasons"]`, keeping only the string items.
   - With no report (`None` or `{}`), both are empty lists.
   - Never copy `discovered_values`, `populated_events`, `reference` or any other report key into
     these fields. The list must not carry discovered raw values (AGENTS.md rule 3).
   - The report may describe an older profile version than the current one. Show it as stored:
     the row's `validated_profile_version` and `profile_version` already let a client tell them
     apart.

Change no other route, schema or service. Do not touch the WAF code.

## Tests

Add them to `backend/tests/integration/test_ips_profile_admin.py`, next to the existing
`GET /ips/sources` tests, using that file's fixtures and helpers:
- a validated profile: each field's `field`, `status` and `detail` appear on the list row, and the
  report's `reasons` appear in `validation_reasons`;
- a profile with no report yet: both lists are empty;
- a report whose `fields` contains a non-dict item, and whose `reasons` contains a non-string item:
  those items are skipped and the rest is kept;
- the list row carries no `discovered_values` anywhere in its JSON, even when the stored report
  has discovered values;
- **statement count:** the list issues the same number of SQL statements as before for two
  profiles and for five. If the file or `tests/` already has a statement-counting helper, use it.

Then break the code on purpose for at least two of these tests, confirm that they fail, and restore
the code (AGENTS.md §4). List the checks in your report.
