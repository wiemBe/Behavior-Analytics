## Design implications for C.2
- Sender field: `logsourceidentifier`. For these events it equals the syslog hostname and is stable per sender; `sourceip`
  is the transport address (would be the relay/forwarder address in production, many hosts behind one IP).
  Reliability caveats: one lab sample; a sender with an IP-only header or RFC5424 hostname may produce a different
  identifier (not tested); the value is attacker/device-controlled so bound it (top n+1, truncate length).
- "Unknown" marker for SIM Generic: `qid = 18750001` (category 10008). Do not rely on `QIDNAME`. For parsed DSMs there
  is no single marker; use a QID set from `qid_records` ("Unknown%"), per DSM, or accept the ILIKE on QIDNAME.
- Cost per tick: one Ariel search over the catch-all types, ~4 s, 1 POST + 1-2 polls + 1 results GET, row count bounded by
  LIMIT n+1. `WHERE devicetype IN (...)`, `starttime / 300000` grouping and `SUM(eventcount)` are all accepted.
  Search needs a pad for ingest latency: events appeared 35-90 s after send, so a window ending at "now" will miss
  the newest 1-2 minutes unless the existing STOP pad is used.
- The SIM Generic source is the single sink, so volume per `logsourceid` alone is the total; the per-sender split exists only
  via `logsourceidentifier`.
