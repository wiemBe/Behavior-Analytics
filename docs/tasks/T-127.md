## 1. D2: install writes no state file when the QRadar check fails

Today `cmd_install` calls `write_install_state` only `if [ "$qr_rc" -eq 0 ]`. On a site whose
QRadar check fails (QRadar unreachable at install time, a wrong token), the install ends with no
`.qradar-dash/state.json`; `status` then reports it invalid, and `upgrade` and `rollback` refuse.
The state file records the installed version and the image digests, which do not depend on
QRadar.

- Write the state file whenever the stack itself came up (the services started and readiness
  answered), **whatever the QRadar check said**. Keep the install's exit code as it is (1 when
  the QRadar check failed), and keep the summary saying why.
- If the stack did not come up, write nothing (as today).
- A failed state write still ends the install with the existing `die` message.
- An idempotent re-run keeps `previous_images` and `last_upgrade`, as `write_install_state`
  already does.

**Tests (the command path, AGENTS.md §4):** run `./qradar-dash install --non-interactive …` itself
with the existing stub harness of `backend/tests/unit/test_qradar_dash_installer.py`, and check
`.qradar-dash/state.json` after: (a) the QRadar check passes → state written, exit 0; (b) the QRadar
check fails → state written, exit 1, the summary names the QRadar failure; (c) the stack does not
come up → no state file. Break the fix once (put the `qr_rc` condition back) and confirm (b) fails.
