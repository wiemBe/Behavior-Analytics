## Why

`mypy app` is advisory, with a baseline of 31 errors in 18 files. Some are typing noise; some may
be real defects. For example:
- `record_audit(object_id=<UUID>)` where the parameter is `str | None`
  (`app/api/routes/alerts.py`, `searches.py`);
- `get_ariel_search_status(<str | None>)` and `_safe_cancel(<str | None>)` in
  `app/services/search_executor.py`;
- methods named `list` that shadow the builtin in annotations (`app/services/scheduled_search.py`,
  `app/repositories/log_source.py`);
- `"list?[…]" has no attribute "__iter__"` in routes;
- `reversed(list[str | None])` in `app/anomaly/engine.py`.

Run `cd backend && .venv/bin/mypy app` to get the full list.

## What to do

For **each** error, decide and record in the report (a table: file:line, error, classification,
fix):
- **typing only**: the annotation is wrong or missing; the code is right. Fix the annotation
  (`builtins.list` where a method named `list` shadows it; a `TYPE_CHECKING` import for a
  forward-referenced model; a real return type). No runtime change.
- **real defect**: the code can do something wrong at runtime (for example a `None` reaching a
  provider call, or a UUID stored where a string is expected and compared later). Fix it in the
  smallest way that keeps the current correct behaviour, and **add a test that fails on the old
  code** (break-it: revert the fix, see it fail, restore). If the fix would change any API
  response, persisted value or Ariel/QRadar call, stop and report it instead of fixing.
- **cannot fix safely**: leave it, with the reason.

Rules:
- No `# type: ignore` unless you explain in the report why no correct annotation exists; never a
  bare `# type: ignore` (always with the error code).
- No change to any public API shape, migration, setting, or provider interface method set
  (AGENTS.md §2.1: no create/update/delete methods on providers).
- Do not reformat files (`ruff format` is banned); touch only the lines a fix needs.
