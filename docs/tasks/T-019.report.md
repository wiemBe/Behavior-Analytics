## What I did

- Reproduced the defect before changing production code. Each test commits the alert, clears the
  session identity map, reloads it, and asserts `type(alert.severity) is str`. A configured generic
  webhook route ensures rendering is reached.
- The corrected pre-fix reproduction produced the requested three failures:


- Fixed the shared boundary in `NotificationDispatcher._render` with
  `Severity(alert.severity).value`; the database column and schema are unchanged.
- Removed the WAF-only workaround. `test_waf_alerting.py` remains green, demonstrating WAF now
  relies on the dispatcher boundary like every other producer.
- Added one genuine two-run Phase A scenario: the first engine opens a volume-drop alert, the
  transaction is committed and expunged, and a later engine resolves it and enqueues `RESOLVED`.
- Added API cases for genuinely reloaded alerts that enqueue `ACKNOWLEDGED` and `RESOLVED`.
- Audited scheduled searches: both threshold and failure alerts call the same dispatcher.
  A database-loaded `ScheduledSearch.severity` can pass through `AlertInput` as a string, and
  recovery loads an existing `Alert`; both are now safe at the dispatcher boundary. The existing
  scheduled-search alert suite passes all 9 tests.
- Audited `.value` reads under `app/` against String-backed ORM enum attributes:
  - **Same defect, fixed:** `Alert.severity.value` in `app/alerts/dispatcher.py` was the only direct
    `.value` read found on such an ORM row attribute. The root conversion now covers Phase A, the
    operator API, scheduled searches, offense-freshness alerts, and WAF notifications.
  - **Safe:** `NotificationMessage.severity/transition` reads in
    `app/alerts/notifiers/base.py` and `app/alerts/notifiers/channels.py`; these are dataclass fields
    normalized by `NotificationDispatcher._message_from_payload`, not ORM row attributes.
  - **Safe:** `RoutingRule.channel` in `app/alerts/routing.py`; routing rules are constructed with
    `NotificationChannel` members and are not ORM rows.
  - **Safe:** detector evidence, lifecycle targets, and point completeness reads in
    `app/anomaly/engine.py`, `app/anomaly/evidence.py`, and `app/anomaly/detectors.py`; these are
    pure domain objects, and ORM bucket completeness is converted to `BucketCompleteness` when the
    detection context is built.
  - **Safe:** validation results, WAF points/verdicts/observations, and collector reports in
    `app/waf/validation.py`, `app/waf/detector.py`, `app/waf/behavior.py`, `app/waf/engine.py`,
    `app/collectors/waf_endpoint_collector.py`, `app/services/waf_profiles.py`, and
    `app/cli/waf.py`; these are typed domain/dataclass outputs rather than ORM-loaded attributes.
  - **Safe:** `report.status.value` in `app/workers/tasks.py`; `report` is an explanation collector
    result with an enum status, not an ORM model.
