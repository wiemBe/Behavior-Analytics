# Task B-2.2 — constant-cost `/behavior/sources` and `/anomalies/summary`

Read `AGENTS.md` at the repository root first and follow it exactly. In particular §4: never weaken
a test.

From the approved redesign plan ([`docs/UI-REDESIGN-PLAN.md`](../UI-REDESIGN-PLAN.md) UR.0.3 items
10–11, UR.8.3). The new Home calls these two endpoints on every auto-refresh. Today both run SQL
**once per monitored source**.

## The defects

In `backend/app/api/routes/anomalies.py`:

1. `list_source_behavior` (`GET /behavior/sources`) calls `repo.latest_bucket(src.id)` and then
   `repo.baseline_cell(...)` **inside the loop over sources**. That is 2 statements per source.
2. `anomaly_summary` (`GET /anomalies/summary`) calls `repo.baseline_cell(...)` **inside the loop
   over sources** to count `insufficient_data_sources`. It also calls `datetime.now(UTC)` twice
   per iteration, once for the weekday and once for the hour, so at a midnight boundary the
   weekday and the hour can come from different instants.
3. `SourceBehaviorOut.observed_eps` is the latest stored bucket **whatever its completeness**.
   No field tells a client that it came from a `PARTIAL` or `MISSING` bucket.

## Build

1. **`backend/app/repositories/anomaly.py`:** add two bulk methods, each **one statement**
   whatever the number of ids:
   - `latest_buckets(log_source_ids) -> dict[uuid.UUID, LogSourceMetric]`: the newest
     `LogSourceMetric` per source (for example `DISTINCT ON (log_source_id) … ORDER BY
     log_source_id, bucket_start DESC`). A source with no bucket is absent from the dict.
   - `baseline_cells(keys, *, metric) -> dict[tuple[uuid.UUID, int, int], LogSourceBaseline]`,
     where `keys` is a collection of `(log_source_id, weekday, hour)`. Use one `SELECT` with a
     tuple `IN`, or an equivalent single statement.
   - An empty input returns `{}` without touching the database.
   - Keep `latest_bucket` and `baseline_cell`: the single-source detail route still uses them.
2. **`list_source_behavior`:** one `latest_buckets` call, then one `baseline_cells` call. The keys
   are each source's latest bucket's `(isoweekday, hour)`, **exactly as today**. Then build the
   rows with the unchanged `_source_behavior`. Keep the output order (`monitored_sources()`
   order) and every field value identical to today.
3. **`anomaly_summary`:** take `now = datetime.now(UTC)` **once**, and make one `baseline_cells`
   call with every monitored source at `(now.isoweekday(), now.hour)`. Count
   `insufficient_data_sources` as today: no cell, or a cell that is not `is_reliable`.
4. **Additive field:** `SourceBehaviorOut.last_bucket_completeness: str | None = None`. It is the
   latest bucket's `completeness` value (`COMPLETE`, `PARTIAL` or `MISSING`), and `None` when
   there is no bucket. Add a `#:` comment in the schema's voice: `observed_eps` comes from this
   bucket, so a client must not rank or present a non-`COMPLETE` value as a measurement. Change
   nothing else in the response.
5. Mirror the field in `frontend/src/lib/api.ts`'s `SourceBehavior` type as an optional
   `last_bucket_completeness?: "COMPLETE" | "PARTIAL" | "MISSING" | null`. Make no other frontend
   change.

## Tests

Put them in `backend/tests/integration/test_phase_a_api.py` next to the existing
`/behavior/sources` and `/anomalies/summary` tests, or in a new
`backend/tests/integration/test_behavior_bulk_reads.py`, whichever fits the file's structure.
- **Statement count.** Each endpoint issues the same number of SQL statements for 2 monitored
  sources as for 6. Use the existing helper `recorded_statements` in
  `tests/integration/test_rule_match_collection.py`; `tests/integration/test_ips_profile_admin.py`
  shows how to point it at a test client's engine. Seed buckets and baseline cells so the
  bucket and cell paths run, including a source with no bucket and a source with an unreliable
  cell.
- **Equivalence.** For a mixed fleet, assert the rows equal what the old per-source path
  produced: the same order and the same `observed_eps`, `expected_eps`, `expected_low`,
  `expected_high`, `deviation_ratio`, `state`, sample count and completeness. Cover:
  - no bucket;
  - a bucket but no cell;
  - an unreliable cell;
  - a zero median (`deviation_ratio` is `None`);
  - an open anomaly;
  - two sources whose latest buckets fall in **different** weekday-hour cells.
- **`last_bucket_completeness`** is `COMPLETE`, `PARTIAL` and `None` (no bucket) on three
  sources.
- **Summary.** `insufficient_data_sources` and `monitored_sources` are correct for a fleet with
  reliable, unreliable and missing cells.
- **Bulk methods directly:** an empty input returns `{}` with **zero** statements.
- Every existing test passes **unchanged**. If one fails, stop and report it.

Break the code on purpose for at least two of these (for example, key the cell lookup on the
wrong hour; put a per-source query back), confirm the tests fail, and restore the code.
