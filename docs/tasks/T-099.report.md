### Part 2 — a page test for `/admin`

`frontend/src/app/admin/page.test.tsx` follows the neighbouring style
(`src/app/config-changes/page.test.tsx`, `src/app/admin/search-cadence/page.test.tsx`): render the
page directly, assert by role and text, with a header comment listing the route's states (the hub
is a static index with one state — no data read, so no loading/empty/error state and no query
parameter). Five tests pin:

1. exactly one `h1`, "Administration", plus the description
   "Settings that control collection, source classification and outage alerting.";
2. the list labelled "Administration sections" contains exactly five links, in order:
   Search cadence, Classification rules, Outage alerts, WAF sources, IPS sources;
3. their `href`s, in order: `/admin/search-cadence`, `/admin/classification-rules`,
   `/admin/outage-policy`, `/admin/waf-sources`, `/admin/ips-sources`;
4. each entry's one-line description;
5. no stale phase wording: `document.body.textContent` does not match `/Phase \d/`.

Two of the five entries are plain `<a href>` and three are Next `<Link>`; both render an anchor, so
the tests read all five uniformly and would catch a broken `Link` too.
