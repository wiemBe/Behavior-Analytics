# Task B-1.2 — `GET /overview`: say when the QRadar instance was last health-checked

Read `AGENTS.md` at the repository root first and follow it exactly. In particular rule 5: secrets
never reach an API response, and §4: never weaken a test.

This task is small and mechanical, from the approved redesign plan
([`docs/UI-REDESIGN-PLAN.md`](../UI-REDESIGN-PLAN.md) UR.3.4, "Connection status"). The top bar
shows the QRadar instance's status from `GET /overview` (`instance_status`). "HEALTHY" means
little without its age. `qradar_instance.last_health_check_at` exists in the model
(`app/models/instance.py`) but is not in the response.

## Build

1. `backend/app/schemas/log_source.py`, `SocOverview`: add
   `instance_last_health_check_at: datetime | None = None` after `instance_version`, with a `#:`
   comment in the file's voice: when the instance's status was last checked, and `None` when it
   was never checked or no instance exists.
2. `backend/app/services/overview.py`: fill it from `instance.last_health_check_at` when an
   instance exists, otherwise `None`. **Do not** expose `last_error`: its text may hold a
   provider message, and a status age is all the top bar needs.
3. `frontend/src/lib/api.ts`: add `instance_last_health_check_at?: string | null` to the overview
   type. Make no other frontend change.

Change nothing else.

## Tests

In the existing `GET /overview` integration tests (find them with
`grep -ln "/overview" backend/tests/integration/*.py`), add:
- an instance with `last_health_check_at` set: the response carries it, in ISO format with its
  timezone;
- an instance never checked: `null`;
- no instance: `null`, and `instance_status` is still `"UNKNOWN"` as today;
- the response contains no `last_error` key, even when the instance has a `last_error` set.

Every existing test passes unchanged. Break the fill on purpose, confirm a test fails, and restore
it (AGENTS.md §4).
