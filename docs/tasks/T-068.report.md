## Review round 1

Defect: `_outage()` is called for every evaluated source (the grace override in `_build_context`),
and it resolved the class through `self._source_class()`, which runs one SELECT per source. The
spec's Engine hook (T-068.md) forbids a query per source, so the per-run statement count grew with
the fleet.

### Change

`backend/app/anomaly/engine.py`:

- `_outage()` no longer calls `_source_class()`. It now reads the policy rows once (unchanged
  `_policies()`), and consults a class **only** when a CLASS policy row exists:
  - no policy rows at all → the default resolves with no class lookup;
  - policy rows but no CLASS row → the class lookup is skipped entirely;
  - a CLASS row present → the class comes from a new `_classes()` map.
- `_classes()` loads `log_source_id -> source_class` for **every** classified source from
  `LogSourceClassification` in **one** statement, on first need, and caches it on the engine
  (`self._class_map`) for the rest of the run. This is the same column `_source_class()` reads.
- `_source_class()` is unchanged, so the alert context (opening/refreshing `open_or_update`) keeps
  its existing per-source memoised lookup.

The per-run SQL cost of evaluation is now `1` policy load `+ 1` class-map load at every fleet size,
independent of the number of evaluated sources.

### New tests

Added to `backend/tests/integration/test_outage_policy_engine.py` (reusing the repo's
`counting()` `before_cursor_execute` helper from `test_waf_scale.py`), with a shared

- `test_class_lookup_is_one_statement_whatever_the_fleet` — a policy with a CLASS row; evaluates
