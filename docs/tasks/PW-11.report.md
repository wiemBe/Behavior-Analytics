## 4. Design / code disagreements (code wins; each is written as the code does)

1. **`PW_ANOMALY_RETENTION_DAYS` is never applied.** `config.py` declares and validates it
   (`Field(default=180, ge=2)`), and §G.14.3 documents it as "resolved incidents". `PwRetention`
   (`backend/app/services/pw_retention.py`) deletes only `pw_value_metric`, `pw_bucket` and retired
   `pw_value`; `pw_anomaly` rows are never deleted. The 180-day anomaly sentence is design intent, not
   built. Documented in README, `§G.7.2` and `§G.14.3`; retained as an open point (§6).
2. **`GET /property-watches/{id}/aql` (PW-5c) exists but is missing from the design's §G.11 API
   table.** The route is real (`property_watches.py:910`) and read-only; the README table lists it.
3. **`pw_drop_ratio` exists in code but is absent from the design's §G.14.3 table.** Declared in
   `config.py` (`Field(default=0.5, gt=0.0, lt=1.0)`); it is documented in the README settings table.
4. **`pw_max_properties_per_watch` is named as a setting in §G.3 (line 295) but is a constant in
   code.** The limit is `PW_MAX_PROPERTIES` in `backend/app/services/property_watches.py` (2), not a
   configurable setting. The README documents it as "at most 2 properties", not as a setting.
5. **§G.11's `property_watch:write` summary row omits "pins".** Line 1263 lists "create, edit, enable,
   disable, delete, preview"; the route table (line 1294) and the code include `PUT /pins`. The README
   lists pins under that permission.
6. **No PW doctor check.** `doctor.py`'s `check_families_off` (4 flags, line 604) and `_family_enabled`
   (5 families, line 562) omit `PW_COLLECTION_ENABLED`. `_family_enabled` returns `.get(family, True)`,
   so `check_cadence` treats `PROPERTY_WATCH` as enabled even when the family switch is off and can
   warn "enabled families late or never run". Written up honestly in `OPS-R46` as a reason `doctor`
   may still warn while collection is intentionally off; left as an open point (§6).
7. **§G.16's PW-11 row lists "the PLANNER board" as an output.** `docs/PLANNER.md` is out of scope for
   this task (AGENTS.md §1: never edit it), so that part is not done.
