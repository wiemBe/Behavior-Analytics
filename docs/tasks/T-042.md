## Build

1. **Routes, schemas and semantics exactly as §FM.4**: `mapping-schema`, `candidates`, profile
   `GET`/`PUT`, `validate`, `enable`, `disable`, `history`. The WAF schema (§FM.3) lives in code next
   to `WafFieldMapping` (one source of truth for labels and descriptions; the table in §FM.3 is the
   copy). `default` per field comes from the `WAF_*_PROPERTY` settings (empty string → null).
2. **PUT** with optimistic concurrency (`expected_profile_version`; 409 with the current version),
   422 with the `WafProfileError` message, 201 on create, 200 otherwise. A mapping change bumps the
   version, resets validation (as `upsert` does) **and requests validation** (§FM.5). A label-only
   change does neither. Unchanged → 200, nothing audited.
3. **Migration `0015`** (chained after `0014`): `waf_source_profile.validation_requested_at
   timestamptz NULL`, `validation_requested_by varchar(255) NULL`. Model columns to match. Add a
   migration test in the existing style of `tests/integration/test_migrations.py` (round trip).
4. **Asynchronous validation (§FM.5):** a request sets the pending columns, audits
   `waf.profile.validation_requested`, and enqueues a new Celery task `validate_waf_profile`. 409
   while pending and younger than the new setting `waf_validation_pending_timeout_seconds`
   (default 900, `ge=60`). The worker:
   - validates through `WafProfileService.validate` with actor = the requester;
   - **re-reads the row `FOR UPDATE` before storing**: if the version changed since it started,
     it discards the result, keeps pending, and re-enqueues once; a result is never stamped onto a
     version it did not check;
   - on any exception: clears pending, stores nothing as `VALID`, audits the failure (class name
     only), and leaves the previous validation state;
   - builds the provider for the profile's instance the way the CLI does
     (`build_provider_for_instance`) and always closes it.
   Make the enqueue function injectable so tests do not need a broker (follow
   `dispatch_waf_collection(enqueue=…)`).
5. **Enable/disable** through `set_enabled`; enable refused with 409 and its message.
6. **History** from `AuditLog` rows with `object_type = "waf_source_profile"` and this profile's id,
   newest first, at most 50, mapped to `WafProfileHistoryEntryOut`. One query.
7. **Candidates:** log sources of the instance without a profile; `q` substring (case-insensitive,
   escaped for `LIKE`), `limit` default 50 max 200; class `WAF` first via the Phase C
   classification table, then name. One query.
8. **The validation report served** is the stored report **without** its `queries` lists.
9. **Prefill (§FM.7)** needs no new route: `GET /waf/sources` already lists profiles; the schema
   carries the settings defaults. Do not build more than that.
10. `tests/unit/test_route_auth_guard.py`: add `_BODIES` entries for the new mutating routes if the
    guard test reports 422. Change nothing else there.

## Tests (new behavior needs tests; pin every guard and exit path)

- API: 401 without a principal; 403 for `read:*`; 404 for an unknown log source and for a missing
  profile; 422 for a bad name (e.g. `URL"; DROP`), overlapping action values, an action map without
  an action property; 409 for a stale `expected_profile_version`, for create when one exists, for
  enable while not `VALID` for the current version, and for validate while pending; 201/200 codes.
- A mapping change: version + 1, validation reset, pending set, one enqueue call, audit rows with
  the principal as actor; an enabled profile becomes ineligible (reason says the version is not
  validated).
- A label-only change: no version bump, no enqueue.
- Worker: success stores the report and clears pending; **the stale-version race** (change the
  mapping between the worker's start and its write; prove the result is discarded and the task
  re-enqueued); an exception clears pending and stores no `VALID`; a stale pending marker (older
  than the timeout) lets a new request through.
- The served report never contains `queries`.
- History and candidates: ordering, limits, the `q` filter (including `%` and `_` treated
  literally).
- The CLI still works: existing CLI tests stay green unchanged.

After writing the tests, break the code on purpose (e.g. remove the `FOR UPDATE` version check,
remove the 409 on pending) and confirm the tests fail, then restore.
