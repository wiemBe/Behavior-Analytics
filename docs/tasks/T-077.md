# Task T-077 — live, read-only: can AQL give a country-level aggregate for the home map? (D-10)

Read `AGENTS.md` at the repository root first. Follow it exactly.

This is a **live, read-only check**. Write no application code, and change no repository file.
Throwaway scripts and the report go only in your scratch directory (below).

## Why

Decision D-10 (`docs/PLANNER.md` §4): the home screen gets a world map, fed by a **new geo
collection**: a country-level aggregate collected under the search cadence, with no raw IP ever
stored (AGENTS.md rules 3, 8 and 9). D-10 says to validate the AQL geo functions on the live lab
QRadar **before** anything is designed or built. T-065 showed what an unverified AQL form costs:
`LIKE` on an IP field was rejected and sank a feature. Find the facts first.

## Method

1. Use the main checkout, `/home/efe/Documents/QRadar-Dash/backend`, with `PYTHONPATH=.` and
   `.venv/bin/python -I`. Build the provider with `app.providers.factory.build_provider` and the
   process-environment overrides below. Run AQL **only** through the provider's
   `create_ariel_search`, `get_ariel_search_status`, `get_ariel_search_results` (and
   `cancel_ariel_search` on a timeout). **Never MCP. No database writes.**
2. First list what the events database offers. One `GET /ariel/databases/events` (through the
   provider's request path, or a read-only GET with the same client) gives the column list. Note
   any geo-like column (for example a source or destination geographic location field), and its
   type.
3. Use the lab's existing events first: a window of the **last 24 hours**. Most lab traffic may use
   private or synthetic addresses. If no public address is found, you may send one burst with
   the repository generator (`tools/qradar_lab_loggen.py` or `lloggen.py`), using a scenario or
   option that emits **public documentation or synthetic public** source IPs, if one exists:
   **at most 5 EPS for at most 5 minutes**. Stop it by PID and confirm that none is left. If no
   such option exists, do not change the generator. Say so, and answer from what the data allows.
4. Probe these forms. Use a small window (≤ 1 hour) and `LIMIT` on every search:
   - `GEO::LOOKUP(sourceip, 'country', 'name')` and the same with `'iso_code'` (an ISO-3166
     code is what a map needs). If the data name is rejected, try the other names the error or
     the IBM 7.x AQL reference suggests, one at a time.
   - The same on `destinationip`.
   - Grouping: `SELECT <geo expr> AS "country", SUM(eventcount) AS "events" ... GROUP BY
     <geo expr>`. If grouping by the expression is rejected, try one alternative (`GROUP BY` the
     alias, or by position).
   - The keyed form the collectors use (see `app/providers/qradar_rest.py`, for example
     `get_log_source_metrics_bucketed` or `get_ips_keyed`): the geo key together with
     `starttime / 300000` in the `GROUP BY`, `ORDER BY SUM(eventcount) DESC`, over **one hour**,
     fleet-wide, with `LIMIT 5000`.
   - A filter that keeps only public addresses. The candidates are `NOT INCIDR('10.0.0.0/8', sourceip)`
     and so on for the private ranges, or the geo key `IS NOT NULL`. Note: T-065 found that QRadar
     rejects `LIKE` on IP fields.
5. For cost, run **one control search**: the same one-hour, fleet-wide keyed window grouped only by
   `starttime / 300000`, with no geo expression. Compare its duration with the geo search's.

## Questions

1. Which geo functions and data names does this QRadar accept? Give the exact AQL of each accepted
   and each rejected form, with QRadar's error text for the rejected ones.
2. What does the lookup return for:
   - private addresses (RFC 1918);
   - loopback;
   - `0.0.0.0`, or a missing address;
   - a public address the GeoIP data does not know?
   Say whether it is `NULL`, an empty string, a sentinel string, or an error. Is the GeoIP data
   populated at all on the lab?
3. Can the geo key share a `GROUP BY` with `starttime / 300000`? How many rows does one fleet-wide
   hour return, and is the result truncated?
4. What does the geo search cost against the control search: its duration, its row count, and any
   QRadar warning?
5. Source or destination: which field holds the external party on the lab's traffic, for inbound
   firewall, IPS and WAF events? State it per source type where the data shows it.
6. What should a collector designer know that this run could not show? For example: skew, very
   large country counts, or GeoIP data age.
