# Task B-4 — dashboard persistence: models, migration `0023`, API, RBAC, audit

Read `AGENTS.md` at the repository root first and follow it exactly. This is the backend half of
Phase 4 of the approved UI redesign (B-4.1 and B-4.2 of `docs/UI-REDESIGN-PLAN.md` UR.7, done as
one task). **The binding design is UR.5.5 "Persistence"**; read it in full, and UR.5.1 and UR.5.7
for context. Where this spec adds a rule, the rule here wins; where it is silent, UR.5.5 wins.

## What to build

### 1. Models and migration (B-4.1)

- `backend/app/models/dashboard.py`: `Dashboard` and `UserDashboardPref`, exactly the columns,
  types, defaults, `CHECK`s, unique constraint and index of UR.5.5. Follow the existing models'
  mixins and idioms (`UUIDPrimaryKeyMixin`, `TimestampMixin`, string enums with a `CHECK`); export
  them from `app/models/__init__.py`.
- `backend/alembic/versions/0023_dashboards.py`, `down_revision = "0022"`: create both tables,
  the unique constraint, `ix_dashboard_owner (owner_subject, updated_at DESC)`, the `CHECK`s and the
  `ON DELETE SET NULL` foreign key. Additive, seeds nothing, symmetric `downgrade()`. The docstring
  says that under the current auth every dev caller is `local-dev`, so all dashboards share one
  owner until OIDC (UR.10 Q3).

### 2. Layout validation (Pydantic, in `app/schemas/dashboard.py`)

The layout JSON version 1 of UR.5.5, with every bound: at most 24 widgets; `x` 0–11, `w` 1–12,
`x + w ≤ 12`, `y ≥ 0`, `h` 1–24; `id` `^w_[a-z0-9]{4,12}$` and unique within the layout; `type`
`^[a-z0-9_.]{1,64}$`; `range` null or `1h|24h|7d`; `config` a JSON object of at most 4 KB
serialized; the whole layout at most 64 KB serialized; **no unknown keys** at the top level or in a
widget; top-level `range` one of `1h|24h|7d`. An unknown widget `type` is valid and stored as is.
`v` must equal `schema_version`; a `v` the server does not know is refused with `422`. A pure
`upgrade_layout(layout) -> layout` function applies on read; today it is the identity for `v: 1`,
with a unit test that pins it and one that refuses an unknown `v`.

The server **never interprets or executes** `config` (AGENTS.md rule 4) and never logs a layout.

### 3. RBAC (`app/security/rbac.py`, following the file's comment style)

- `PERM_DASHBOARD_READ = "read:dashboards"` (granted by `read:*`);
- `PERM_DASHBOARD_WRITE = "dashboard:write"` (**not** granted by `read:*`, like `log_source:write`);
- `PERM_DASHBOARD_SHARE = "admin:dashboards"` (granted by `admin:*`).
Check how the seeded roles and the local-dev / local-token principals get permissions, and say in
the report what each of them can do with dashboards. Do not change any existing role's grants.

### 4. API (`app/api/routes/dashboards.py`, registered in the API router, prefix `/dashboards`)

The routes, purposes and permissions of the UR.5.5 table (all except `GET /me`, which exists).
The router guard is `dependencies=[Depends(requires(PERM_DASHBOARD_READ))]` on its
`include_router` line in `app/api/router.py`, with a comment like its neighbours'; each write
handler calls `require_permission` for its write permission, as `catchall.py` does.
Rulings that UR.5.5 leaves open:
- **Visibility.** A caller sees their own dashboards and every `SHARED` one. Another owner's
  `PRIVATE` dashboard answers **`404`** to read, write and duplicate (never `403`: do not reveal
  that it exists).
- **Owner rule.** `PUT`, `PATCH` and `DELETE` need `dashboard:write` **and** ownership, or
  `admin:*`. A non-owner with `dashboard:write` on a `SHARED` dashboard gets `403`.
- **Any change of `visibility`** (to or from `SHARED`) needs `admin:dashboards`.
- **`PUT /dashboards/default` must be declared before `/dashboards/{id}`** so `default` is never
  parsed as an id. Its target must be readable by the caller (own or `SHARED`), else `404`; `null`
  clears it. `GET /dashboards` sets `is_default` from the caller's pref; a default that points at a
  dashboard the caller can no longer read (it became `PRIVATE`) reads as no default.
- **Optimistic concurrency.** `PUT` carries `expected_revision`. The update is one atomic
  statement conditioned on the revision (`UPDATE … WHERE id = :id AND revision = :expected`),
  never read-then-write; it increments `revision`. On mismatch, `409` with the current revision in
  the body. `PATCH` also increments `revision`.
- **Limits.** 20 dashboards per owner (create and duplicate): `409` naming the limit. A duplicate
  name for the same owner: `409` naming the conflict. Duplicate names the copy "Copy of {name}",
  then "Copy of {name} (2)", (3)…, truncated so the whole name fits 80 characters.
- **List.** `GET /dashboards` returns a `PagedDashboards` model in the shape of the existing
  `Paged*` models in `app/schemas/anomaly.py` (`items`, `total`, `limit`, `offset`; `limit`
  default 50, max 200), ordered by `updated_at` descending, with the fields of
  UR.5.5 (`widget_count` computed from the layout, no layout body in the list).
- **Audit.** Every successful write calls `record_audit` with the actions, `object_type` and
  `detail` of UR.5.5 (`{name, revision, widget_count}`; **never the layout**). A refused write
  (403, 404, 409) writes no success row.

## Tests

- `tests/integration/test_migration_0023.py`: round trip pinned to its own revision
  (`upgrade 0023`, `downgrade 0022`, `upgrade 0023`), then `upgrade head` and `alembic check` (the
  pattern of `test_migration_0017.py`); the constraints exist (unique name per owner, the
  `CHECK`s, `ON DELETE SET NULL` clears the pref).
- `tests/integration/test_dashboards_api.py`: the RBAC matrix (read-only principal, writer,
  owner, non-owner, admin) for every route; every layout bound (one test per bound, at the limit
  and one past it); unknown `v`; unknown widget type stored and returned unchanged; revision
  conflict (two writers, the second gets `409` with the current revision); the per-owner limit;
  duplicate naming and its 80-character truncation; default set, cleared, cleared by delete,
  hidden when the target turns `PRIVATE`; the `404` for another owner's private dashboard; audit
  rows (action, detail, no layout); `/dashboards/default` is not captured by `/{id}`.
