## Build

1. **Model and migration.**
   - Add `outage_alert_policy` exactly as §C.7 describes, in a new model module
     `app/models/outage.py`, exported from `app/models/__init__.py`.
   - Add an `OutagePolicyMode` StrEnum (`ALERT`, `RECORD_ONLY`) and an `OutagePolicyScope`
     StrEnum (`CLASS`, `SOURCE`), stored as strings with CHECK constraints.
   - `silence_grace_buckets` is nullable and bounded 0–48 by a CHECK.
   - Uniqueness is on `(instance_id, scope_kind, scope_value)`. `instance_id` NULL means global,
     so make the uniqueness hold with NULL too (`NULLS NOT DISTINCT`, or an expression index).
   - **Migration revision id `0019`, with `down_revision = "0017"` for now.** Another task (T-050b)
     is adding `0018` in parallel, and the orchestrator re-chains at merge. Say so in your report.
   - Upgrade → downgrade → upgrade must run clean, with no drift.
   - The round-trip test must be pinned to its own revision, in the style of the `0016` and `0017`
     tests.
2. **Resolution, pure:** `app/fleet/outage_policy.py`, with
   `resolve(policy_rows, *, log_source_id, source_class, instance_id, default) -> ResolvedOutage(mode, silence_grace_buckets, basis)`.
   - Precedence: SOURCE row > CLASS row > default.
   - Instance-specific rows win over global rows at the same scope.
   - `basis` records which rule applied (`SOURCE`, `CLASS`, `DEFAULT`).
3. **Engine hook** in `app/anomaly/engine.py`:
   - Load every policy row **once per engine instance or run**, in one statement, and reuse
     the existing per-run source-class lookup. Do not add a query per source.
   - **When `NO_EVENTS` opens or refreshes for a source whose resolved mode is `RECORD_ONLY`, do
     not call `AlertService.open_or_update` and do not enqueue a notification.** Everything else
     stays as it is: the anomaly row, its state, its lifecycle, evidence and explanation pending.
   - Resolution is unchanged: when a `NO_EVENTS` anomaly resolves, `resolve_by_fingerprint` still
     runs. An alert opened before the switch therefore closes normally.
   - A resolved `silence_grace_buckets` overrides `thresholds.silence_grace_buckets` for that
     source's `NO_EVENTS` evaluation. Read `app/anomaly/thresholds.py` and
     `app/anomaly/detectors.py:149`.
   - `VOLUME_DROP`, `VOLUME_SPIKE` and every other type are untouched.
   - The setting `outage_alert_default` (`ALERT` | `RECORD_ONLY`) defaults to `ALERT`.
4. **API**, `app/api/routes/outage_policy.py`, mounted under `/api/v1/outage-policy` with a
   router guard on a new permission `admin:outage` (in `app/security/rbac.py`; `read:*` does not
   satisfy it; the seeded admin role gets it through `admin:*`):
   - `GET` lists the rows. For each CLASS row, include the number of monitored sources it
     currently governs.
   - `PUT /classes/{source_class}` and `PUT /sources/{log_source_id}` take
     `{mode, silence_grace_buckets, instance_id?}` and upsert.
   - `DELETE` on either removes the row. 404 when it is absent.
   - 422 for an unknown class, a grace outside 0–48 or an unknown mode. 404 for an unknown source.
   - Every mutation writes an audit record with the principal as actor, `object_type =
     "outage_alert_policy"`, and the before and after values.
   - Add `_BODIES` entries for the new mutating routes in `tests/unit/test_route_auth_guard.py`, and
     change nothing else there.
5. **`GET /api/v1/fleet/summary`**: each class gains `outage_mode` (resolved for that class, with no
   source overrides) and `outage_overrides` (the count of source rows in that class). Additive
   fields only. The summary's statement count must stay constant (it is pinned at two sizes).

## Tests (pin every guard and exit path)

- **Resolution:** every precedence pair; instance-specific over global; the default; NULL grace
  falling through.
- **Engine (integration):**
  - a `RECORD_ONLY` class gives `NO_EVENTS` opening with **no alert row and no notification**;
  - an `ALERT` source override inside a `RECORD_ONLY` class does alert;
  - with the default, alerts behave exactly as today, and every existing engine test passes
    unchanged;
  - an alert opened under `ALERT`, followed by a switch to `RECORD_ONLY` and recovery, ends
    resolved;

  - a `VOLUME_SPIKE` in a `RECORD_ONLY` class still alerts;
  - the fingerprint is unchanged;
  - the statement count per evaluation is constant at two fleet sizes (reuse the existing scale
    test pattern, if there is one).
- **API:** 401; 403 for `read:*`; 404; 422; 200 or 201; delete; audit actor and before/after;
  the count in `GET`.
- Migration round trip and drift.
