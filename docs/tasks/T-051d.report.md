## 2. What I did

Shape chosen: one call per source, via `rebuild_due(..., log_source_id=...)`. Why: each source needs its own `train_through`, and a mapping argument would complicate the least-recently-computed ordering and the per-call limit. A call is a constant set of statements (the limit is at most one chunk of `ips_baseline_rebuild_batch_size`), pinned at 5 and 40 entities in the scale test.

Each source that evaluated successfully this run, or whose watermark exists and did not fail, trains through its own bound. A failed or never-evaluated source is skipped alone, with its reason in its own report. A rebuild failure runs in a savepoint and is recorded as that source's skip reason (sanitized class). Evaluate-before-train, the per-source savepoint, and the sanitized error are unchanged.

Tests added: a lagging source does not hold back another; a never-evaluated source is skipped alone; a source failing this run is skipped despite an older watermark; two instances (training A leaves B's cell untouched); scoped `rebuild_due` never touches another source; scoped training statement count constant at two sizes.

Ruled and consequential test changes (the old instance-wide rule no longer holds):
- `test_training_stops_at_the_least_evaluated_source` is replaced by `test_a_lagging_source_does_not_hold_back_another_sources_training`: the expectation is now per-source bounds (`START + 2 days + 1h` and `START + 1h`). This is the ruled change.
- `test_one_source_failure_leaves_the_other_sources_evaluated`: its instance-level "training skipped" assertion now reads "the failed source is skipped alone, the healthy one trained", which is what the spec requires. The spec did not name this test; flagging it.
- `test_a_spike_is_judged_before_the_run_trains_its_cell` reads the per-source report fields instead of the instance report; values unchanged.
