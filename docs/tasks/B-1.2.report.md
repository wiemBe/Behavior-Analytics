# Task B-1.2 report — `GET /overview`: say when the QRadar instance was last health-checked

## 1. Files changed

- `backend/app/schemas/log_source.py` — `SocOverview` gains `instance_last_health_check_at: datetime | None = None` after `instance_version`, with a `#:` comment stating when the instance's status was last checked, and `None` when it was never checked or no instance exists.
- `backend/app/services/overview.py` — `OverviewService.build()` fills the new field from `instance.last_health_check_at` when an instance exists, otherwise `None`. `last_error` is deliberately not exposed.
- `frontend/src/lib/api.ts` — `SocOverview` gains `instance_last_health_check_at?: string | null`. No other frontend change.
- `backend/tests/integration/test_api.py` — additions only: two helpers (`_overview_client`, `_seed_instance`) and four integration tests.
- `docs/tasks/B-1.2.report.md` — this report.

## 2. What you did

- The schema field is optional with a `None` default, so the response shape stays backward compatible, and it sits after `instance_version` as specified.
- The service fills the field only from `instance.last_health_check_at`; it never reads or exposes `instance.last_error`, whose text may hold a provider message. With no instance row, the field is `None` and `instance_status` stays `"UNKNOWN"` as before.
- Four integration tests in the existing `GET /overview` test file (`tests/integration/test_api.py`), one per required case:
  - `test_overview_carries_instance_last_health_check_at` — an instance with `last_health_check_at` set: the response carries it, parsed back with `datetime.fromisoformat` and asserted to keep its timezone (`tzinfo is not None`) and to equal the seeded instant;
  - `test_overview_instance_never_checked_is_null` — an instance never checked: `null`;
  - `test_overview_without_instance_is_unknown_and_null` — no instance: `null`, and `instance_status` is still `"UNKNOWN"`;
  - `test_overview_never_exposes_instance_last_error` — an instance with `last_error` set: the response contains no `last_error` key.
- Break-on-purpose check (AGENTS.md §4): the fill was temporarily broken to always yield `None`; `test_overview_carries_instance_last_health_check_at` failed (`FAILED tests/integration/test_api.py::test_overview_carries_instance_last_health_check_at`, summary `1 failed, 4 passed, 2 deselected, 2 warnings in 2.68s`). The fill was restored and the file went green again.
- Every existing test passes unchanged (the pre-existing `test_inventory_and_overview_flow` and the two always-run liveness/security-header tests are untouched).
- Frontend: only the one optional field was added to the overview type; `npm run typecheck` is clean.
