# Task T-130 — install refuses a backup directory it cannot write

Read `AGENTS.md` at the repository root first and follow it exactly (§4 especially: test the
command path, not only the helper). Then read the `qradar-dash` script (`preflight_host`, ~339;
the install step that creates the backup directory, ~717) and
`backend/tests/unit/test_qradar_dash_installer.py` (the `inst`, `build_path` and `flow_path`
fixtures; `_install_flow`; `test_preflight_refuses_a_host_with_7_gib_of_memory` is the pattern).

## The defect (found in the OPS-9 r3 review, 2026-10-17)

1. `preflight_host` never checks that the account running the script can create or write the
   backup directory. It only checks free space (`free_kb`, which walks up to the nearest existing
   parent) and that an existing path is a directory.
2. The install step runs `mkdir -p "${ANS[BACKUP_DIR]}" && chmod 700 "${ANS[BACKUP_DIR]}"`. Under
   `set -euo pipefail` a failing command on the **left** of `&&` does not stop the script, so when
   `mkdir` fails (for example `/var/backups/qradar-dash` under a `root`-owned `/var/backups`, the
   operator not root) the install goes on, finishes "healthy", and the first `backup` (and the
   pre-upgrade backup, so every `upgrade`) fails later.

The operator runbook (`docs/OPERATIONS.md`, "Operatör hesabı ve yedek dizini") already says the
preflight stops in that case. Make that true.

## What to build

1. **Preflight check**, next to the existing "exists and is not a directory" check, and like every
   other preflight check it writes nothing (it also runs under `--dry-run`):
   - the backup directory exists: it must be a directory the running account can write and enter
     (`-w` and `-x`); otherwise
     `fail "the backup directory <path> is not writable by this account; give it to this account (see docs/OPERATIONS.md, Kurulum)"`;
   - it does not exist: its nearest existing parent must be writable and enterable; otherwise
     `fail "cannot create the backup directory <path>: <parent> is not writable by this account; create it first (see docs/OPERATIONS.md, Kurulum)"`.
   - Set `bad=1` in both cases, so the preflight refuses before anything is written, as the
     memory check does.
   - Keep the exact wording above (the runbook and the 0.1.1 release notes quote it); `<path>` and
     `<parent>` are the real paths.
2. **The install step:** a failing `mkdir` or `chmod` of the backup directory stops the install
   with `die` and a message that names the directory. Not `&&`.
3. **Runbook:** in `docs/OPERATIONS.md`, section "Operatör hesabı ve yedek dizini", change only
   the sentence that says what happens when the operator cannot create the directory, so it quotes
   the two real messages. Turkish prose, English messages copied from the script (OPS-9 rules).
   Touch no other paragraph and no symptom id.

## Tests (in `test_qradar_dash_installer.py`, through `install` itself)

- An existing backup directory the account cannot write (`chmod 0o500`): `install` exits 1, the
  message is on stderr, and neither `.env` nor `.qradar-dash/` exists.
- A missing backup directory under a parent the account cannot write: same three assertions, with
  the second message.
- `--dry-run` with an unwritable backup directory also refuses and writes nothing.
- A missing backup directory under a writable parent: `install` completes (`flow_path`), and the
  directory exists with mode `0700`.
- The `die` at the install step: make `mkdir` fail for the backup path only after the preflight
  passed (for example a `mkdir` stub in the test PATH that fails for that one argument and
  `exec`s the real one otherwise), and assert exit 1, the message, and **no** state file. If the
  harness cannot reach that line without changing the script's design, say so in the report and
  explain what you pinned instead.
- Restore every permission you changed in a `finally` (or a fixture), so `tmp_path` cleanup works.
- **Root bypasses file permissions.** The 3.12 gate container runs as root, so a permission test
  would pass there for the wrong reason. Mark each permission-dependent test
  `@pytest.mark.skipif(os.geteuid() == 0, reason="root bypasses file permissions")`. They run on
  the host (user `efe`) and in GitHub CI (user `runner`). Say in the report how many skips you
  added.
- Break the check on purpose (remove the new `bad=1`; put `&&` back) and confirm the tests fail;
  then restore.
