# Task T-032 — live discovery: one Ariel search per cadence, many buckets per search

Read `AGENTS.md` at the repository root first. Follow it exactly.

This is a **research task**. Write no application code, and change no repository file except the
report. Its findings decide the design of the **search cadence** feature.

## Why

The user asked for a per-family search cadence (5 min, 15 min, 30 min, 1 h, 2 h, 4 h, 8 h; default
1 h) so the platform stops flooding QRadar with Ariel searches. The families are:
- Phase A volume (`QRadarRestProvider.get_log_source_metrics`);
- WAF collection (the endpoint search and the breakdown searches);
- anomaly explanations;
- rule matches over `creEventList` (T-025, on `agent/t025`);
- operator-defined scheduled searches.

The detectors are tuned for 5-minute buckets. With the defaults (`baseline_min_samples=8`,
`baseline_lookback_days=28`), a 1-hour bucket gives each weekday×hour cell at most 4 samples, so
Phase A would never train. The cadence must therefore be **decoupled from the bucket width**: each
family runs **one** search per cadence tick, and that search returns **every** bucket in the
window, grouped by time. Today the collectors run one search per bucket.

T-027 proved that Ariel accepts
`GROUP BY logsourceid, DATEFORMAT(starttime, 'yyyy-MM-dd HH')`. This task finds out whether the
same works at 5-minute granularity, safely, and at what cost.

## Questions

1. **A timezone-free 5-minute bucket key.** Which of these does Ariel accept as a `SELECT` column
   and in `GROUP BY`, alongside `logsourceid`, `SUM(eventcount)` and `MAX(starttime)`?
   - `starttime / 300000`
   - `FLOOR(starttime / 300000)`
   - any other integer form you find documented

   Is the division integer or floating point? Show the raw values that come back.
2. **The `DATEFORMAT` fallback.** Is `DATEFORMAT(starttime, 'yyyy-MM-dd HH:mm')` accepted? Which
   timezone does it render in: the console's, the user's, or UTC? Prove it against a known epoch,
   for example by selecting `starttime` and the formatted value from the same rows. If it is not
   UTC, explain why it is unsafe across a DST change.
3. **Equivalence.** Pick the best accepted form from questions 1–2. Run one search over a closed
   1-hour window that returns per-source per-5-minute rows. Then run the current per-bucket query
   (the exact AQL in `get_log_source_metrics`, `backend/app/providers/qradar_rest.py`) for **two**
   of those 5-minute buckets. For those buckets, per source, do these agree?
   - `SUM(eventcount)`
   - `MAX(starttime)`

   Explain any difference. Look at the half-open `starttime >= a AND starttime < b` bound at the
   bucket edges.
4. **Cost and shape.** For the multi-bucket Phase A search over **1 hour** and over **8 hours**,
   record:
   - the number of rows;
   - the time to `COMPLETED`;
   - `record_count` and `data_file_count`, if the status reports them;
   - the size of the results payload.

   Does `get_ariel_search_results` need paging (a `Range` header) at that row count? How does the
   provider page today?
5. **`LIMIT` across buckets.** The WAF endpoint and breakdown searches use
   `ORDER BY SUM(eventcount) DESC LIMIT n`. With a time key added to `GROUP BY`, confirm that
   `LIMIT` caps the **whole** result, not each bucket. Say whether any AQL form gives a per-bucket
   top-N. Then pick any source with a custom property or a multi-key grouping, and measure the
   rows from one 1-hour, 5-minute-keyed endpoint-style search. A synthetic WAF source is best;
   use one if the lab has one with events, and otherwise use a stand-in.
6. **`creEventList` by bucket.** Is
   `GROUP BY creEventList, <bucket key>` accepted over a 1-hour window? Record its row count.
7. **Late events.** Over the last 8 hours, how far does `MAX(starttime)` lag behind the wall clock
   per active source? Is there any sign that events land in a bucket after it closes (for example
   `devicetime` far behind `starttime`)? The answer decides how long a multi-bucket window must
   wait after its end before it counts as complete.
