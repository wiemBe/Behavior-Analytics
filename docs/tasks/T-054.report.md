### Defect D-1 (root cause of hours 07–09): the generator never enters the change phase with two profiles

* **Where:** `tools/qradar_lab_loggen.py`. `_scenario_event` (lines 890–892) round-robins the two
  profiles and passes `local_index = index // len(profiles)` to `_ips_event`; `_ips_event`
  (lines 983–987) computes `planned = self.options.count` and
  `transition = max(1, planned // 2)`, then `anomaly = index >= transition`.
* **Arithmetic:** every scenario B run used `--types pan_threat ftd_ips --count 9000`. Each profile
  emits 4500 events, so `local_index` ranges over 0…4499 while `transition` is 9000 // 2 = 4500.
  `anomaly` is therefore False for **every** event of the run.
* **Effect:** the change shapes gated on `anomaly` never begin: `ips-signature-burst`
  (line 1002, `signature_index = 0`), `ips-source-concentration` (line 1000, 70% of events from
  one source), `ips-new-port` (line 998, port 8443) and `ips-block-shift` (line 1006). The pilot
  `ips-port-sweep` (lines 994–997) is *not* gated on `anomaly`, which is why the sweep did change
  shape and was detected.
* **Recorded evidence:** hours 07/08/09 B-run buckets are indistinguishable from baseline:
  `top1_events` 25 of 750 (share 0.0333), `max_distinct_ports` 2, `distinct_sources` 30
  (`ips_source_bucket`); the signature mix stayed 9–10 QIDs at ~75 events each in every bucket
  (`ips_entity_metric`; e.g. burst bucket 07:35 on 412: all 9 QIDs observed 75.0 vs expected ~74,
  ratio 1.01); no `8443/*` entity exists anywhere in the run (SELECT returned zero rows).
* **Classification:** a defect in the lab generator (a repository file), **not** in the Phase D
  application. Every detector was armed when the change would have been judged (hour cells trained
  to 4 reliable samples at t1: entity cells verified in `ips_entity_baseline`, source cells in
  `ips_source_baseline`), and every verdict on the flat traffic it did see was correct. The fix
  belongs to the orchestrator: derive the transition from the per-profile event count
  (`planned // len(profiles) // 2`) or pass the per-profile planned count into `_ips_event`.

### Defects and limitations (classified)

**Defects**
- **D-1 (lab generator, repository file `tools/qradar_lab_loggen.py`)** — with two `--types`
  profiles the per-phase transition index is computed from the total `--count`, so the anomaly
  half of every phase-gated IPS scenario never runs. Full statement above. This voided the
  signature-burst, source-concentration and new-port scenarios of this run (and would void
  block-shift). It is a tooling defect; no Phase D detector, engine, pipeline or baseline behaviour
  contradicted §D.6–§D.8 or §D.12 anywhere in the recorded data.

**Limitations of the run (not defects)**
- **L-1: 24 h / 7 d port-history rule.** `ips_new_port_history_days=7` (2016 buckets; `ge=1`, so
  24 h minimum) cannot be satisfied by a several-hour run. Observed as INSUFFICIENT_DATA inside
  the novelty window (buckets 06:20–07:15). Recorded at 06:28Z; stands.
- **L-2: shortened baseline settings (strategy B).** `BASELINE_MIN_SAMPLES=4` only; every judging
  cell reached exactly 4 samples at its hour's t1 tick. No threshold, ratio, floor or lifecycle
  setting was changed.
