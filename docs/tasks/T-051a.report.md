## What I did

The inherited enum, plain observation shape, threshold set, evidence structure, detector math
scaffold and most capability declarations were sound and were kept. The sparse-row implementation
already had the required core rule; I retained it and pinned every condition independently:
missing rows become zero only for an active, already-admitted entity under exact measurement,
coverage at the floor and explicitly non-truncated admission. Present rows in lower-bound
dimensions remain lower bounds.

I changed the inherited implementation where it diverged from the binding design:

- Split the 1,039-line detector into two focused modules (548 and 597 lines).
- Allowed an optional protocol represented as `unknown`; only port `0`, protocol `255` and malformed
  port keys fail closed.
- Added the destination-port population requirement and coverage guard to fan-out detection.
- Imported WAF's expected-band helper instead of carrying separate band fallback math.
- Kept overall scope separate from the observed fan-out measurement so evidence never labels an
  exact maximum as a lower-bound count merely because another precondition narrowed the verdict.
- Withheld contributor shares for lower-bound or unavailable contributor searches.
- Made `IPS_BLOCK_RATIO_SHIFT` return the exact required reason, `no action property mapped`.
- Removed the source/novelty detector copies from `detector.py` after moving them to `behavior.py`,
  plus the imports made redundant by that split. No inherited detector behavior was discarded.
- Removed the one new mypy error in `IpsSourceBucketFacts.of`; no WAF annotation widening was
  necessary.

All seven pure detectors now return `AnomalyEvidence[IpsAnomalyType]`, fail closed for maintenance,
unknown or low-coverage inputs and incompatible/thin baselines, and derive lower-bound scope only
from capability declarations. Entity spikes, fan-out, block ratio and novelty can prove an
increase from a permitted lower bound but cannot return `NORMAL` from it. Concentration requires
both share inputs exact. Port history verifies presence, width, exact discovery, coverage,
admission, profile, normalizer and maintenance per bucket. Every IPS capability remains explicitly
`NOT_SCHEDULED` with an operator-readable limitation.

Five deliberate break checks were performed and then restored:

1. Treating unrecorded admission as non-truncated failed the absence-rule test: 1 failed, 6 passed.
2. Allowing a normal exit from `INCREASE_ONLY` failed all three entity lower-bound tests: 3 failed.
3. Disabling the current-bucket maintenance guard failed all three source-detector tests: 3 failed.
4. Disabling the history maintenance guard failed its history case: 1 failed, 9 passed.
5. Disabling the coverage guard failed the fan-out destination-port coverage test: 1 failed.

The restored focused suite passed 182 tests.
