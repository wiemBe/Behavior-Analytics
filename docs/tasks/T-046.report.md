## 2. What I did
- Capacity history stored only on a new `capacity_timestamp` (PK conflict does nothing, so first values are kept); null timestamp never offered; one statement per batch.
- Statistics: counts; window block (expected/complete/truncated/failed/missing windows, `complete`, `reason`); `silent` only for EXACT evidence (EVENT incl. EVENT BBs, SQL mirrors `match_evidence` on case/padding), enabled, and only if the span is complete via the same `assess_coverage` rule health uses; otherwise null with a reason. COMMON/FLOW/OFFENSE/unknown are counted per type in `excluded` with the reason. Top lists by `match_records` / `matched_events`, `lower_bound` set for any non-EXACT type (COMMON in practice). Benchmark section: lowest non-zero `average_capacity` of enabled rules, zero/null counted in `no_benchmark_count`, labelled as QRadar's benchmark (not a firing rate) with unit.
- Match sums and rates count only COMPLETE windows (joined on `rule_match_window`); rate = matched events / `measured_seconds` (equals the span when complete). A partly collected span therefore never reads as a low rate; the top lists then still show with the partial-coverage reason. No complete window gives null lists.
- Constant SQL: 7 queries max regardless of rule count (counts, ever-collected, windows, silent, 2 tops, benchmark x2), pinned at 20 vs 600 rules.
