## 2. What I did

The platform stays read-only against QRadar. Evaluation reads stored buckets only. No Ariel search is sent. Raw paths, action values, response codes, and source addresses stay inside the fold. A breach's `details` holds the metric, unit, operator, threshold, subject kind, and a truncated subject label.

**Catalog.** Ten metrics. `EXACT_ONLY`: `event_count`, `average_eps`, `total_events`. `LOWER_BOUND_PROVES_INCREASE`: fleet `eps`, `request_count`, the three WAF ratios, IPS entity `events`, and `blocked_share`. Ratios are `block_ratio`, `server_error_ratio`, `client_error_ratio`, and `blocked_share`. The loader key is the subject kind. An import-time check in `evaluate.py` raises if the interpreters and the catalog diverge.

**Validation.** Pure, no database. It returns every reason at once: subject-column pairing, metric belonging to the kind, `source_class` a known `SourceClass`, operator in `GT`/`GE`/`LT`/`LE`/`EQ`, sustain and recovery at least 1, ratio thresholds strictly inside `(0, 1)`, and the enabled cap. The cap message names the limit and the current count: `at most {max} rules may be enabled at once ({count} already are)`. A rule that is already enabled keeps its slot. A disabled draft never trips the cap. The API that returns 409 is F-3.

**Loaders.** One statement per kind that has an evaluable rule, windowed by `bucket_start > watermark` and `bucket_start <= latest closed`. Empty id lists are not executed. Fleet EPS is `SUM(event_count) / SUM(bucket_seconds)` over `COMPLETE` rows of sources that are both enabled and `monitoring_enabled`, classed by `coalesce(source_class, UNCLASSIFIED)`. A disabled source cannot inflate the rate or the expected count. The rate is `EXACT` only when every monitored source of the class is complete. IPS entity metrics are one statement; the dimension's measurement column is chosen in Python.

**Fold.** Sustain opens on the bucket where the streak is met. Recovery resolves only after `recovery_buckets` consecutive exact unders; one under enters `RECOVERING` and emits no alert event. A later breach during recovery returns to `OPEN` and emits `refresh`. Unmeasured counts toward neither counter and is recorded on `unmeasured_buckets` only while a breach exists. Maintenance pauses the same way and does not open, refresh, or resolve, and does not increment `unmeasured_buckets`. `LOWER_BOUND` with `GT`/`GE` counts toward the breach and never resolves it. `LOWER_BOUND` with `LT`/`LE`, and any `LOWER_BOUND` on an `EXACT_ONLY` metric, is insufficient. Ratios need an exact positive denominator; an unmapped remainder makes the numerator a lower bound. A missing metric row is unmeasured, including a WAF exact sparse absence, and is never stored as zero. Re-evaluation skips `bucket_start <= last_evaluated_bucket_start`. `EQ` is numeric equality. An unknown operator or a non-finite threshold produces no verdict and does not resolve. Verdict scope comes from the catalog through `verdict_scope` in `app/waf/measurement.py`.

Rule statuses, all of which fit `String(16)`: `NOT_ENABLED`, `SUBJECT_RETIRED`, `DISABLED`, `NOT_COLLECTED`, `OPEN`, `RECOVERING`, `OK`, `NO_VERDICT`. `INSUFFICIENT_DATA` is a bucket outcome, not a rule status. An idle tick preserves the previous status. A halt (disabled, retired, family off, platform off) preserves counters and the live breach and does not move `last_evaluated_bucket_start`.

**Beat.** `evaluate_custom_rules` returns `{"status": "disabled"}` before it opens a session while `custom_rules_enabled` is false (the default). The first enabled run seeds each kind that has an evaluable rule at `latest_closed_bucket` and judges nothing, including buckets already stored at or before that point. Later runs walk observed collected buckets after the watermark, up to the latest closed bucket, at most `custom_rules_max_buckets_per_run` (default 288). Aligned gaps between observed buckets are filled as unmeasured. An empty grid up to now is not invented. The engine writes breach rows and rule state, then calls the sink, then flushes. The default sink is a no-op. Sink errors are not caught, so the tick rolls back. The task commits after a successful run.

Family off is `NOT_COLLECTED` and names the setting (`waf_collection_enabled` or `ips_collection_enabled`). A retired or missing subject is `SUBJECT_RETIRED`. The retired reason names the timestamp and does not include the path.

**Retention.** `apply_custom_rule_retention` runs daily. It deletes `RESOLVED` rows whose `resolved_at` is older than 180 days, in batches of 5000, at most 20 batches, and skips any row a rule still points at with `active_breach_id`. Live breaches and rows with a null `resolved_at` stay. Rules are not deleted. Each batch commits. A full batch still waiting after the cap is reported incomplete.

Design §F.15 lists the breach retention task under F-2. `docs/tasks/F-1.md` and the task prompt put §F.10 in this task, and that is the copy implemented. `search_result_metric` retention is F-4 and was not built.

### Bound

A kind is stale when `closed - watermark` is **greater than**

`cadence + bucket + settle + 60 seconds`.

A lag equal to that bound is still inside the time collection can take. One second more is stale.

- `cadence` is the search-cadence row for the kind's family. `LOG_SOURCE` and `FLEET_CLASS` use `PHASE_A_VOLUME`, because fleet EPS is summed from Phase A `log_source_metric` and there is no fleet family. `WAF_ENDPOINT` uses `WAF_COLLECTION`. `IPS_ENTITY` and `IPS_SOURCE` use `IPS_COLLECTION`. A missing row is the migration seed, `SearchCadence.ONE_HOUR` (3600), not the 8 h ceiling. The evaluator does not insert that seed.
- `bucket` is `collection_interval_seconds` (default 300). Phase A, WAF and IPS all bucket on that width.
- `settle` is `search_cadence_settle_seconds` (default 120).
- `60` is the catalog lateness tolerance: a run is due `cadence + settle` after the previous one, and it is late only beyond 60 s, because the scheduler ticks once a minute (`frontend/src/components/catalog/derive.ts`).

The first three terms are the documented detection delay, `cadence + bucket + settle` (design F.1.3, `worstCaseDelay`, `docs/SEARCH-CADENCE.md` §SC.8). The minute is the same margin that lateness rule already uses. At the defaults the bound is 4080 s (1 h 8 min). At the 8 h cadence it is 29280 s. The cadence is read once per tick, and only for kinds whose grid is empty, so the statement count stays constant in the number of rules.

A search that runs for the default Ariel timeout (300 s) still finishes inside this bound. A search that runs to the 900 s maximum can be marked stale for one tick; the next tick judges the rows it wrote.

### Status and freshness

The status is `STALE`, not `NO_VERDICT`. `NO_VERDICT` already means a bucket was judged and proved nothing, and the fold only uses it when there is no live breach. `STALE` is 5 characters and fits `String(16)`. The reason is the sentence the review asked for, for example `no bucket collected for this kind since 2026-10-16 08:55 UTC (3 h 10 min)`. The timestamp is the watermark. The age is the wall-clock age of that bucket, and it is rewritten on each stale tick.

Every evaluable rule of the kind gets `STALE`. A disabled, retired or family-off rule keeps its own status. An open or recovering breach stays in that state: counters do not move, `unmeasured_buckets` does not move, and the alert seam is not told to resolve. The watermark does not move, so the backlog is judged when rows return.

`last_evaluated_at` is left unchanged on any tick that judged no bucket: the seed, a gap still inside the bound, and a stale kind. No new column. A later reader treats `last_evaluated_at` as "buckets were judged at T" and `last_status` plus the reason as the current honesty. `STALE` with an old `last_evaluated_at` is "nothing to evaluate since T". A recent `last_evaluated_at` is "evaluated now". The row's `updated_at` can still move, because the status write is a real update; evaluation freshness is `last_evaluated_at`.

A log source with no row, while another source of the same kind has one, stays the per-bucket unmeasured path. It is `NO_VERDICT` with `no row for this subject in the bucket`, the kind watermark still advances, and `last_evaluated_at` does move, because those grid points were judged. That case is now pinned.
