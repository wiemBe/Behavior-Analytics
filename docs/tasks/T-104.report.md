## 3. Why none of the flagged candidates is a real defect

Each "real defect" candidate the task named was traced to its guard:

**(a) `get_ariel_search_status(<str \| None>)`, `_safe_cancel(<str \| None>)` —
`search_executor.py:191,197`.** `execute()` retries by calling `_run_once()` afresh, and
`_run_once()` calls `create_ariel_search()` and assigns `execution.ariel_search_id =
handle.search_id` (`ArielSearchHandleDTO.search_id` is a plain `str`) on line 162, then just
flushes before `_poll_until_terminal`. The attribute is `str | None` only because the row is
created before the search is (the column is nullable in `models/search.py:142`); no path reaches
the poll with `None`. A `None` can therefore never reach a provider call. To keep the guarantee
visible in the types, the created id is bound to a local `search_id` and passed to
`_poll_until_terminal(search, execution, search_id)`, which passes it to both the status call and
`_safe_cancel`. Same id, same calls, same rows.

**(b) `reversed(list[str \| None])` — `engine.py:387`.** `_recent_signatures` selects
`LogSourceMetric.payload_signature` filtered by `.is_not(None)`, so a NULL can never be in `rows`;
the declared `-> list[str]` was already true. The comprehension keeps the SQL predicate's
guarantee explicit in Python (defence in depth) and changes the result only in the case the query
forbids.

**(c) `record_audit(object_id=<UUID>)` — `alerts.py`, `searches.py`.** `record_audit`
(`repositories/audit.py:30`) does `str(object_id) if object_id is not None else None` before
persisting to the `String(128)` column, and every reader compares against `str(...)`
(`routes/ips.py:447`, `routes/waf.py:406`). So the UUID never reaches storage as a UUID and no
comparison can mismatch: the annotation `str | None` is simply narrower than the function accepts.
Passing `str(uuid)` at the call site is a no-op relative to what `record_audit` already does. The
alternative — widening `record_audit`'s parameter — would have been the cleaner single fix, but that
file is not named in the mypy output and so is outside the allowed file list (AGENTS.md §1); I
did not touch it.

Because there is no real defect, no new test was required and none was added: every change is a
no-op at runtime, and I did not want to add a test that pins a behaviour the code already had.

Break-its: because there is no failing-on-old-code test to write for a typing fix, the break-it
discipline was applied to the gate itself — each fix was reverted and the corresponding mypy error
was confirmed to return, then the fix was restored.
