## 2. Built-in rule updates must reach existing installs

release that fixes a built-in pattern (like item 1) never reaches a database where the rule
already exists.

Operators may only **enable or disable** a built-in rule (design §C.3 and §C.5). So the seed must:
- upsert the definition fields (`kind`, `pattern`, `target_class`, `priority`, `description`)
  on conflict, **where the row is `built_in`**;
- preserve `enabled`.

sync, carries the new pattern and is still disabled.
