## 2. What I did

- Implemented every §FM.4 route under the existing `admin:waf` router. Property names and action
  maps still pass through `WafFieldMapping`; no frontend AQL is accepted and no QRadar write was
  added.
- Added optimistic concurrency with row serialization, create/update status codes, safe 409/422
  errors, idempotent enable/disable, and mapping-change versus label-only behavior. Create and
  mapping changes reset validation, mark it pending, audit the authenticated subject and enqueue
  exactly one task call. Label-only and unchanged writes do not enqueue or bump the version.
- Declared the seven WAF field labels/descriptions once beside `WafFieldMapping`. The schema route
  supplies settings-derived defaults and turns empty settings into null.
- Added bounded, one-query candidate selection with literal `%`/`_` matching and WAF-first class
  ordering, plus the bounded newest-first audit history query.
- Projected stored validation reports through a typed response that omits both `total_query` and
  every per-field `queries` list.
- Added asynchronous validation using the collection pipeline's per-source advisory lock. The
  worker validates without mutating the row, re-reads it `FOR UPDATE`, stores only a same-version
  result, requeues locked/stale work, clears pending state on failure, audits only the exception
  class, and always attempts to close the instance provider.
- Preserved the CLI's existing synchronous `WafProfileService.validate(...)` behavior and default
  product-label semantics.
- Per the required mutation check, temporarily removed the post-validation version comparison.
  `test_worker_discards_stale_version_and_requeues` failed (`ok` instead of `stale_requeued`), then
  the guard was restored and the test passed.
