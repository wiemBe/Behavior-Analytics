## What was built
Query is separate from value. Opening shows the whole list with the current value marked ("current", aria-selected) and scrolled into view. Typing filters; Escape restores the previous value; Tab/blur keeps typed free text. Search is case-insensitive, tokens split on space, underscore, hyphen and camelCase, so "resp code", "responsecode" and "waf resp" find WAF_ResponseCode. Matched characters are bold and underlined (no new colour). Groups: QRadar normalized fields, Applies to this source type, Other source types, Type unknown. The count line ("7 of 119 properties match") is a polite role=status region. No match says so and that the typed name can be used and validation checks it. Not-selectable names are visible, marked, skipped by arrow keys, and cannot be chosen. No cap; the list scrolls inside itself with sticky group headers. Unavailable or empty catalog: plain input, no listbox. No suggestion logic was added.
Design choices: opens on click, typing, or Down (not on Tab focus, to avoid popups while tabbing through fields). The field text is selected on focus so typing replaces it. Home/End move through the list only once an option is active; before that they move the text cursor. Option aria-label carries the whole name (the highlight marks otherwise split it).
