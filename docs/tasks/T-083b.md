# Task T-083b — one schema reset for every migration test file

Read `AGENTS.md` at the repository root first and follow it exactly. Tests only: no file under
`backend/app/` or `backend/alembic/`.

## Why

T-083 (merged; read `docs/tasks/T-083.report.md` in full) proved why the migration tests error
at setup now and then. `DROP SCHEMA public CASCADE` takes `AccessExclusiveLock` on every `public`
relation, and the TimescaleDB **Telemetry Reporter** background worker reads those relations at
the same moment. PostgreSQL resolves the cycle as a deadlock, and when the fixture is the victim
the test errors at setup.

T-083 fixed `clean_db` in `backend/tests/integration/test_migrations.py` only: it terminates the
other sessions on its own test database and waits for them to go before the drop. The same drop,
without that fix, is in eleven more files. Under load T-083 saw it fail 12 times in 271 passes.

The eleven files:
- `test_migration_0012.py`, `0013`, `0014`, `0016`, `0017`, `0018`;
- `0019`, `0020`, `0021`, `0022`, `0023`.

## Build

1. A new helper module, `backend/tests/integration/schema_reset.py`. It must not be named
   `test_*`, so pytest does not collect it; it sits beside `factories.py`. It holds one
   function, `reset_public_schema(sync_url: str) -> None`, which does exactly what T-083's
   `clean_db` does today, in the same order:
   - terminate every other session on **this database only**;
   - wait (bounded, as T-083 does) for those PIDs to be gone, committing between polls,
     because `pg_stat_activity` does not refresh inside an open transaction;
   - `DROP SCHEMA public CASCADE` and `CREATE SCHEMA public` in one transaction;
   - dispose the engine.

   Move T-083's comment with it, so the reason stays next to the code.
2. `test_migrations.py` and the eleven files above: in each `clean_db`, replace the
   drop/create block with a call to `reset_public_schema(sync_url)`. Everything else stays as it
   is in every file: the fixture's name, its scope, its return value, anything it does besides
   the drop, every test body and assertion, every other fixture.
   - The eleven `clean_db` bodies are not all byte-identical. Read each one and keep whatever it
     does beyond the drop.
   - If one does something that conflicts with the helper, stop and report it rather than
     changing it.
3. Never change the server configuration, the compose file or `conftest.py`.

## Tests

- A new integration test, `backend/tests/integration/test_schema_reset.py`, pins the guard
  directly, because the deadlock itself is intermittent. It:
  - opens a second connection on the test database and reads its backend PID;
  - calls `reset_public_schema`;
  - asserts that PID is no longer in `pg_stat_activity`, and that `public` exists and is empty;
  - asserts that a session on **another** database is never touched. Use the database named in
    the gates below plus `postgres`, read-only: it must only *open* a connection there and check
    it survived.
- Break the guards on purpose, confirm a test fails each time, restore, and list each break in
  the report:
  - drop the terminate step;
  - drop the wait;
  - widen the terminate to every database.
