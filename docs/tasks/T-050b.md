## Build

1. **Migration `0018`** (chained after `0017`) and the models in `app/models/ips.py`:
   - `ips_source_bucket`: a TimescaleDB hypertable on `bucket_start`, PK
     `(log_source_id, bucket_start)`. It mirrors `waf_source_bucket`'s role (read its docstring):
     - totals: events and records;
     - per dimension: the measurement (`EXACT` / `LOWER_BOUND` / `NOT_COLLECTED` / `FAILED` /
       `REJECTED`) and the coverage, which is nullable and never 0 from a missing input;
     - concentration facts: `source_events`, `distinct_sources` (a lower bound flag included),
       `top1_events`, `top5_events`;
     - fan-out: the max distinct ports of one source IP;
     - action: blocked, allowed and unmapped, each nullable;
     - `contributors` JSONB, ≤ 10 per list: source IPs by events and by fan-out;
     - the admission outcome per dimension: `admitted`, `below_admission_threshold`,
       `rejected_over_quota`, `untracked_entities`, `untracked_events`, `admission_truncated`;
     - `profile_version`, `normalizer_version` and `query_provenance` (the T-050a cell
       provenance);
     - `in_maintenance` and `collected_at`.

     The row is written for every collected bucket, even when no entity row is.
   - `ips_entity`: `(instance_id, log_source_id, dimension, value_key)` unique;
     `display_name` (signature name; display only); `first_seen_at`, `last_seen_at`, `active`,
     `retired_at`, `normalizer_version`.
   - `ips_entity_metric`: a hypertable, PK `(ips_entity_id, bucket_start)`, sparse and slim like
     `waf_endpoint_metric`. It holds `events`, `bucket_seconds` and nothing per-bucket that the
     bucket row already has.
   - The `SearchFamily` gains `IPS_COLLECTION`, and a `search_cadence` row is seeded for it
     (default 1 h, the §SC.3 conventions). If `SearchFamily` is stored as a PostgreSQL enum, extend
     it additively.
   - The migration must upgrade → downgrade → upgrade cleanly, `alembic check` must show no drift,
     and a round-trip test is **pinned to its own revision** (see the `0016` and `0017` tests).
2. **Admission** (§D.4). Reuse `app/waf/admission.py`'s pure `decide_admission` and
   `admission_order_key`; generalise them only if no WAF test changes. Apply them per
   `(source, dimension)`:
   - a per-bucket new-entity quota of `ips_max_new_entities_per_bucket` (default 20);
   - an active ceiling of `ips_max_active_entities_per_source_dimension` (default 2,000);
   - `ips_min_admission_events` (default 3);
   - retirement after `ips_entity_active_days` without an observation.

   An entity that is refused creates no row and is **never stored by name**; only counts are
   kept. A `LOWER_BOUND` cell admits from its exact top only, and records that its discovery was
   incomplete.
3. **The collector** — `app/collectors/ips_collector.py` (plus a thin task in
   `app/workers/tasks.py`):
   - One run per claimed `IPS_COLLECTION` slot (`SearchCadenceService.claim_slot`, §SC.4) for
     **every** enabled source whose current version is `VALID`, at once. That is the fleet-wide
     keyed design of §D.5: one plan, one search per group per dimension.
   - The window per source runs from its own watermark (`collection_watermark`, collector name
     `ips_collection`, one per source) to the current bucket boundary. It is bounded by
     `cadence/bucket + collection_max_backfill_intervals` buckets. Sources with different
     watermarks are grouped by window, so a search never spans a bucket a source already has.
   - The tick-wide search budget is `search_cadence_max_searches_per_tick`. On exhaustion the
     collector stops, the remaining cells are `NOT_COLLECTED`, and each source's watermark stays at
     its last contiguous fully collected bucket.
   - **A bucket is committed for a source only when its `TOTALS` cell is `COMPLETE`.** Without
     totals there is no denominator, so the bucket is not written and the watermark holds. A
     dimension that is `FAILED`, `REJECTED` or `NOT_COLLECTED` in an otherwise collected bucket is
     recorded as such, and its coverage is `NULL`. Decide, and document in the report, whether such
     a bucket advances the watermark. The rule must be the one that never turns a missing
     measurement into a zero. WAF's per-breakdown rule is the precedent.
   - Each source holds its pipeline lock `ips_pipeline_lock_key(qradar_id)` (T-049) while its
     buckets are written, so validation and collection never interleave on one source.
   - Maintenance is recorded as WAF does. A source whose profile is not `VALID` for its current
     version is skipped and recorded, never collected.
   - **Constant SQL per run:** bulk loads of entities, one bulk upsert per table per run, and
     retirement as one statement. Pin it with a statement-count test at two fleet sizes (for
     example 2 and 20 sources, and 10 against 400 entities), as the WAF scale tests do.
   - Retention follows WAF's settings pattern (`ips_*_retention_days`), with one retention task.
4. **Gate and beat:** a beat entry ticking every 60 s that claims the `IPS_COLLECTION` slot. It
   sends nothing to QRadar on a lost or early tick. Mirror `dispatch_waf_collection`.
5. **Settings** in `app/core/config.py`, bounded, in the WAF style.

## Tests (pin every guard and exit path)

- Migration round trip and drift.
- Admission: quota, ceiling, threshold, deterministic order, reactivation, retirement, and no row
  for a refused entity.
- Collector:
  - one keyed plan per tick for the whole fleet;
  - a source not `VALID` is skipped;
  - a missing `TOTALS` cell means no bucket and the watermark holds;
  - failed, rejected and not-collected dimensions are recorded and never written as zero;
  - `LOWER_BOUND` propagates;
  - budget exhaustion holds the watermark;
  - two sources with different watermarks;
  - re-collecting a bucket replaces its entity rows;
  - the pipeline lock is held;
  - maintenance.
- Gate: one winner per slot, and an early tick sends nothing.
- Constant SQL at two fleet sizes.
- Retention.
- Break each guard on purpose, see a test fail, restore.
