2. **Model** `SearchCadenceSetting`, table `search_cadence`.
   - Put it in a new `app/models/search_cadence.py`, and register it in `app/models/__init__.py`.
   - Columns exactly as §SC.3: `family` PK; `cadence_seconds` with the CHECK; `last_slot_start`;
     `updated_at`; `updated_by`; the five `last_run_*` columns.
   - Name the CHECK constraint following the project's naming convention.
3. **Migration `0013_search_cadence.py`.**
   - `down_revision = '0012'`. Additive.
   - Seed one row per family with `cadence_seconds = 3600` and `updated_at = now()`.
   - The downgrade drops the table.
   - Write the CHECK list as a literal in the migration; migrations are frozen.
   - Add a test asserting the literal equals `SearchCadence` values, so the two cannot drift.
4. **Setting:** `search_cadence_settle_seconds: int = Field(default=120, ge=0, le=900)`, with a
   comment in the voice of `app/core/config.py`.
5. **Service** `app/services/search_cadence.py`.
   - `slot_start(now, cadence_seconds, settle_seconds) -> datetime`.
     - It is a pure function: `floor(now - settle)` to a multiple of `cadence_seconds`, aligned to
       the epoch and returned in UTC.
     - It rejects a naive datetime.
   - `SearchCadenceService(session, settings, clock)` has these methods:
     - `list()`, and `get(family)`. A missing row is a seed failure: log a warning and treat the
       family as `ONE_HOUR`.
     - `claim_slot(family) -> datetime | None`.
       - It runs the single conditional `UPDATE … WHERE last_slot_start IS NULL OR last_slot_start < :slot RETURNING`
         from §SC.4.
       - If the row is missing, insert the default with `ON CONFLICT DO NOTHING` first.
       - It returns the claimed slot, or `None` when not due.
     - `set_cadence(family, cadence_seconds, *, actor, source_ip) -> SearchCadenceSetting`.
       - A value not in `SearchCadence` raises a dedicated error.
       - An unchanged value is a no-op: nothing written, no audit.
       - A change writes `updated_at` and `updated_by`. It also writes one audit record through
         `app/repositories/audit.py::record_audit`: `action="search_cadence.update"`,
         `object_type="search_cadence"`, `object_id=<family>`,
         `detail={"old": …, "new": …}`.
     - `record_run(family, *, outcome, searches, buckets, splits)` writes the `last_run_*`
       columns. `searches`, `buckets` and `splits` may be `None` when the caller cannot count
       them honestly. They are never defaulted to 0.
     - `next_dispatch_at(row, now)`. The next slot is `max(last_slot_start + cadence,
       slot_start(now))`, or `slot_start(now)` when the row was never claimed. This method returns
       that slot plus settle.

7. **Permissions** (`app/security/rbac.py`).
   - Add `PERM_SEARCH_CADENCE_READ = "read:search_cadence"` and
     `PERM_SEARCH_CADENCE_ADMIN = "admin:search_cadence"`.

8. **API**: a new route module mounted in `app/api/router.py`, with a router-level
   `requires(PERM_SEARCH_CADENCE_READ)`.
   - `GET /admin/search-cadence` returns one item per family, ordered as the enum, with:
     - `family`;
     - `cadence_seconds`;
     - `allowed_cadences_seconds`;
     - `bucket_seconds`:
       - `collection_interval_seconds` for `PHASE_A_VOLUME` and `WAF_COLLECTION`;
       - `rule_match_window_seconds` for `RULE_MATCH`;
       - `null` for `ANOMALY_EXPLANATION`;
     - `settle_seconds`;
     - `last_slot_start`;
     - `next_dispatch_at`;
     - `updated_at` and `updated_by`;
     - `last_run`: an object of the five columns, or `null`.
   - `PUT /admin/search-cadence/{family}` takes `{"cadence_seconds": int}` and requires
     `PERM_SEARCH_CADENCE_ADMIN`.
     - An unknown family gets a 404.
     - A value outside the presets gets a 422.
     - Success returns the updated item.

   - The T-028 guard test (`tests/unit/test_route_auth_guard.py`) must pass with the new routes

## Tests (new behavior needs tests; pin every guard and exit path)

- `slot_start`:
  - alignment for every preset (4 h slots at 00, 04, 08 … UTC);
  - the settle boundary (one second before and at `slot + settle`);
  - a naive datetime is rejected.
- `claim_slot`:
  - due, then not due within the slot, then due in the next slot;
  - a missing row;
  - **two concurrent sessions claiming one slot, where exactly one wins** (integration);
  - after `set_cadence` from 1 h to 4 h, the next claim follows the 4-hour grid.
- `set_cadence`: an invalid value; the unchanged no-op (no audit row); one audit row with
  old/new on change.
- `record_run`: a `None` count stays `NULL`.
- The explanation task:
  - when not due, it returns before any provider call (prove it with a spy or mock);
  - when due, it runs and records the run.
- API:
  - 401 without a principal;
  - a read-only principal can `GET`, and gets 403 on `PUT`;
  - 404 for an unknown family; 422 for a value outside the presets;
  - 200 with the audit row written;
  - `last_run` is `null` before any run.
- Migration: an integration test following `tests/integration/test_migration_0012.py`. It covers
  the round trip, the seed rows, the CHECK rejecting 600, and no drift.
- After writing each guard test, break the code on purpose, see the test fail, then restore it.
