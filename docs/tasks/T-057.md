## Build

1. **Unified anomaly list and detail** (`app/api/routes/anomalies.py`, `app/schemas/anomaly.py`,
   `app/repositories/anomaly.py`), exactly as §27.14 — **additive only**:
   - `AnomalyListItem` / `AnomalyDetailOut` gain `subject_kind` (`"LOG_SOURCE" | "WAF_ENDPOINT"`,
     a `str` enum in the schema module — not a DB enum, nothing persisted) and `waf_endpoint`
     (`{id, normalized_endpoint, http_method, virtual_host | null, virtual_host_available,
     normalizer_version} | null`). `log_source_id` stays required (for a WAF subject: the WAF log
     source). `anomaly_type` accepts `AnomalyType | WafAnomalyType` (a WAF row's
     `detector_type`).
   - `GET /api/v1/anomalies` gains `subject_kind` and `waf_endpoint_id` filters. Without
     `subject_kind`, the list returns **both** kinds in one ordering (the existing order), with a
     correct `total`, through **one** `UNION ALL` query (plus at most one name/endpoint resolution
     query) — never a query per row, never two full lists merged in Python. Every existing filter
     keeps its meaning; a filter that cannot apply to a kind (e.g. `evidence_status` if WAF has
     none, or a Phase A-only `anomaly_type`) excludes that kind rather than being ignored. State in
     the report exactly which filters apply to which kind.
   - `GET /api/v1/anomalies/{id}` resolves a WAF anomaly id too. Its `detection` gains a WAF
     projection (observed and expected requests or ratio, coverage, normalizer version) through the
     same explicit whitelist as Phase A (`detection_detail`) — never a raw `details` dump.
     Transitions come from `waf_anomaly_transition`. Phase A-only sections (explanation, baseline
     cells keyed by weekday/hour of the log source) are `null`/empty for a WAF subject, not faked.
   - `/anomalies/summary` and every existing Phase A response stay **byte-identical** for Phase A
     rows (new fields aside). Existing tests must pass unchanged.
2. **WAF behavior routes** under the existing `behavior_router`, all `GET`, behind
   `read:anomalies`, paginated (`limit` ≤ `api_max_page_size`) and range-bounded by
   `api_max_range_days` (reuse `_validate_range`):
   - `/behavior/waf/sources` — per WAF source: profile status (enabled, version, validation status
     for the current version), latest coverage, active endpoints against the ceiling, admission
     overflow in range;
   - `/behavior/waf/sources/{log_source_id}` — one source plus its last validation report,
     **counts only** (no `queries`, no value lists beyond the bounded ones already stored);
   - `/behavior/waf/sources/{log_source_id}/endpoints` — paged endpoint inventory: baseline
     adequacy, last seen, retired, current state;
   - `/behavior/waf/endpoints/{id}/metrics` — buckets in range with completeness and coverage;
     `NULL` stays `null` (never 0); `PARTIAL` buckets flagged;
   - `/behavior/waf/endpoints/{id}/baselines` — cells, reliability, versions.
   404 for an unknown id. One query per route, or a small constant number.
3. Add every new route to the existing GET-only / route-auth guard tests (they walk the app; add
   only what they require). Do not change the guard logic.

## Tests (pin every guard and exit path)

- Mixed list: Phase A and WAF rows interleaved in the right order across pages; `total` exact;
  each filter on each kind (including the "filter excludes the kind" rule); `subject_kind`
  filter; `waf_endpoint_id` filter; `anomaly_type` with a WAF type returns only WAF rows.
- Detail: WAF anomaly with the WAF projection and transitions; Phase A detail unchanged; unknown
  id 404.
- No raw values: a WAF detail and the source report contain no `queries` key and no field outside
  the whitelist (assert the key set).
- Unmeasured: a bucket with NULL coverage/requests serializes as `null`.
- Range and page limits: 422 beyond `api_max_range_days`; `limit` clamped.
- 401 without a principal; 403 without `read:anomalies` (follow the existing pattern).
- Constant SQL: statement count for the list at two sizes (e.g. 5 and 60 mixed rows) is equal
  (follow the counting pattern in `tests/integration/test_fleet_api.py`).
- Break the union ordering, the filter-exclusion rule and the whitelist on purpose; see tests
  fail; restore.
