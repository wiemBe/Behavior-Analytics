## Build

For each untested file, a test beside it (in the route's existing `page.test.tsx` only if that file
already groups its `loading`/`error` tests that way; otherwise a new `loading.test.tsx` or
`error.test.tsx`). Follow the existing ones, for example `app/rules/statistics/page.test.tsx`
(which imports `./loading` and `./error`) and `app/fleet/` and `app/admin/outage-policy/`.
- `loading.tsx`: it renders the page's heading or skeleton as it does today, exposes a busy state
  to assistive technology if it does (`aria-busy`, a status role, or visually hidden text), and
  shows no data, no zero and no "No results" text.
- `error.tsx`: it renders what failed and what the analyst can do, as the file does today; the
  `reset` button (if any) calls the `reset` prop; the error's message or digest is shown only as
  the file shows it today. Assert the file's own words.
- **Defects are not asserted as correct.** If an error file says something vague ("Something went
  wrong", which §3a bans), has no recovery action, or a loading file shows a zero, write the
  correct behaviour as `it.todo("…")` and list it in the report. Do not fix any file.
- **Break-it:** for each test file, change one rendered word in the component, confirm a test
  fails, restore.
