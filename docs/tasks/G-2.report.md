## 2. What I did

- **Provider.** The AQL selects only `GEO::LOOKUP(<field>, 'country', 'iso_code') AS "geo"`, `starttime / <bucket_ms> AS "k"` and `SUM(eventcount) AS "events"`. It groups by the first two and orders by `SUM(eventcount) DESC`. It is bounded by `WHERE starttime >= … AND starttime < …`, uses the padded `STOP` (`_ariel_scope`) and `LIMIT cap + 1`. The address field comes from a direction-keyed constant, never from a caller. No address is selected.
- **Fold.** `json.loads` runs inside a guard. A two-letter ASCII uppercase `country.iso_code` is a country. `{}` or an object with no `country` is UNRESOLVED. Anything else is UNPARSEABLE, logged as "N distinct unparseable key(s)" only. Several strings for one code are summed. The top 64 per (bucket, direction) are kept (ties by code), and the rest go to OVER_CAP.
- **Driver.** It halves the time window first. At one bucket a truncated result is LOWER_BOUND. A failed or rejected search marks its buckets with no row (the error text is dropped). One `IpsSearchBudget` (`search_cadence_max_searches_per_tick`) is shared by both directions in a run. Buckets it never searched are NOT_COLLECTED and get no row. Each direction's watermark (`geo_countries_source` / `geo_countries_destination` in `CollectionWatermark`) holds at the last contiguous measured bucket.
- **Writes.** A run does one DELETE of the re-collected buckets (so a country that left the top list leaves no stale row), then one chunked bulk upsert (3000 rows per statement, 10 columns, under asyncpg's 32767 parameter limit). Statements per run are constant up to 3000 rows. A measured bucket with no events at all, or with only unresolved events, stores a single UNRESOLVED row. That row is what marks it measured.
- **Model and migration 0022.** `geo_country_bucket` is a hypertable with all the columns in the spec. `country_code` is CHAR(2), and `measurement` is EXACT/LOWER_BOUND. CHECKs cover: direction; remainder_kind; the `^[A-Z]{2}$` code; exactly one of code and remainder (`(country_code IS NULL) <> (remainder_kind IS NULL)`); measurement; bucket_seconds > 0; events >= 0. The FK to `qradar_instance` cascades. The raw JSON string is never stored; a test dumps every row as text and finds no key.
- **Uniqueness construction (chosen).** A STORED generated column `slot = COALESCE(country_code, remainder_kind)` is part of the primary key `(instance_id, bucket_start, direction, slot)`. It works with the nullable pair and with the hypertable. `ON CONFLICT` can name it, and there is no expression index to drift in `alembic check`. The alternatives were an expression unique index or two partial indexes.
- **API.** `GET /geo/countries?since&until&direction`. The range is required and must be tz-aware, `since < until` and within `api_max_range_days`; otherwise 422. Two statements per request: one aggregate and one coverage count. Per-country `{country_code, events, share}` is sorted by events then code. `share` is over country events only. `remainders`, `measurement`, `coverage`, `status` and the fixed `unresolved_note` are included.
  - `expected_buckets` counts only settled buckets (`now - search_cadence_settle_seconds`), per instance with rows.
  - Status is NOT_COLLECTED (no row in range), INSUFFICIENT_DATA (rows, zero country events), PARTIAL (measured < expected) or OK.
- **Permission.** `read:geo`, satisfied by `read:*`. `read:fleet` alone gets 403.

   - The split driver is in `geo_collector.py`, not a new `app/geo/keyed_search.py`.

5. **API `measurement` when NOT_COLLECTED.** It is `EXACT`, following the spec text ("LOWER_BOUND if any bucket in range is, else EXACT"). With no rows that is not a claim of measurement; the UI should key on `status`. Making it null would be a spec change.
6. **A measured, completely empty bucket stores `UNRESOLVED events=0`.** A window with no events at all therefore reads as INSUFFICIENT_DATA (fail closed), not "no foreign traffic".
7. **Shared search budget.** The per-tick cap is shared by the two directions, SOURCE first. A run that splits heavily on SOURCE can leave DESTINATION buckets NOT_COLLECTED. They are retried next tick, because their watermark held.
8. **`expected_buckets` uses the current `collection_interval_seconds`.** Rows collected under a different bucket width would be miscounted.
