## What I did

Inherited work was the `api.ts` additions above. They match F-4: `POST /searches` creates, `PATCH /searches/{id}` updates, and an enable/disable patch whose only field is `enabled` is audited as `search.enable` or `search.disable`. `runSearch` already POSTed `/searches/{id}/run` with no body. I kept that surface and built the UI on it.

The editor is on `/searches/new` and on `/searches/[id]` for a caller whose `/me` permissions include `search:write` or `admin:*`. A failed `/me` hides the editor and says the permissions could not be read. Copy names admin and `detection_engineer` as the roles that can grant `search:write`. That role is still absent from `backend/app/services/seed.py` (admin, analyst, viewer). This task does not add it.

Create sends `enabled: false` and then opens the saved search. Edit sends the update without `name` or `enabled`. An unchanged query says the version stayed the same. A changed query says it was saved as the new version. Run now is `POST /searches/{id}/run` on the stored draft. The new page has no Run now until the search exists.

Schedule offers the seven presets from `docs/SEARCH-CADENCE.md` (5 min, 15 min, 30 min, 1 h, 2 h, 4 h, 8 h). A new search defaults to hourly (`0 * * * *`). A stored cron that is not a preset is labeled Custom and is submitted unchanged, including after the analyst picks a preset and comes back.

A 422 body whose `detail.reasons` is a string list renders under the AQL field, each reason as sent. The cron-floor 422 string renders beside the schedule control. A 409 whose detail contains the enabled-search limit shows that string and "Disable another search, then enable this one." Guardrails refuse a timeout outside 1–900 seconds, a window outside 1–168 hours, or a row cap outside 1–10000 before any request. Defaults are 300, 24, and 10000. An empty threshold value is stored as null.

The latency sentence of §F.12 is the constant `SEARCH_LATENCY_STATEMENT`, rendered once, inside the editor:

> Rules are judged on collected 5-minute buckets, up to about an hour after the events arrive. This is not a real-time correlation engine — for alerting within seconds, use QRadar's own rules.

The catalog does not repeat it. The version diff is a second `CodePanel` of plain text (`- `, `+ `, `  `). Equal queries omit it. Visualization offers table, line, bar, and single value. A stored pie or heatmap stays selectable and is sent back unchanged.

Honesty for the latest run: a truncated count is a lower bound ("at least N"); a truncated missing count is not shown as zero; a completed zero is a measured zero; a completed missing count is unmeasured; failed, timeout, and cancelled show `error_type` as sent. The searches-list empty sentence and the never-run sentence stay in their own paragraphs.

Break-it (`/home/efe/Documents/QRadar-Dash-work/f5/break-it.py`, log `break-it.log`) broke eight guards, confirmed each pinning test failed, and restored the file from its backup. The script logs a restore only when the restored text differs, and the log has no such line. No `.breakbak` file remains. The eight failures were: hidden 422 list, custom cron rewritten to `0 * * * *`, create with `enabled: true`, cap copy that dropped "the limit is 25 enabled searches", editor shown without `search:write`, truncated 500 rendered as a measured return, run POST body carrying AQL, latency sentence removed.
