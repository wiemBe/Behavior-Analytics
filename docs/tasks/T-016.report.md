## 2. What you did

- WAF alert fingerprints use condition family `waf_anomaly`, so Phase A rules limited to
  `alert_types={"anomaly"}` do not match them. Identity includes instance, log source, virtual host,
  normalized endpoint, method, normalizer version, and detector type; it never uses endpoint ID.
- With `waf_alerting_enabled=False`, WAF lifecycle processing is unchanged and writes no alerts or
  notifications. With it enabled, only OPEN and RESOLVED transitions notify. A still-anomalous OPEN
  incident refreshes evidence and occurrence count without notification; maintenance suppresses
  both opening and refresh.
- WAF alert title, evidence, incident IDs, endpoint source link, and all required routing/context
  fields are populated. Each detector owns a distinct fingerprint and resolves independently.
- Alert actions are collected synchronously while detector state is folded, then applied in one
  async phase. The active-alert loader uses one PostgreSQL array query, avoiding both per-endpoint
  queries and bind-count growth. Existing refreshes flush as one batched update.
- Scheduled WAF execution accepts and forwards an enqueuer, and the Celery WAF task constructs the
  same enqueue-only dispatcher pattern used by Phase A.
- Measured scale counts:
  - no transitions: alerting off = 4 statements at both 40 and 800 endpoints; alerting on = 4 at
    both 40 and 800 endpoints;
  - every endpoint holding an open incident and alert: refresh = 8 statements at both 40 and 800
    endpoints;
  - one transition with one matching notification route: OPEN evaluation was 14 statements versus
    7 in shadow mode, an alerting cost of 7; RESOLVED was 12 versus 7, a cost of 5.
- Required mutation check: removing the maintenance refresh guard made
  `test_maintenance_neither_opens_nor_refreshes` fail because occurrence count rose from 1 to 2.
  Restoring the guard made the test pass.

## 4. Open points

- A source-wide event can open one alert per affected endpoint and detector, and each alert creates
  one notification per matching route. Endpoint admission limits, hysteresis, and default-off
  shadow mode bound or delay this, but there is no source-level notification coalescing or burst
  cap. A broadly correlated WAF event can therefore create an alert storm; operators should stage
  thresholds and routing in shadow mode before enabling paging. Coalescing would be separate design
  work because it changes the fixed per-endpoint/per-detector alert identity.
