## 5. Contract questions

1. `GET /fleet/sources` has no name or text filter, and no monitoring flag. The picker loads the first 1000 sources once and searches client-side (and says so when `total` is larger). A `q` parameter would make it exact. Disabled sources are listed with "disabled"; whether a source is monitored is unknown to the UI.
2. `ClassSummary.sources` counts enabled sources, not monitored ones. For a class without a row the "Sources covered" figure is `enabled - outage_overrides`, labelled "enabled". A monitored count in the summary would remove that caveat and make the impact numbers uniform.
3. The default silence grace (`anomaly_silence_grace_buckets`) is not exposed, so "Default" cannot be shown in buckets or minutes, and the impact text says "the default grace".
4. The default mode is read from the first class without a row in the summary (`outage_mode`). If every class has a row it is unknown, and the removal impact says so rather than guessing. A top-level `outage_default` in the summary would fix it.
5. `OutagePolicyOut` has no instance name, only `instance_id`; the badge shows its first 8 characters. An instance-scoped class row shows no covered count, because `governed_monitored_sources` is computed per class, not per instance.
6. A 422 from PUT arrives as a list of `{msg}` objects with `loc`; `detailText` drops `loc`, so the UI treats every 422 as concerning the grace field (the only user-editable numeric field).
