Sync uses `admin:*` rather than a dedicated `admin:inventory`: it is an administrative action that loads QRadar, and no role other than admin needs it, so a new permission would be held by nobody else.

Role/permission matrix (seed):

| Role | Permissions | read:* routes | log_source PATCH | sync |
|---|---|---|---|---|
| admin | admin:*, search:execute/write, alert:ack/resolve, log_source:write | yes | yes | yes |
| analyst | read:*, search:execute, alert:ack/resolve, log_source:write | yes | yes | no |
| viewer | read:* | yes | no | no |

Analyst previously had no `read:*`; with every read route guarded it would have lost all reads, so it now has it. Note: a principal holding only a write permission (e.g. `alert:ack`) now also needs the matching read permission, because the router-level guard applies to the whole router.

Guard test: walks every route (private `effective_candidates` walker, cross-checked against the public OpenAPI schema; fails on unclassifiable routes). Under OIDC with no header every non-allowlisted route must be exactly 401. Under local auth with a `read:*` bearer every POST/PUT/PATCH/DELETE must be 403, with a body map for routes that validate bodies first. Allowlists have per-entry comments. Mutation check: removing the `log_sources` router guard made the OIDC test fail for all three GET log-source routes; restored.

Frontend: `frontend/src/lib/api.ts` calls `/overview`, `/log-sources`, `/log-sources/sync` with no Authorization header, so local dev yields `admin:*` and keeps working. No frontend change. In production the UI will need a real token (Phase 4).
