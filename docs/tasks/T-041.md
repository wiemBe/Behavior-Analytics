## Why

The user asked (2026-10-12) that the names of the QRadar custom properties the platform reads — the
WAF URL, method, action, response code…, and later the IPS fields — be editable from the UI,
because they differ from site to site. The editor should **offer the property names that exist on
the console** (ideally only those that apply to the source's log-source type) instead of a bare text
box, and later the IPS mapping must accept **normalized** Ariel fields (`sourceip`,
`destinationport`, `qid`…) as well as custom properties.

T-027 already found that `GET /api/config/event_sources/custom_properties/regex_properties` works
with the lab token (119 rows), that "AQL property expressions" could be listed, and that
`.../regex_property_expressions` does not exist. Read `docs/tasks/T-027.report.md` §3 first.

## Questions

1. **Which custom-property definition endpoints exist and answer with this token** on the lab
   console (QRadar 7.6, API version 29.0)? Try the documented GET collections under
   `/config/event_sources/custom_properties/` — at least `regex_properties`,
   `calculated_properties`, `property_expressions`, `property_aql_expressions` (or whatever name
   T-027 used), `property_json_expressions`, `property_leef_expressions`,
   `property_cef_expressions`, `property_nvp_expressions`, `property_xml_expressions`,
   `property_genericlist_expressions`. For each: HTTP status class, row count, and the **field
   names** of one row (values only for non-sensitive fields such as `id`, `name`,
   `property_type`, `log_source_type_id`, `log_source_id`, `enabled`; never print a regex or
   expression body).
2. **Property → log-source type.** Which endpoint, if any, says which log-source types (or log
   sources) a property has an expression for? Show the join: for the lab WAF source
   `lab-waf-behavior-01` (QRadar id 312) and its type, list the property names that apply. Do the
   same for one IPS-typed source (T-027 lists them).
3. **Request shape.** Do these endpoints honour `fields=` and `filter=` (e.g.
   `filter=log_source_type_id=<n>`) and `Range: items=…` paging? What is the payload size of the
   full catalog? Is one cached fetch per instance per N minutes realistic?
4. **Ariel: normalized vs custom fields** (at most **3** Ariel searches, each `START`/`STOP`
   bounded to at most 1 hour, `LIMIT 10`):
   - Is a normalized field accepted **double-quoted**, e.g. `SELECT "destinationport", "sourceip"
     FROM events WHERE logsourceid = <n> …`? (The WAF code double-quotes every property name; the
     IPS mapping would like one code path for both kinds.)
   - Is `QIDNAME(qid)` accepted next to a quoted custom property in one `GROUP BY`?
5. **Name rules.** Do any lab property names fall outside the allowlist
   `^[A-Za-z0-9_][A-Za-z0-9_ -]{0,63}$` (`app/providers/base.py::PROPERTY_NAME_PATTERN`)? Count
   them and give examples of the offending characters (e.g. `.`, `/`, parentheses), without
   printing anything sensitive.
